# CSAM Repair v1.0 维护指南

面向运维人员。版本：1.0.0 | 发布日期：2026-07-15。

本指南覆盖日常运维、故障排查、版本升级等维护工作。

---

## 1. 日常检查清单

建议每日开机后或交接班时执行以下检查。

### 1.1 日志检查

- [ ] 检查 `logs\error_*.log` 当天是否有新增 ERROR 条目
- [ ] 检查 `logs\app_*.log` 末尾是否有 WARNING 级别异常
- [ ] 确认日志文件未异常膨胀（单文件应 ≤10MB 自动滚动）

### 1.2 磁盘检查

- [ ] 用户数据目录（`%APPDATA%\CSAM_Repair\`）剩余空间 ≥ 2GB
- [ ] `logs\` 目录大小未超过 500MB（超出按第 2 节清理）
- [ ] `exports\` 目录无历史遗留的大文件
- [ ] MATLAB 临时文件目录（`%TEMP%`）未堆积

### 1.3 MATLAB 进程检查

- [ ] 软件未运行时，任务管理器中**无残留 MATLAB 进程**
- [ ] 软件运行时，MATLAB 进程内存占用稳定（无持续增长泄漏）
- [ ] MATLAB 进程 CPU 在空闲时接近 0%（异常则可能有死循环）

### 1.4 License 检查

- [ ] 软件启动后 License 状态正常
- [ ] License 剩余天数 > 7 天（接近到期需按第 3 节续期）
- [ ] 未出现 "License 签名验证失败" 错误

## 2. 日志管理

### 2.1 日志位置

| 平台 | 日志目录 |
|------|---------|
| Windows 打包 | `%APPDATA%\CSAM_Repair\logs\` |
| macOS 打包 | `~/Library/Application Support/CSAM_Repair/logs/` |
| Linux 打包 | `~/.local/share/CSAM_Repair/logs/` |
| 开发环境 | `<项目根>\logs\` |
| 自定义 | `$CSAM_USER_DATA\logs\` |

可通过环境变量 `CSAM_USER_DATA` 重新指定根目录。

### 2.2 日志轮转策略（自动）

软件内置 loguru 自动轮转，无需手动干预：

| 文件 | 滚动阈值 | 保留时长 | 压缩 |
|------|---------|---------|------|
| `app_YYYY-MM-DD.log` | 10 MB | 30 天 | zip |
| `error_YYYY-MM-DD.log` | 10 MB | 60 天 | zip |
| `structured_YYYY-MM-DD.jsonl` | 10 MB | 30 天 | zip |

### 2.3 手动清理

当磁盘紧张或历史日志过多时，手动清理：

```powershell
# 清理 30 天前的所有日志（保留近期）
$logsDir = "$env:APPDATA\CSAM_Repair\logs"
Get-ChildItem $logsDir -Filter "*.log" | Where-Object {
    $_.LastWriteTime -lt (Get-Date).AddDays(-30)
} | Remove-Item

# 清理已压缩的历史日志包
Get-ChildItem $logsDir -Filter "*.zip" | Remove-Item
```

### 2.4 日志级别调整

通过环境变量 `CSAM_LOG_LEVEL` 调整：

| 级别 | 适用场景 |
|------|---------|
| `DEBUG` | 故障排查、开发调试（日志量大） |
| `INFO` | 日常运行（默认） |
| `WARNING` | 生产精简模式 |
| `ERROR` | 仅记录错误（最小日志） |

> 生产环境不建议长期使用 `DEBUG`，会显著增加磁盘占用。

### 2.5 崩溃日志

软件异常崩溃时，会在 `logs\` 目录生成 `crash_*.log`。此类日志**不会自动清理**，需运维定期归档或删除。崩溃日志包含完整堆栈，是排查问题的关键证据。

## 3. License 续期流程

### 3.1 续期时机

- 到期前 **7 天**，软件会在启动时弹出续期提示
- 到期后软件**无法启动**，必须续期

### 3.2 续期步骤

1. 在目标机器启动软件（若已过期，会显示具体到期日期）
2. 从 "关于" 对话框获取本机机器码（UUID 格式，如 `a1b2c3d4-...`）
3. 将机器码 + 续期需求（到期日期、功能权限）提交给授权方
4. 授权方签发新的 `license.key` 文件
5. 将新 `license.key` 覆盖到用户配置目录：
   - Windows：`%APPDATA%\CSAM_Repair\config\license.key`
   - macOS：`~/Library/Application Support/CSAM_Repair/config/license.key`
   - Linux：`~/.local/share/CSAM_Repair/config/license.key`
6. 重启软件，确认 "关于" 对话框显示新的到期日期

### 3.3 换机迁移

机器码绑定 MAC 地址 + 主机名哈希，换机或更换网卡后机器码会变化：

1. 在新机器上启动软件，获取**新机器码**
2. 提交新机器码给授权方重新签发 license
3. 旧机器的 license 自动失效（无法在新机器使用）

### 3.4 注意事项

- `public_key.pem` 公钥**内置于 EXE**，无需运维管理
- `CSAM_HMAC_SECRET` 环境变量必须与签发方保持一致
- License 文件被篡改会触发签名验证失败，软件拒绝启动

## 4. MATLAB 版本升级注意事项

### 4.1 升级前评估

升级 MATLAB 前，确认以下事项：

- [ ] 新版本在软件支持列表内（R2022a - R2025b）
- [ ] 必需 Toolbox 已购买授权（Curve Fitting / Statistics）
- [ ] 已在测试环境验证（不要直接在生产升级）
- [ ] 已备份现有 MATLAB 配置和算法脚本

### 4.2 升级步骤

1. 在测试机安装新版本 MATLAB（保留旧版本）
2. 修改系统 PATH 或通过软件配置指定新 MATLAB 路径
3. 运行 `docs\MATLAB集成\算法验证体系.md` 中的验证流程
4. 执行完整测试套件：`.\run_all_tests.ps1`
5. 验证算法结果与旧版本一致（容差范围内）
6. 验证通过后，在生产环境升级

### 4.3 兼容性风险

| 风险点 | 检查方式 |
|--------|---------|
| Toolbox 接口变更 | 运行 `path_planning\` 和 `profile_prediction\` 全部脚本 |
| 数值精度变化 | 对比新旧版本计算结果（容差 ≤1e-6） |
| 启动参数变化 | 确认 `-nodesktop -nosplash -r` 仍被支持 |
| Bridge 兼容性 | 运行 `matlab_bridge_server.m` 验证 ZMQ 通信 |

### 4.4 回滚方案

升级失败时回滚：

1. 卸载新版 MATLAB
2. 恢复系统 PATH 指向旧版本
3. 重启软件，确认 Bridge 连接正常
4. 检查日志确认无残留错误

## 5. 备份策略

### 5.1 备份对象

| 对象 | 位置 | 重要性 | 备份频率 |
|------|------|--------|---------|
| 用户数据 | `%APPDATA%\CSAM_Repair\projects\` | 高 | 每日 |
| 标定数据 | `config\calibration_db.json` | 高 | 每次标定后 |
| 配置文件 | `config\` 目录 | 中 | 变更后 |
| 导出文件 | `%APPDATA%\CSAM_Repair\exports\` | 中 | 每周 |
| 日志 | `%APPDATA%\CSAM_Repair\logs\` | 低 | 每月归档 |
| License | `%APPDATA%\CSAM_Repair\config\license.key` | 高 | 续期后 |

### 5.2 备份命令示例

```powershell
# 备份用户数据目录（含 projects、exports、config）
$dataDir = "$env:APPDATA\CSAM_Repair"
$backupDir = "D:\Backup\CSAM_$(Get-Date -Format 'yyyyMMdd')"

# 完整备份
Copy-Item -Path $dataDir -Destination $backupDir -Recurse

# 仅备份关键数据（projects + config + calibration）
$keyItems = @("projects", "config")
foreach ($item in $keyItems) {
    Copy-Item -Path "$dataDir\$item" -Destination "$backupDir\$item" -Recurse
}
Copy-Item -Path "<项目根>\config\calibration_db.json" -Destination "$backupDir\" -ErrorAction SilentlyContinue
```

### 5.3 标定数据备份

标定数据（`calibration_db.json`）是设备级数据，丢失需重新标定，**必须重点备份**：

- 每次标定完成后立即备份
- 保留至少 3 个历史版本
- 备份到独立存储（不与运行环境同盘）

### 5.4 恢复流程

1. 停止软件运行
2. 清空或重命名当前用户数据目录
3. 从备份恢复到 `%APPDATA%\CSAM_Repair\`
4. 恢复 `config\calibration_db.json` 到项目根 `config\`
5. 启动软件，验证数据完整性

## 6. 故障排查流程

### 6.1 软件无法启动

**排查步骤：**

1. 检查 `logs\error_*.log` 最近条目
2. 确认 `CSAM_HMAC_SECRET` 环境变量已设置（生产环境）
3. 确认 License 未过期（检查 `license.key`）
4. 确认系统磁盘空间充足
5. 尝试以管理员身份运行
6. 检查杀毒软件是否拦截 EXE

**常见原因：**

| 原因 | 解决方案 |
|------|---------|
| License 过期 | 按第 3 节续期 |
| `CSAM_HMAC_SECRET` 未设置 | 设置环境变量后重启 |
| 用户数据目录无写权限 | 修改目录权限或改用 `CSAM_USER_DATA` 重定向 |
| 杀毒软件拦截 | 将 EXE 加入白名单 |
| VC 运行时缺失 | 安装 Visual C++ Redistributable |

### 6.2 MATLAB 连接失败

**排查步骤：**

1. 检查 MATLAB 是否在系统 PATH：
   ```powershell
   matlab -batch "disp('OK')"
   ```
2. 检查 `logs\app_*.log` 中 `MatlabBridgeLauncher` 相关条目
3. 检查端口 5555 是否被占用：
   ```powershell
   netstat -ano | findstr :5555
   ```
4. 检查 MATLAB 进程是否启动（任务管理器）
5. 确认 MATLAB 版本在支持列表内
6. 尝试手动启动 `matlab_bridge_server.m` 验证 Bridge

**常见原因：**

| 原因 | 解决方案 |
|------|---------|
| MATLAB 未加入 PATH | 添加 MATLAB `bin` 目录到系统 PATH |
| 端口被占用 | 修改 `CSAM_ZMQ_ADDRESS` 或释放端口 |
| MATLAB 启动超时 | 增大 `launcher_startup_timeout_sec` |
| Toolbox 缺失 | 安装 Curve Fitting / Statistics Toolbox |
| MATLAB 许可证过期 | 续期 MATLAB License |
| 僵尸 MATLAB 进程 | 任务管理器结束所有 MATLAB 进程后重启软件 |

### 6.3 G-code 导出失败

**排查步骤：**

1. 检查 `logs\error_*.log` 中 EXPORT 类错误
2. 确认导出目录可写：
   ```powershell
   echo test > "$env:APPDATA\CSAM_Repair\exports\gcode\test.txt"
   ```
3. 确认计算结果完整（路径规划已生成）
4. 确认磁盘空间充足
5. 检查导出文件名是否含非法字符

**常见原因：**

| 原因 | 解决方案 |
|------|---------|
| 导出目录无权限 | 修改目录权限 |
| 磁盘空间不足 | 清理磁盘 |
| 计算未完成 | 重新执行计算流程 |
| 文件名非法 | 使用合法文件名（避免特殊字符） |
| 路径规划结果为空 | 检查 STL 模型有效性 |

### 6.4 通用排查流程

```
故障发生
   ↓
查看 error_*.log（定位错误类别）
   ↓
按错误类别查表（License/MATLAB/File/Mesh/Network/Export）
   ↓
尝试对应解决方案
   ↓
未解决 → 收集日志 + 环境信息 → 联系开发团队
```

**联系开发团队时需提供：**
- `logs\` 目录完整打包
- 软件版本号（"关于" 对话框）
- 操作系统版本
- MATLAB 版本
- 故障复现步骤

## 7. 性能监控建议

### 7.1 关键指标

| 指标 | 正常范围 | 监控方式 |
|------|---------|---------|
| MATLAB 启动时间 | < 60 秒 | 日志中 `Bridge 端口就绪` 时间戳 |
| 单次计算耗时 | 视模型大小 | 日志中计算开始/结束时间 |
| Bridge 请求延迟 | < 5000 毫秒 | 超过会记录 WARNING |
| 内存占用 | < 2 GB | 任务管理器 |
| 心跳丢失次数 | 0 | 日志中 `heartbeat miss` 计数 |

### 7.2 性能日志

日志中关注以下关键字：

- `CSAM_BRIDGE_LATENCY_LOG_MS`：超过阈值会记录 WARNING
- `restart`：MATLAB 重启事件（频繁重启需排查）
- `timeout`：超时事件

### 7.3 性能优化建议

- 大模型计算时关闭其他占内存程序
- 定期重启软件（避免内存碎片）
- SSD 磁盘可显著提升 STL 读取速度
- MATLAB R2025b 性能优于旧版本
- 若 `CSAM_LOG_LEVEL=DEBUG` 长期开启，会拖慢性能

### 7.4 压力测试

软件提供 `stress` 测试标记，可在维护窗口模拟大数据量场景：

```powershell
pytest -m stress --tb=short -v
```

## 8. 版本升级流程

### 8.1 升级前准备

1. 通知所有用户停止使用软件
2. 备份用户数据（按第 5 节）
3. 备份 License 文件
4. 记录当前版本号（"关于" 对话框）
5. 在测试环境验证新版本

### 8.2 升级步骤

**EXE 用户：**

1. 关闭软件（确保 MATLAB 进程已清理）
2. 备份旧 EXE（重命名为 `CSAM_Repair.exe.bak`）
3. 复制新 EXE 到原目录
4. 启动新版本，确认版本号正确
5. 验证 License 仍有效（机器码未变则无需重新签发）
6. 执行首次运行验证（参考 `部署指南.md` 第 8 节）

**源码用户：**

```powershell
# 1. 拉取新版本代码
git pull origin main

# 2. 更新依赖
pip install -e ".[dev]" --upgrade

# 3. 运行测试验证
.\run_all_tests.ps1 -Quick

# 4. 启动验证
python run_app.py
```

### 8.3 升级后验证

- [ ] 软件版本号正确
- [ ] License 状态正常
- [ ] MATLAB 连接正常
- [ ] 历史项目文件可正常打开
- [ ] G-code 导出功能正常
- [ ] 日志正常生成

### 8.4 回滚方案

升级失败时回滚到旧版本：

1. 停止新版本软件
2. 恢复旧 EXE（删除新版，恢复 `.bak`）
3. 恢复备份的用户数据（若数据格式不兼容）
4. 启动旧版本，确认功能正常
5. 收集升级失败日志，反馈给开发团队

### 8.5 数据兼容性

版本升级通常保持用户数据向后兼容。若存在不兼容变更：

- 开发团队会在 `docs\更新日志\更新日志.md` 中明确说明
- 升级前会提示备份
- 软件会自动迁移旧格式数据（若支持）
