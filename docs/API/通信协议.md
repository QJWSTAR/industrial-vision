## 1. 通信架构

### 1.1 完整通信链路

```
GUI (MainWindow)
    ↓  CoordinationService.create_zmq_client()
CoordinationService
    ↓  返回 LegacyZmqClient
LegacyZmqClient (bridge/adapters/legacy_adapter.py)
    ↓  委托
BridgeClient (bridge/communication/zmq_client.py)
    ↓  ZMQ REQ, tcp://127.0.0.1:5555
ZeroMQ (Protobuf v2.1 二进制)
    ↓
matlab_bridge_server.m (MATLAB 宿主脚本)
    ↓  pyenv 调用 Python
MatlabAdapter (bridge/adapters/matlab_adapter.py, 继承 BridgeServer)
    ↓  调用算法
MatlabEngineProxy (bridge/adapters/matlab_engine_proxy.py, 单例)
    ↓  matlab.engine.connect_matlab('matlab_bridge')
    ↓  eng.run_path_planning() / eng.call_profile_prediction()
MATLAB R2025b 算法
    ↓  结果
RepairResult (Protobuf) → 原路返回 → GUI
```

### 1.2 分层设计

```
┌─────────────────────────────────────────────────┐
│              业务层 (UI / Service)                │
│         MainWindow → CoordinationService         │
├─────────────────────────────────────────────────┤
│              适配器层 (Adapters)                  │
│    LegacyZmqClient    MatlabAdapter              │
├─────────────────────────────────────────────────┤
│            通信层 (Communication)                 │
│  BridgeClient  BridgeServer  Serializer          │
│  HeartbeatMonitor  MessageEnvelope               │
├─────────────────────────────────────────────────┤
│           基础设施 (Infrastructure)               │
│      ZeroMQ  +  Protobuf  +  NumPy               │
└─────────────────────────────────────────────────┘
```

### 1.3 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 传输层 | ZeroMQ REQ/REP | 同步请求-应答模式 |
| 端口 | 5555 | 生产端口，可通过 `CSAM_ZMQ_ADDRESS` 配置 |
| 协议 | Protocol Buffers v2.1 | `repair_protocol.proto` |
| 消息类型 | `RepairRequest` / `RepairResult` | 业务专用消息 |
| 序列化 | Protobuf 二进制 | 由 `repair_protocol_pb2.py` 提供 |
| MATLAB 入口 | `matlab_bridge_server.m` | 通过 `pyenv` 调用 Python 的 `MatlabAdapter` |
| 协议版本常量 | `PROTOCOL_VERSION = "2.1"` | 定义于 `bridge/communication/protocol.py` |

## 2. ZeroMQ 模式

### 2.1 模式选型

采用 **REQ/REP**（请求-应答）模式，匹配修复请求的严格一发一收语义。

| 模式 | 适用性 | 评估 |
|------|--------|------|
| **REQ/REP** | ✅ 采用 | 同步请求-回复，匹配修复请求语义。简单可靠，MATLAB 易实现 |
| DEALER/ROUTER | ❌ 不采用 | 异步多路复用，复杂度高。当前单客户端单服务端无需 |
| PUSH/PULL | ❌ 不采用 | 单向管道，不适合请求-回复模式 |
| PUB/SUB | 🔜 预留 | 适合进度推送（逐层路径规划）。当前一次性返回，未来扩展用 |

### 2.2 选型理由

1. 修复请求是严格的请求-回复语义（一发一收）
2. MATLAB 原生 ZMQ 绑定对 REQ/REP 支持最好
3. 协议已有 `HealthCheckRequest` / `RepairRequest` 两种消息类型，REQ/REP 可自然分发
4. 同步模型降低调试难度，符合工业软件可靠性要求

### 2.3 端口分配

| 端口 | 协议 | 用途 | 进程 |
|------|------|------|------|
| 5555 | ZMQ v2.1（REQ/REP） | 生产通信（唯一路径） | `matlab_bridge_server.m` |

> 系统仅使用 5555 一个端口。未来若需逐层进度推送，可预留 PUB 5556（`ProgressUpdate` 消息已在 proto 中定义）。

### 2.4 跨平台传输地址

`platform/transport.py` 按操作系统选择传输地址，可由环境变量 `CSAM_ZMQ_ADDRESS` 覆盖：

| 平台 | 默认传输地址 | 说明 |
|------|-------------|------|
| Windows | `tcp://127.0.0.1:5555` | TCP 回环 |
| POSIX（Linux/macOS） | `ipc:///tmp/csam_engine` | Unix 域套接字 |

## 3. Protocol Buffers v2.1

### 3.1 版本

- 当前版本：**v2.1**（`PROTOCOL_VERSION = "2.1"`，定义于 `bridge/communication/protocol.py`）
- 兼容版本：v2.0, v2.1（`COMPATIBLE_PROTOCOL_VERSIONS = ("2.0", "2.1")`）
- 协议定义文件：`repair_protocol.proto`（项目根目录，不可修改）
- 生成代码：`repair_app/communication/repair_protocol_pb2.py`（仍被 bridge 层复用）

### 3.2 消息类型

| 类型 | 方向 | Protobuf 消息 | 用途 |
|------|------|--------------|------|
| 健康检查 | C→S | `HealthCheckRequest` | 探活 |
| 健康响应 | S→C | `HealthCheckResponse` | 返回引擎状态 |
| 修复请求 | C→S | `RepairRequest` | 点云 + 工艺参数 |
| 修复结果 | S→C | `RepairResult` | 航点 + 指标 |
| 进度更新 | S→C | `ProgressUpdate` | 逐层推送（预留） |
| 心跳 | 双向 | `Heartbeat` | 心跳监控 |

### 3.3 关键字段说明

#### RepairRequest（修复请求）

| 字段 | 类型 | 说明 |
|------|------|------|
| 点云坐标 | `repeated float x/y/z` | SoA 布局（Struct of Arrays） |
| 法向量 | `repeated float nx/ny/nz` | 点云法向量 |
| 工艺参数 | `ProcessParams` | 材料类型、粒子速度、气体温度、倾角等 |
| 材料类型 | `MaterialType` 枚举 | 材料标识（如 `STEEL_316L`） |
| 请求 ID | `string` | 全链路追踪 |

#### RepairResult（修复结果）

| 字段 | 类型 | 说明 |
|------|------|------|
| 航点 | `repeated Waypoint` | AoS 布局（Array of Structs） |
| 状态码 | `int32` | 见状态码表 |
| 错误信息 | `string` | 失败时的可读描述 |
| 计算耗时 | `float compute_time_ms` | 算法真实计算耗时 |
| 估计时间 | `float estimated_time_s` | 基于路径长度与速度计算 |
| 均匀性评分 | `float uniformity_score` | 路径均匀性指标 |
| 可行性 | `bool is_feasible` | 修复可行性结论 |
| 可行性原因 | `string feasibility_reason` | 可行性结论说明 |

#### Waypoint（航点）

| 字段 | 类型 | 说明 |
|------|------|------|
| 坐标 | `float x/y/z` | 航点空间坐标 |
| 法向量 | `float nx/ny/nz` | 航点法向量 |
| 进给速度 | `float feed_rate` | 进给速度 |
| 层索引 | `int32 layer_index` | 所属层 |

### 3.4 消息信封（MessageEnvelope）

每条消息附加元数据，定义于 `bridge/communication/message.py`：

```python
MessageEnvelope(
    message_type=MessageType.REPAIR_REQUEST,
    payload=<protobuf bytes>,
    request_id="path-1234567890-abc123",  # 全链路追踪
    timestamp=1719900000.0,                # 延迟分析
    version="2.1",                         # 兼容性检查
    algorithm="path_planner",              # 算法标识
    processing_time_ms=50,                 # 服务端耗时
)
```

### 3.5 状态码

定义于 `bridge/communication/protocol.py`：

| 码值 | 名称 | 含义 | 可重试 |
|------|------|------|--------|
| 0 | SUCCESS | 成功 | - |
| 1 | ERR_INVALID_INPUT | 参数错误 | 否 |
| 2 | ERR_NO_DEFECT_FOUND | 未发现缺陷 | 否 |
| 3 | ERR_ALGORITHM_FAIL | 算法失败 | 否 |
| 4 | ERR_TIMEOUT | 超时 | 是 |
| 5 | ERR_NOT_FEASIBLE | 不可修复 | 否 |
| 99 | ERR_UNKNOWN | 未知错误 | 是 |

### 3.6 数据布局

- **点云**：SoA (Struct of Arrays) — `x[], y[], z[], nx[], ny[], nz[]` 各为 `repeated float`，比 AoS 减少 20% 序列化体积
- **航点**：AoS (Array of Structs) — `repeated Waypoint {x, y, z, nx, ny, nz, feed_rate, layer_index}`

## 4. Bridge 组件

### 4.1 目录结构

```text
repair_app/bridge/
├── __init__.py                      # 公共 API 导出
├── communication/
│   ├── config.py                    # BridgeConfig（集中化配置，无硬编码）
│   ├── exceptions.py                # 结构化异常层次 + translate_zmq_error
│   ├── message.py                   # MessageEnvelope + request_id 生成
│   ├── protocol.py                  # PROTOCOL_VERSION="2.1" + 状态码定义
│   ├── serializer.py                # Protobuf 序列化门面
│   ├── heartbeat.py                 # HeartbeatMonitor（QThread）
│   ├── zmq_client.py                # BridgeClient + _RequestWorker（QThread）
│   └── zmq_server.py                # BridgeServer（REP 端，poll 可中断）
├── services/
│   └── matlab_service.py            # MatlabService 门面（未接入 GUI）
├── adapters/
│   ├── matlab_adapter.py            # MatlabAdapter（BridgeServer 子类）
│   ├── matlab_engine_proxy.py       # MatlabEngineProxy（matlab.engine 单例）
│   └── legacy_adapter.py            # LegacyZmqClient（UI 适配器）
└── tests/
    └── test_bridge.py               # Bridge 测试套件
```

### 4.2 BridgeServer（REP 端）

- **源文件**：`bridge/communication/zmq_server.py`
- **角色**：ZMQ REP 服务端基类，`MatlabAdapter` 继承此类

| 方法 | 说明 |
|------|------|
| `serve()` | 阻塞服务，创建 REP socket + bind，poll 循环（200ms 可中断） |
| `_dispatch()` | 消息分发，try/except 包裹异常捕获 |
| `handle_repair(request)` | 由子类 `MatlabAdapter` 实现，处理修复请求 |
| `stop()` | 优雅关闭，200ms 内退出 |

### 4.3 BridgeClient（REQ 端）

- **源文件**：`bridge/communication/zmq_client.py`
- **角色**：ZMQ REQ 客户端，被 `LegacyZmqClient` 持有与委托

| 方法 | 说明 |
|------|------|
| `request_repair(request, on_result, on_error=None) -> str` | 异步发起请求，返回 `request_id` 用于跟踪/取消 |
| `check_health(on_health)` | 异步健康检查 |
| `start_heartbeat()` / `stop_heartbeat()` | 心跳控制 |
| `close(wait_ms=4000)` | 关闭连接 |

特性：QThread 封装（`_RequestWorker` + `_HealthWorker`），协作式中断（200ms poll），不阻塞 Qt 事件循环。

### 4.4 LegacyZmqClient（UI 适配器）

- **源文件**：`bridge/adapters/legacy_adapter.py`
- **角色**：bridge 适配器，封装旧版 ZMQ 协议，由 `CoordinationService.create_zmq_client()` 优先返回。API 与旧版 `ZmqRepairClient` 完全兼容，保证调用方零改动迁移。

### 4.5 MatlabAdapter（算法调度）

- **源文件**：`bridge/adapters/matlab_adapter.py`
- **角色**：`BridgeServer` 子类，处理修复请求，调用 MATLAB 算法或降级到 Python
- **服务版本**：`matlab-adapter-2.0.0`
- **异常**：`MatlabAlgorithmError(Exception)`

| 方法 | 说明 |
|------|------|
| `handle_repair(request: RepairRequest) -> RepairResult` | 处理修复请求，调用 MATLAB 算法或降级到 Python 原型 |
| `_invoke_with_fallback()` | 降级策略：MATLAB 失败时自动切换到 `LocalEngine`（auto 模式） |

### 4.6 Serializer（Protobuf 序列化）

- **源文件**：`bridge/communication/serializer.py`
- **角色**：Protobuf 序列化/反序列化门面，复用 `repair_protocol_pb2.py`

### 4.7 HeartbeatMonitor（心跳监控）

- **源文件**：`bridge/communication/heartbeat.py`
- **角色**：周期性健康检查（QThread），miss 阈值告警

### 4.8 MessageEnvelope（消息封装）

- **源文件**：`bridge/communication/message.py`
- **角色**：消息信封，附加 `request_id`、`timestamp`、`version`、`algorithm` 等元数据，支持全链路追踪
- **方法**：`generate_request_id()` 生成唯一请求 ID

### 4.9 BridgeConfig（配置管理）

- **源文件**：`bridge/communication/config.py`
- **角色**：`@dataclass(frozen=True)` 不可变配置，所有通信参数集中于此，无硬编码值，支持环境变量覆盖
- **方法**：`from_env()` 从环境变量加载配置

### 4.10 异常层次（exceptions.py）

- **源文件**：`bridge/communication/exceptions.py`
- **角色**：结构化异常层次（`BridgeError` 基类及子类）+ `translate_zmq_error` 翻译函数，业务层永不接触原始 ZMQ 异常

详见 [6. 错误处理](#6-错误处理)。

## 6. 错误处理

### 6.1 异常层次

所有通信层异常继承自 `BridgeError`，业务层只需捕获 `BridgeError`，永不接触原始 ZMQ/Protobuf 异常。定义于 `bridge/communication/exceptions.py`：

```
BridgeError(Exception)                 # 基类，含 request_id: str
├── ConnectionError(BridgeError)       # 连接失败/中断
│   ├── ConnectionTimeoutError         # 超时，含 timeout_ms: int
│   └── EngineUnavailableError         # MATLAB 引擎未启动/不可达
│       └── EngineCrashError           # 引擎处理中崩溃
├── SerializationError(BridgeError)    # 序列化/反序列化失败
├── InvalidParameterError(BridgeError) # 参数校验失败，含 parameter: str
├── AlgorithmError(BridgeError)        # 算法执行异常，含 algorithm: str
├── ProtocolError(BridgeError)         # 协议版本不兼容，含 expected_version/actual_version
└── ShutdownError(BridgeError)         # 通信层正在关闭/已关闭
```

### 6.2 关键字段

| 异常类 | 附加字段 |
|--------|----------|
| `BridgeError` | `request_id: str` |
| `ConnectionTimeoutError` | `timeout_ms: int` |
| `InvalidParameterError` | `parameter: str` |
| `AlgorithmError` | `algorithm: str` |
| `ProtocolError` | `expected_version: str`、`actual_version: str` |

### 6.3 翻译函数

```python
translate_zmq_error(exc: Exception, request_id: str = "") -> BridgeError
```

将底层 `zmq.Again`、`zmq.ZMQError`、`ValueError`、`TypeError` 等翻译为上述结构化异常。

### 6.4 错误处理原则

- **业务层永不接触原始异常**：所有 ZMQ/Protobuf 异常经 `translate_zmq_error()` 翻译
- **不返回原始堆栈**：异常消息只含可读描述 + `request_id`
- **结构化错误**：每个异常携带上下文信息（`timeout_ms`、`parameter`、`algorithm` 等）
- **可重试判断**：`is_status_retriable()` 区分可重试错误（超时/未知）与不可重试错误（参数错误）

### 6.5 重试策略

| 错误类型 | 可重试 | 策略 |
|----------|--------|------|
| `ConnectionTimeoutError` | 是 | 按 `max_retries`（默认 3）和 `retry_interval_ms`（默认 2000ms）重试 |
| `ERR_TIMEOUT`（状态码 4） | 是 | 同上 |
| `ERR_UNKNOWN`（状态码 99） | 是 | 同上 |
| `InvalidParameterError` | 否 | 立即返回，不重试 |
| `ERR_INVALID_INPUT`（状态码 1） | 否 | 立即返回 |
| `AlgorithmError` | 否 | 立即返回（auto 模式下降级到 Python） |

### 6.6 已知问题

- `zmq_client.py:279` 处异常类型信息丢失，底层异常未被翻译为结构化 `BridgeError`
- `HeartbeatMonitor` 检测到心跳丢失时仅告警，不触发自动重连

## 7. 时序图

### 7.1 修复请求-响应流程

```
GUI (MainWindow)     CoordinationService   LegacyZmqClient   BridgeClient    ZMQ REP Server
     │                      │                    │                │                  │
     │ create_zmq_client    │                    │                │                  │
     │─────────────────────>│                    │                │                  │
     │                      │ return LegacyZmqClient              │                  │
     │<─────────────────────│                    │                │                  │
     │                      │                    │                │                  │
     │ request_repair       │                    │                │                  │
     │──────────────────────────────────────────>│                │                  │
     │                      │                    │ delegate       │                  │
     │                      │                    │───────────────>│                  │
     │                      │                    │                │ build_repair_req │
     │                      │                    │                │ serialize        │
     │                      │                    │                │ ZMQ REQ send     │
     │                      │                    │                │─────────────────>│
     │                      │                    │                │                  │ handle_repair
     │                      │                    │                │                  │ run_path_planning
     │                      │                    │                │                  │ build_repair_result
     │                      │                    │                │<─────────────────│
     │                      │                    │                │ deserialize      │
     │                      │                    │                │ emit result_ready│
     │                      │                    │<───────────────│                  │
     │                      │                    │ RepairResult   │                  │
     │                      │<──────────────────────────────────│                  │
     │ update UI            │                    │                │                  │
     │<─────────────────────────────────────────│                │                  │
```

### 7.2 心跳监控流程

```
HeartbeatMonitor       BridgeClient         ZMQ REP Server
     │                      │                     │
     │ ── loop ──>          │                     │
     │   check_health       │                     │
     │─────────────────────>│                     │
     │                      │ HealthCheckRequest  │
     │                      │────────────────────>│
     │                      │<────────────────────│
     │                      │ HealthCheckResponse │
     │<─────────────────────│                     │
     │   ok=True, latency=5ms                     │
     │   emit latency_updated                     │
     │                      │                     │
     │   sleep(heartbeat_interval_ms)             │
     │   ── loop ──>        │                     │
```

### 7.3 错误处理流程

```
BridgeClient              ZMQ Server (crashed)
     │                        │
     │ REQ send               │
     │───────────────────────>│ X (no response)
     │                        │
     │ poll(200ms) x N        │
     │ timeout (30000ms)      │
     │                        │
     │ emit error_occurred    │
     │ translate_zmq_error    │
     │   → ConnectionTimeout  │
     │<───────────────────────│
     │ on_error(BridgeError)  │
```

### 8.6 抓包与诊断

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| 健康检查超时 | 服务端未启动 | 启动 `matlab_bridge_server` |
| `Address in use` | 端口被占用 | 更改 `CSAM_ZMQ_ADDRESS` 端口 |
| 序列化失败 | 点云形状不对 | 确保 xyz 为 (N,3) float32 |
| `pyzmq 未安装` | 依赖缺失 | `pip install pyzmq` |
| 心跳频繁丢失 | 网络不稳定 | 增大 `CSAM_BRIDGE_HEARTBEAT_MISS` |
| 请求无响应 | 服务端阻塞 | 检查算法是否死循环 |

## 9. 性能基准

| 操作 | 数据量 | 耗时 | 吞吐 |
|------|--------|------|------|
| 序列化请求 | 5 万点 | < 1s | > 5 万点/s |
| 反序列化往返 | 2000 点 | < 100ms | - |
| 构建结果 | 500 航点 | < 100ms | - |
| 端到端请求 | 2000 点 | ~150ms | - |

性能优化要点：

- 点云使用 **SoA 布局**（Protobuf `repeated float`），比 AoS 减少 20% 序列化体积
- `zmq.Context.instance()` 共享上下文，避免重复创建
- `LINGER=0` 确保 socket 即时释放
- QThread worker 用完即销毁，不持有引用
- 超过 100 万点触发警告日志
