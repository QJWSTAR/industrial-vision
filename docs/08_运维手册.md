## 日志

系统日志分为 Python 应用日志与 MATLAB Server 日志两部分，均支持级别控制与文件滚动。

### Python 日志

由 `repair_app/utils/logger_config.py` 配置，输出到 `logs/` 目录。

| 日志文件 | 级别 | 滚动策略 | 保留期 |
|----------|------|----------|--------|
| `logs/app_{date}.log` | 全部级别（DEBUG 及以上） | 单文件 10 MB 滚动 | 30 天 |
| `logs/error_{date}.log` | ERROR 及以上 | 按日期滚动 | 60 天 |
| `logs/structured_{date}.jsonl` | 全部级别（JSONL 结构化，可选） | 按日期滚动 | 30 天 |
| 控制台 | 全部级别 | — | — | 彩色输出 |

**日志级别**：`DEBUG` / `INFO` / `WARNING` / `ERROR`

**级别配置**：

```powershell
# Windows PowerShell
$env:CSAM_LOG_LEVEL = "DEBUG"

# macOS/Linux
export CSAM_LOG_LEVEL=DEBUG
```

生产环境默认 `INFO`，排查问题时切换为 `DEBUG`。

### MATLAB 日志

由 `matlab_server/logger.m` 配置，JSONL 格式，UTF-8 编码，stdout + 文件双写。

| 日志文件 | 格式 | 说明 |
|----------|------|------|
| `logs/matlab_server_{yyyymmdd}.log` | JSONL | 按日期滚动，UTF-8 编码，stdout + 文件双写 |

**日志级别**：`debug` / `info` / `warn` / `error`

**级别配置**：

```powershell
$env:CSAM_MATLAB_LOG_LEVEL = "debug"
```

默认级别为 `info`。

### 关键事件

以下为系统中需要重点关注的日志事件：

| 事件 | 来源 | 含义 |
|------|------|------|
| `server.start` | MATLAB Server | 服务器启动成功 |
| `request.start` | Bridge / MATLAB | 请求处理开始（携带 request_id） |
| `request.crash` | MATLAB | 请求处理过程中发生崩溃 |
| `cleanup.done` | MATLAB | 周期内存回收完成 |
| `server.stop` | MATLAB Server | 服务器停止 |
| `heartbeat.miss` | Bridge | 心跳丢失 |
| `engine.lost` | Bridge | MATLAB 引擎连接丢失 |

### 日志分析技巧

1. **按 `request_id` 关联请求全链路**：每个请求分配唯一 `request_id`，在 Python 与 MATLAB 日志中均可检索，用于追踪完整调用链。
2. **`error` 级别优先排查**：`error_{date}.log` 仅记录 ERROR 及以上，是定位故障的起点。
3. **结构化日志便于聚合**：`structured_{date}.jsonl` 可导入 ELK / Loki 等日志平台进行聚合分析。
4. **MATLAB 日志与 Python 日志交叉比对**：同一 `request_id` 在两侧均有记录，可定位通信层与算法层的边界问题。

## 恢复

### MATLAB Server 崩溃恢复

1. 确认 MATLAB Server 进程已退出
2. 重启 MATLAB Server：
   ```matlab
   cd matlab_server
   startup
   ```
3. GUI 侧重试当前操作，或重新生成修复方案
4. 检查 `logs/matlab_server_*.log` 确认崩溃原因

### GUI 崩溃恢复

1. `crash_handler` 自动记录崩溃日志到 `logs/`
2. 重启 GUI：
   ```powershell
   python run_app.py
   ```
3. 检查崩溃日志定位原因

### 数据恢复

- 从 `morphology_prediction/` 目录恢复形貌预测中间文件（`pointlist.npz`、`velocitylist.json` 等）
- 从备份恢复配置文件

### 配置恢复

- 从 `.env.example` 重建 `.env`，按实际环境填写值
- 从备份恢复 `calibration_db.json` 与 `material_db.json`

### 完整重置

当系统状态异常且常规恢复无效时，执行完整重置：

1. 关闭所有进程（GUI + MATLAB Server）
2. 清理 `logs/` 目录与临时文件
3. 从备份恢复配置文件
4. 重启 MATLAB Server（`startup`）
5. 重启 GUI（`python run_app.py`）
6. 执行一次完整工作流验证

## 升级

### 升级前准备

1. 备份配置和数据（见 [备份](#备份)）
2. 记录当前版本号（`repair_app/__init__.py` 中 `__version__`）
3. 暂存或提交本地改动：
   ```bash
   git stash        # 暂存未提交改动
   # 或
   git commit -am "WIP: 升级前提交"
   ```

### 升级步骤

1. 拉取最新代码：
   ```bash
   git pull origin main
   ```
2. 更新 Python 依赖：
   ```bash
   pip install -r requirements.txt
   ```
3. 更新 MATLAB 算法文件（如算法目录有变更）
4. 重启 MATLAB Server：
   ```matlab
   cd matlab_server
   startup
   ```
5. 重启 GUI：
   ```powershell
   python run_app.py
   ```

### 升级后验证

1. 运行测试套件：
   ```bash
   pytest --cov=repair_app
   ```
   覆盖率应 ≥ 60%（CI 门控阈值）。
2. 启动 GUI 验证 MATLAB Server 连接正常
3. 执行一次完整工作流：加载模型 → 选区 → 路径生成 → 形貌预测 → 导出

### 回滚

```bash
git checkout <旧版本标签或commit>
pip install -r requirements.txt
# 重启 MATLAB Server 与 GUI
```

### MATLAB 升级注意事项

- **R2025b 非 ASCII 字符限制**：R2025b 拒绝 `.m` 文件中的非 ASCII 字符，升级 MATLAB 版本前需确认所有算法文件注释为纯 ASCII
- **工具箱许可证变更**：升级后检查工具箱许可证是否仍有效（`license('test', 'Map_Toolbox')` 等），部分算法依赖 `Map_Toolbox`、`Curve_Fitting_Toolbox`

## 新增 MATLAB 算法

### 操作步骤

1. **编写算法 `.m` 文件**：将原生算法函数放在 `形貌预测\`（path_planning 算法）或 `路径规划\`（morphology 算法）目录中
   > 注意：磁盘目录名与实际内容相反，参见 [07 开发者文档](07_开发者文档.md) 中的说明。

2. **在 `register_algorithms.m` 中注册**：使用 `add()` 函数注册新算法：
   ```matlab
   add(reg, 'namespace.algorithm_name', '1.0.0', @wrapper_fn, ...
       'category', '算法描述', {'Toolbox_Name'}, timeout_ms);
   ```
   参数说明：
   - `reg`：registry 实例
   - `'namespace.algorithm_name'`：算法全名（命名空间.算法名）
   - `'1.0.0'`：版本号
   - `@wrapper_fn`：wrapper 函数句柄
   - `'category'`：分类（`'path_planning'` 或 `'morphology'`）
   - `'算法描述'`：算法描述
   - `{'Toolbox_Name'}`：依赖工具箱列表（无依赖填 `{}`）
   - `timeout_ms`：超时时间（毫秒）

3. **编写 wrapper 函数**：wrapper 签名为 `out = wrap_xxx(params, inputs)`，负责：
   - 参数验证与类型转换（`get_param` / `get_input` / `get_json`）
   - 调用原生算法函数
   - 结果序列化（`ok(results, artifacts)`，矩阵通过 `json_codec('matrix_to_tensor', ...)` 转换）

4. **重启 MATLAB Server**：
   ```matlab
   cd matlab_server
   startup
   ```

5. **验证**：发送 `LIST_ALGORITHMS` 请求查看新算法是否注册成功

### 关键说明

- **不需要修改 `dispatcher.m`**：dispatcher 自动路由 `ALGORITHM_REQUEST` 到 registry，新增算法注册后即可被调用
- **算法 `.m` 文件规范**：
  - 不要使用非 ASCII 字符（R2025b 限制）
  - 不要使用 `clear all` / `fclose all`
  - 不要使用 `evalin('base', 'pack')`
- **wrapper 契约**：返回 `out.results`（标量/字符串/打包 JSON）与 `out.artifacts`（Tensor 数值矩阵）

## 替换算法

### 操作步骤

1. **修改算法 `.m` 文件**：更新原生算法实现
2. **保持注册名不变**：`register_algorithms.m` 中的算法名（`namespace.algorithm_name`）保持不变，确保向后兼容
3. **递增版本号**（如需）：修改 `add()` 调用中的 version 字段（如 `'1.0.0'` → `'1.1.0'`）
4. **重启 MATLAB Server**：
   ```matlab
   cd matlab_server
   startup
   ```
5. **验证**：调用该算法检查输出是否符合预期

## 发布流程

### 发布步骤

1. **代码冻结**：停止新功能合并，仅允许缺陷修复
2. **运行测试**：
   ```bash
   pytest --cov=repair_app
   ```
   覆盖率 ≥ 60%（CI 门控阈值）
3. **更新版本号**：修改 `repair_app/__init__.py` 中的 `__version__`
4. **更新 CHANGELOG**：在 `CHANGELOG.md` 中记录本次变更
5. **打包**：
   ```cmd
   build_windows.bat
   ```
   产物：`dist/CSAM_Repair.exe`
6. **打包验证**：执行 `docs/PACKAGING_GUIDE.md` 中的 7 项检查清单
7. **冒烟测试**：执行完整工作流验证 —— 启动 → 加载模型 → 选区 → 路径生成 → 形貌预测 → 导出
8. **生成发布说明**：创建 `docs/RELEASE_NOTES_Vx.x.md`
9. **打标签**：
   ```bash
   git tag v1.x.0
   git push origin v1.x.0
   ```
10. **分发**：
    - Windows：直接分发 `dist/CSAM_Repair.exe`
    - macOS：需代码签名 + 公证后分发

## 环境变量运维参考

下表列出所有运维相关环境变量及其作用。默认值标注于括号内。

### MATLAB Server

| 环境变量 | 默认值 | 作用 |
|----------|--------|------|
| `CSAM_MATLAB_BIND` | `tcp://*:5570` | MATLAB Server 监听地址（解析为 host/port） |
| `CSAM_MATLAB_PORT` | `5570` | MatlabEngine 连接端口 |
| `CSAM_MATLAB_LOG_DIR` | `<repo>/logs` | MATLAB Server 日志目录 |
| `CSAM_MATLAB_LOG_LEVEL` | `info` | MATLAB Server 日志级别（debug/info/warn/error） |
| `CSAM_MATLAB_HEARTBEAT_MS` | `1000` | MATLAB Server 心跳间隔（毫秒） |
| `CSAM_MATLAB_MAX_REQ_BYTES` | `67108864`（64 MB） | 单次请求最大字节数 |
| `CSAM_MATLAB_CLEANUP_INTERVAL` | `50` | 内存清理间隔（每 N 次请求触发一次） |
| `CSAM_MATLAB_MEM_THRESHOLD_MB` | `4096` | 内存阈值（MB），超过则触发 `pack` 回收 |

### Bridge 通信层

| 环境变量 | 默认值 | 作用 |
|----------|--------|------|
| `CSAM_BRIDGE_TIMEOUT_MS` | `30000` | 请求超时（毫秒），复杂算法可调大 |
| `CSAM_BRIDGE_HEARTBEAT_MS` | `5000` | Bridge 心跳间隔（毫秒） |
| `CSAM_BRIDGE_MAX_RETRIES` | `3` | 请求最大重试次数 |

### 通用

| 环境变量 | 默认值 | 作用 |
|----------|--------|------|
| `CSAM_LOG_LEVEL` | `INFO` | Python 应用日志级别（DEBUG/INFO/WARNING/ERROR） |
| `CSAM_HMAC_SECRET` | （开发内置密钥） | HMAC 密钥，生产环境必须设置 |
| `CSAM_ENGINE_DISABLE_MATLAB` | `0` | 设为 `1` 强制禁用 MATLAB 引擎，降级到 Python 原型引擎（调试用） |
| `CSAM_ZMQ_ADDRESS` | 平台相关 | ZMQ 连接地址（macOS/Linux 默认 `ipc:///tmp/csam_engine`，Windows 默认 `tcp://127.0.0.1:5555`） |

> 完整环境变量模板参见项目根 `.env.example`。

## 日常运维检查清单

建议每日执行以下检查，确保系统正常运行：

- [ ] MATLAB Server 进程存活
- [ ] 端口 5570（v3.0 / MATLAB TCP）/ 5555（v2.1 / ZMQ）可访问
- [ ] 日志无 `ERROR` 级别条目
- [ ] 磁盘空间充足（`logs/` 与 `morphology_prediction/` 目录）
- [ ] MATLAB 内存不超过阈值（默认 4096 MB）
- [ ] 工具箱许可证有效（`license('test', 'Map_Toolbox')` 返回 `1`）
- [ ] 备份已完成

### 检查命令参考

```powershell
# 检查 MATLAB Server 进程
Get-Process -Name MATLAB -ErrorAction SilentlyContinue

# 检查端口可访问性
Test-NetConnection -ComputerName 127.0.0.1 -Port 5570
Test-NetConnection -ComputerName 127.0.0.1 -Port 5555
```

```matlab
% 在 MATLAB 中检查工具箱许可证
license('test', 'Map_Toolbox')          % 返回 1 表示可用
license('test', 'Curve_Fitting_Toolbox')
```

## 性能调优

### 关键调优参数

| 调优方向 | 环境变量 | 默认值 | 调优建议 |
|----------|----------|--------|----------|
| 请求超时 | `CSAM_BRIDGE_TIMEOUT_MS` | 30000（30 秒） | 复杂算法（如 `profile_predict`、`generate_path`）耗时较长，可调大至 120000 |
| 清理间隔 | `CSAM_MATLAB_CLEANUP_INTERVAL` | 50（每 50 请求） | 内存压力大的场景可调小（如 20），清理频繁会增加 `System.gc()` 开销 |
| 内存阈值 | `CSAM_MATLAB_MEM_THRESHOLD_MB` | 4096 | 根据服务器物理内存调整，超过阈值触发 `pack` 回收 |
| 心跳间隔 | `CSAM_BRIDGE_HEARTBEAT_MS` | 5000 | 网络不稳定时可调小以更快检测断连 |
| 心跳间隔 | `CSAM_MATLAB_HEARTBEAT_MS` | 1000 | MATLAB 侧心跳间隔，与 Bridge 侧配合 |
| 日志级别 | `CSAM_LOG_LEVEL` | INFO | 生产用 `INFO`，排查问题时用 `DEBUG`（注意 DEBUG 日志量大） |
| 日志级别 | `CSAM_MATLAB_LOG_LEVEL` | info | 同上，MATLAB 侧日志级别 |

### 调优原则

1. **生产环境用 `INFO` 级别**：`DEBUG` 日志量大幅增加，影响性能与磁盘占用，仅在排查问题时临时启用。
2. **超时与算法复杂度匹配**：`generate_path`（120000 ms 超时）、`profile_predict`（120000 ms）等复杂算法需要更长的请求超时，确保 `CSAM_BRIDGE_TIMEOUT_MS` 大于算法超时。
3. **内存清理权衡**：`CSAM_MATLAB_CLEANUP_INTERVAL` 调小可降低内存峰值，但 `System.gc()` + `drawnow` 本身有开销，需根据实际负载平衡。
4. **心跳与重连配合**：心跳丢失阈值触发重连，网络不稳定环境可适当调大丢失阈值避免频繁重连。
