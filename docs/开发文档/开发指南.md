## 1. 开发环境搭建

### 1.1 环境要求

- **Python**：3.12（推荐）
- **操作系统**：Windows / macOS / Linux
- **MATLAB**：R2025b（生产算法，可选；无 MATLAB 时可使用 Python 原型降级）

### 1.2 搭建步骤

```bash
# 1. 克隆仓库
git clone <repository-url>
cd industrial-vision

# 2. 创建并激活虚拟环境
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS/Linux

# 3. 安装运行时依赖
pip install -r requirements.txt

# 4. 安装开发依赖（可编辑模式）
pip install -e ".[dev]"

# 5. 运行测试验证环境
pytest repair_app/tests/ repair_app/bridge/tests/ -v

# 6. 安装 pre-commit 钩子
pre-commit install
```

### 1.3 运行时依赖

| 依赖 | 版本要求 | 用途 |
|------|----------|------|
| numpy | >=1.21 | 数值计算 |
| scipy | >=1.7 | 科学计算 |
| shapely | >=1.8 | 几何运算 |
| PySide6 | >=6.4 | GUI 框架 |
| matplotlib | >=3.5 | 可视化 |
| pyzmq | >=24 | ZMQ 通信 |
| protobuf | >=5.26 | 协议序列化 |
| reportlab | >=4.0 | PDF 报告 |
| cryptography | >=41.0 | RSA 许可证验证 |

### 1.4 开发依赖

`pytest`、`pytest-cov`、`pytest-benchmark`、`flake8`、`bandit`、`pyinstaller`

## 4. 编码规范

### 4.1 Python

- **flake8**：代码检查，`max-line-length = 120`
- **bandit**：安全分析
- **pre-commit 钩子**：flake8、bandit、trailing-whitespace、end-of-file-fixer
- 使用 `numpy` 向量化操作而非 Python 循环
- 使用 `np.random.randint` 生成随机数（不使用 `random` 模块）
- 禁止 `try-except-pass`，必须始终记录错误
- 禁止 `np.savez` / `np.load` 配合 `allow_pickle=True`，使用 JSON 存储元数据
- HMAC 密钥从环境变量读取，不硬编码
- 小型 git 提交：每次提交一个逻辑变更，每次最多 5 个文件
- Python 3.10+，要求类型标注

提交前运行：

```bash
pre-commit run --all-files
```

### 4.2 MATLAB

- 注释使用 **ASCII** 字符（R2025b 拒绝非 ASCII 字符）
- **不使用** `clear all` / `fclose all`
- **不使用** `evalin('base', 'pack')`
- 算法函数通过 wrapper 封装后注册，wrapper 负责参数验证、调用原生函数与结果序列化

### 4.3 架构准则

- UI 层不得直接导入 `core/` 或 `communication/` 模块
- 通过 `CoordinationService` 进行 UI 到核心的通信
- 平台相关代码放在 `repair_app/platform/` 中
- 业务逻辑放在 `repair_app/service/` 和 `repair_app/core/` 中

## 6. 性能分析

### 6.1 性能分析工具

项目提供性能分析与基准测试工具：

| 工具 | 用途 |
|------|------|
| `profiler.py` | 性能分析（profiling），定位算法热点 |
| `benchmark.py` | 基准测试（benchmark），量化算法吞吐与延迟 |

### 6.2 运行基准测试

```bash
# 仅基准测试
pytest repair_app/tests/test_stress.py -v --benchmark-only

# 带性能对比
pytest repair_app/tests/test_stress.py -v --benchmark-compare
```

### 6.3 性能基准（参考值）

| 操作 | 数据量 | 耗时 | 吞吐 |
|------|--------|------|------|
| 序列化请求 | 5 万点 | < 1s | > 5 万点/s |
| 反序列化往返 | 2000 点 | < 100ms | - |
| 构建结果 | 500 航点 | < 100ms | - |
| 端到端请求 | 2000 点 | ~150ms | - |

### 6.4 性能优化要点

- 点云使用 **SoA 布局**（Protobuf `repeated float`），比 AoS 减少 20% 序列化体积
- `zmq.Context.instance()` 共享上下文，避免重复创建
- `LINGER=0` 确保 socket 即时释放
- QThread worker 用完即销毁，不持有引用
- 超过 100 万点触发警告日志

## 7. MATLAB 算法集成

MATLAB 算法服务以 `matlab_bridge_server.m`（项目根目录）为入口，MATLAB 作为进程宿主通过 `pyenv` 调用 Python 的 `MatlabAdapter`（`BridgeServer` 子类），对外提供 ZMQ v2.1 协议的算法调用服务。

### 7.1 架构组成

| 组件 | 位置 | 职责 |
|------|------|------|
| `matlab_bridge_server.m` | 项目根目录 | MATLAB 宿主脚本，通过 `pyenv` 启动 Python `MatlabAdapter`，监听 ZMQ 端口 5555 |
| `MatlabAdapter` | `repair_app/bridge/adapters/matlab_adapter.py` | `BridgeServer` 子类，处理修复请求，调用 MATLAB 算法或降级到 Python |
| `MatlabEngineProxy` | `repair_app/bridge/adapters/matlab_engine_proxy.py` | `matlab.engine` 单例封装，连接共享会话，符合 `_algorithm_fn` 签名 |

### 7.2 MATLAB 共享引擎会话

`MatlabEngineProxy` 通过 `matlab.engine.shareEngine('matlab_bridge')` 将当前 MATLAB 会话共享，Python 侧通过 `matlab.engine.connect_matlab('matlab_bridge')` 连接该共享会话，实现反向调用 MATLAB 算法函数。

### 7.3 算法目录

| 目录 | 实际内容 | 主入口函数 |
|------|----------|-----------|
| `路径规划\` | morphology 算法源码（注：目录名与内容相反） | `run_profile_prediction.m` |
| `形貌预测\` | path_planning 算法源码（注：目录名与内容相反） | `run_path_planning.m` |

两个主入口函数：

- `run_path_planning.m`：路径规划算法入口
- `run_profile_prediction.m`：形貌预测算法入口

### 7.4 新增 MATLAB 算法步骤

1. **放置算法源码**：将 `.m` 算法文件放入对应算法目录（`形貌预测\` 或 `路径规划\`，注意目录名与内容的相反关系）
2. **编写 wrapper 函数**：在 `run_path_planning.m` 或 `run_profile_prediction.m` 中添加算法调用入口，wrapper 负责参数验证、调用原生函数与结果序列化
3. **符合 `_algorithm_fn` 签名**：算法函数签名应为 `(xyz, meta) -> waypoints`（路径规划）或 `(xyz, meta) -> dict`（形貌预测）
4. **MATLAB 注释使用 ASCII**：R2025b 拒绝非 ASCII 字符
5. **不使用** `clear all` / `fclose all` / `evalin('base', 'pack')`

### 7.5 降级策略

当 MATLAB 不可用时，`MatlabAdapter` 通过 `_invoke_with_fallback` 自动降级到 `LocalEngine` 的 Python 原型算法，保证生产连续性。降级由 `CSAM_ALGORITHM_ENGINE` 环境变量控制：

| 值 | 行为 |
|-----|------|
| `auto` | 优先 MATLAB，不可用降级 Python（默认） |
| `matlab` | 强制使用 MATLAB，不可用报错 |
| `python` | 强制使用 Python 原型 |

### 7.6 启动 MATLAB 服务端

```matlab
% 在 MATLAB 命令行
cd('D:\work\demo\industrial-vision')
matlab_bridge_server                           % 默认地址
matlab_bridge_server('tcp://127.0.0.1:5555')  % 指定地址
```

## 8. Bridge 通信层开发

`repair_app/bridge/` 是唯一生产通信层，目标是替代旧版 `communication/`。当前生产路径为 **v2.1 协议 + BridgeClient**。

### 8.1 通信链路

```text
MainWindow
  ↓ CoordinationService.create_zmq_client()
CoordinationService
  ↓ 返回 LegacyZmqClient（bridge 适配器，API 与旧版 ZmqRepairClient 完全兼容）
LegacyZmqClient  (bridge/adapters/legacy_adapter.py)
  ↓ 委托
BridgeClient  (bridge/communication/zmq_client.py)
  ↓ ZMQ REQ/REP
matlab_bridge_server.m / MatlabAdapter
```

**通信入口**：`CoordinationService.create_zmq_client()` 是 UI 层获取通信客户端的唯一入口。它返回 bridge 适配器 `LegacyZmqClient`，API 与旧版 `ZmqRepairClient` 完全兼容，便于平滑迁移。

### 8.2 模块说明

| 文件 | 职责 |
|------|------|
| `bridge/adapters/legacy_adapter.py` | `LegacyZmqClient` 适配器，将旧版 API 适配到 `BridgeClient`，保证调用方零改动迁移 |
| `bridge/adapters/matlab_adapter.py` | `MatlabAdapter`（`BridgeServer` 子类），处理修复请求，调用 MATLAB 算法或降级到 Python |
| `bridge/adapters/matlab_engine_proxy.py` | `MatlabEngineProxy`，`matlab.engine` 单例封装 |
| `bridge/communication/zmq_client.py` | `BridgeClient` + `_RequestWorker` + `_HealthWorker`（均为 QThread），异步请求与健康检查 |
| `bridge/communication/zmq_server.py` | `BridgeServer`，ZMQ REP 服务端基类（poll 可中断） |
| `bridge/communication/config.py` | `BridgeConfig`（frozen dataclass），集中所有通信参数，无硬编码值，支持环境变量覆盖 |
| `bridge/communication/exceptions.py` | 结构化异常层次（`BridgeError` 基类及子类）+ `translate_zmq_error` 翻译函数 |
| `bridge/communication/serializer.py` | Protobuf 序列化/反序列化 |
| `bridge/communication/protocol.py` | `MessageType`（IntEnum）、`PROTOCOL_VERSION = "2.1"`、状态码映射 |
| `bridge/communication/message.py` | `MessageEnvelope`、`generate_request_id` |
| `bridge/communication/heartbeat.py` | `HeartbeatMonitor`，心跳机制实现 |
| `bridge/services/matlab_service.py` | `MatlabService` 业务门面（**未接入 GUI**，技术债务） |

### 8.3 异常层次

所有通信层异常继承自 `BridgeError`，业务层只需捕获 `BridgeError`：

```text
BridgeError                      # 基类（携带 request_id）
├── ConnectionError              # 连接失败/中断
│   ├── ConnectionTimeoutError   # 超时（携带 timeout_ms）
│   └── EngineUnavailableError   # MATLAB 引擎未启动/不可达
│       └── EngineCrashError     # 引擎崩溃
├── SerializationError           # 序列化失败
├── InvalidParameterError        # 参数校验失败（携带 parameter）
├── AlgorithmError               # MATLAB 算法执行异常（携带 algorithm）
├── ProtocolError                # 协议版本/格式错误（携带 expected/actual_version）
└── ShutdownError                # 通信层关闭中/已关闭
```

`translate_zmq_error(exc, request_id)` 将底层 `zmq.Again`、`zmq.ZMQError`、`ValueError`、`TypeError` 等翻译为上述结构化异常。

### 8.4 新增通信应使用

```python
# 适配器（与旧版 API 兼容，推荐迁移用）
from repair_app.bridge.adapters.legacy_adapter import LegacyZmqClient

# 业务层门面（推荐）
from repair_app.bridge import MatlabService
```

## 9. GUI 开发

### 9.1 技术栈

- **框架**：PySide6（Qt for Python）
- **可视化**：matplotlib（三维点云渲染）
- **线程模型**：QThread（后台工作线程，避免阻塞 UI 主线程）

### 9.2 UI 模块

| 文件 | 职责 |
|------|------|
| `main_window.py` | 主窗口（God Class，约 1898 行），集成工具栏、画布、停靠面板、工作流、对话框与状态栏 |
| `defect_selector.py` | 缺陷选区控件，处理点云拾取与区域选择（套索、画笔、矩形） |
| `repair_visualizer.py` | 三维可视化器，渲染点云、路径与修复结果 |
| `profile_result_panel.py` | 形貌结果面板，展示预测形貌 |
| `workers.py` | 后台工作线程（QThread），避免阻塞 UI 主线程 |

### 9.3 ProfileResultPanel 开发

`ProfileResultPanel` 负责展示形貌预测结果。开发时注意：

- 通过信号/槽（Signals/Slots）与 `MainWindow` 通信，不直接调用算法模块
- 数据更新通过 `CoordinationService` 获取，不直接访问 `core/`
- 使用 Qt 的模型/视图模式分离数据与展示

### 9.4 Worker 线程开发

后台工作线程（`workers.py`）遵循以下原则：

- 继承 `QThread`，重写 `run()` 方法
- 通过信号（`pyqtSignal`）向 UI 主线程传递结果，禁止直接操作 UI 控件
- 支持协作式中断（200ms poll），不阻塞 Qt 事件循环
- 用完即销毁，不持有引用

## 10. 打包

### 10.1 PyInstaller（生产打包方式）

生产级 spec 文件 `repair_app.spec` 配置如下：

- **打包模式**：单文件 EXE，UPX 压缩
- **隐藏导入**：显式声明 40+ 个模块（所有 `repair_app` 子包、PySide6 模块、protobuf、zmq、matplotlib、scipy、reportlab、cryptography、shapely）
- **运行时钩子**：5 个（`hooks/pyi_runtime_hook.py`），在应用启动前设置 SSL 证书、Qt 插件、matplotlib 配置目录、ZMQ 前缀和字体缓存
- **资源打包**：`material_db.json`、`calibration_db.json`、`repair_protocol.proto`
- **UPX 排除**：Qt DLL（`Qt6Core.dll`、`Qt6Gui.dll` 等）排除压缩以防加载失败
- **模块排除**：`PySide6.QtQml`、`QtQuick`、`QtDesigner`、`QtHelp` 排除以减小体积

### 10.2 平台构建

| 平台 | 命令 | 产物 |
|------|------|------|
| Windows | `build_windows.bat` | `dist/CSAM_Repair.exe`（80-120 MB） |
| macOS | `build_macos.sh` | `dist/CSAM_Repair.app`（需代码签名 + 公证） |
| 手动 | `pyinstaller --clean repair_app.spec` | 同上 |

### 10.3 运行时钩子

`hooks/pyi_runtime_hook.py` 在应用启动前完成以下设置：

- SSL 证书路径
- Qt 插件路径（`QT_PLUGIN_PATH`）
- matplotlib 配置目录
- ZMQ 前缀
- 字体缓存

### 10.4 入口命令

`pyproject.toml` 中 `[project.scripts]` 注册：

```toml
[project.scripts]
csam-repair = "run_app:main"
```

开发安装后可直接执行 `csam-repair` 启动应用。

## 11. 贡献流程

### 11.1 Pull Request 流程

1. Fork 本仓库
2. 创建功能分支：`git checkout -b feature/your-feature`
3. 以小的、逻辑独立的提交进行修改（每次提交一个逻辑变更，每次最多 5 个文件）
4. 运行测试和代码检查：
   ```bash
   pytest repair_app/tests/ repair_app/bridge/tests/ -v
   pre-commit run --all-files
   ```
5. 向 `main` 分支提交 Pull Request

### 11.2 提交信息规范

遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```text
feat: 新增功能 X
fix: 修复问题 Y
refactor: 重构模块 Z
docs: 更新 README
test: 为功能 X 添加测试
```

### 11.3 测试要求

- 所有变更必须通过现有测试：`pytest repair_app/tests/ repair_app/bridge/tests/ -v`
- 新增功能应包含测试
- 目标覆盖率：60%+

### 11.4 架构准则

- UI 层不得直接导入 `core/` 或 `communication/` 模块
- 通过 `CoordinationService` 进行 UI 到核心的通信
- 平台相关代码放在 `repair_app/platform/` 中
- 业务逻辑放在 `repair_app/service/` 和 `repair_app/core/` 中

请提交 Issue 或联系 CSAM 团队。
