# CSAM Repair v1.0 开发者指南

面向新加入的开发者。版本：1.0.0 | 发布日期：2026-07-15。

技术栈：PySide6 GUI + MATLAB 算法 + ZeroMQ Bridge + Protobuf。

---

## 1. 开发环境搭建

### 1.1 前置依赖

- Python 3.10 - 3.12（推荐 3.12，CI 主验证版本）
- MATLAB R2024b+（可选，无 MATLAB 可用 Python 原型引擎调试）
- Git

### 1.2 环境搭建步骤

```powershell
# 1. 克隆代码
git clone <repo-url> industrial-vision
cd industrial-vision

# 2. 创建虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1   # Windows
# source .venv/bin/activate    # macOS/Linux

# 3. 安装开发依赖（含 pytest / pytest-cov / flake8 / bandit / pyinstaller）
python -m pip install --upgrade pip
pip install -e ".[dev]"

# 4. 安装 pre-commit hooks（代码规范自动检查）
pip install pre-commit
pre-commit install

# 5. 配置开发环境变量（参考 .env.example）
$env:QT_QPA_PLATFORM = "offscreen"           # 无头测试
$env:CSAM_ALGORITHM_ENGINE = "python"        # 无 MATLAB 时用原型引擎
$env:CSAM_HMAC_SECRET = "csam_test_secret_2026"

# 6. 启动软件验证
python run_app.py
```

### 1.3 可选：完整日志依赖

```powershell
pip install -e ".[full]"   # 安装 loguru（结构化日志）
```

### 1.4 验证环境

```powershell
# 运行冒烟测试（应 < 2 秒通过）
pytest -m smoke --tb=short -q

# 运行一键测试套件
.\run_all_tests.ps1 -Quick
```

## 3. 架构约束

以下约束是项目的硬性规则，违反会导致 PR 被拒。

### 3.1 Bridge 是唯一生产通信路径

- 生产环境所有 MATLAB 通信**必须**走 `repair_app/bridge/`
- 旧版 `repair_app/communication/zmq_client.py` 仅作回退，不可新增依赖
- UI 层不可直接导入 `bridge.adapters` 或 `bridge.communication`

### 3.2 UI 不直连 core

- UI 层**不得**直接 `import repair_app.core.*`
- UI 层**不得**直接 `import repair_app.communication.*`
- 所有调用必须通过 `service/coordination_service.py`（facade 模式）
- `CoordinationService` 是 UI 与 core/communication 之间的唯一中介

```python
# 正确
from repair_app.service.coordination_service import CoordinationService
service = CoordinationService()
result = service.run_repair(params)

# 错误（违反约束）
from repair_app.core.path_planner import PathPlanner  # 禁止
from repair_app.communication.zmq_client import ZmqRepairClient  # 禁止
```

### 3.3 No Magic Numbers

- 代码中**禁止**出现裸数字常量（如 `if x > 5555:`）
- 所有可配置参数必须定义在 `config/parameter_schema.json`
- 通过 `schema_loader.get_network_value()` 等方法读取
- Schema 是参数的**单一 Truth Source**

### 3.4 单一 Truth Source

- 版本号：`repair_app/__init__.py` 的 `__version__`（打包配置从此读取）
- 参数定义：`config/parameter_schema.json`
- 材料数据：`repair_app/core/material_db.json`
- 标定数据：`config/calibration_db.json`
- Protobuf 协议：`repair_protocol.proto`（生成 `repair_protocol_pb2.py`）

### 3.5 分层依赖方向

```
ui  →  service  →  bridge / core / communication / export
                →  domain（模型共享）
                →  repository（数据访问）
                →  utils（工具）
```

- 上层可依赖下层，下层不可依赖上层
- 同层模块间避免循环依赖
- `domain` 是最底层，不依赖任何业务层

## 4. 测试体系

### 4.1 测试分层（10 个 marker）

项目使用 pytest marker 分层组织测试：

| Marker | 说明 | 触发条件 |
|--------|------|---------|
| `smoke` | 冒烟测试 — 核心 import 与启动验证（<2s） | 每次 PR |
| `regression` | 回归测试 — 关键 bug 修复回归 | 每次 PR |
| `unit` | 单元测试 — 函数 / 类级别 | 全量 |
| `integration` | 集成测试 — 模块间协作 | 全量 |
| `gui` | GUI 测试 — QtBot / QTest | CI offscreen |
| `export` | 导出测试 — G-code / Robot / Report | 全量 |
| `performance` | 性能测试 — pytest-benchmark | 仅主分支 |
| `stress` | 压力测试 — 大数据量 / 极端参数 | 全量 |
| `mock` | Mock 测试 — MATLAB Mock / License Mock | 全量 |
| `slow` | 慢测试 — 运行时间 >2s | 全量 |

### 4.2 一键测试脚本

```powershell
# 完整测试 + 覆盖率
.\run_all_tests.ps1

# 快速模式（仅 smoke + regression）
.\run_all_tests.ps1 -Quick

# 跳过依赖安装
.\run_all_tests.ps1 -SkipInstall

.\run_all_tests.ps1 -NoCoverage
```

- `test_results.json` — 机器可读结果
- `coverage.xml` — CI / Codecov 兼容
- `htmlcov/index.html` — 覆盖率 HTML 报告
- `TEST_REPORT.md` — 人工阅读报告

## 5. 代码规范

### 5.1 错误处理 7 类

所有异常必须归类到 `ErrorCode` 枚举之一（见 `utils/error_manager.py`）：

| ErrorCode | 场景 | 默认恢复策略 |
|-----------|------|-------------|
| `LICENSE` | License 授权无效 / 过期 / 缺失 | fatal |
| `MATLAB` | MATLAB 引擎崩溃 / 算法异常 / 启动失败 | retry |
| `FILE` | 文件读写 / 路径 / 权限 / 磁盘空间 | continue |
| `MESH` | STL 读取 / 点云形状 / 三角化失败 | continue |
| `NETWORK` | ZMQ 连接 / 超时 / 协议 / 序列化 | retry |
| `EXPORT` | G-code / 机器人轨迹 / PDF 报告导出 | continue |
| `UNKNOWN` | 兜底：未分类异常 | continue |

### 5.2 三段式友好消息

用户**永远不看到 Python Traceback**。所有错误通过 `ErrorManager` 转换为三段式消息：

- **What**：发生了什么（一句话）
- **Why**：为什么发生（可能原因）
- **How**：如何解决（具体步骤）

```python
from repair_app.utils.error_manager import ErrorManager, ErrorCode

# 方式 1：手动分类
try:
    risky_operation()
except Exception as exc:
    ErrorManager.handle(exc, ErrorCode.MATLAB, context="路径规划", parent=self)

# 方式 2：装饰器
@ErrorManager.guard(ErrorCode.FILE, context="导出 G-code")
def export_gcode():
    ...

# 方式 3：上下文管理器
with ErrorManager.context(ErrorCode.NETWORK, context="ZMQ 请求"):
    reply = sock.recv()
```

### 5.3 无 Traceback 暴露

- 打包配置 `disable_windowed_traceback=True`
- 所有 `except` 必须经过 `ErrorManager`，禁止裸 `except + QMessageBox`
- 完整 traceback 仅写入 `error_*.log`，供技术员展开查看
- 用户对话框只展示三段式友好消息

### 5.4 错误处理流程

```
try
  ↓
log（LogManager 记录完整 traceback 到 error.log）
  ↓
friendly message（ErrorManager.classify 生成 What/Why/How）
  ↓
detail（保留 exc 供技术员展开）
  ↓
recover（RecoveryStrategy 指明回退动作）
  ↓
continue（用户确认后继续 / 重试 / 退出）
```

### 5.5 代码风格

- 行宽：120 字符（`flake8 max-line-length = 120`）
- Lint：`pre-commit run --all-files`（flake8 + bandit）
- 类型注解：推荐使用 `from __future__ import annotations`
- 日志：使用 `utils/logger_config` 的便捷函数，不直接 `print`

## 6. 添加新算法流程

### 6.1 算法分层

新算法通常分布在三层：

| 层 | 位置 | 职责 |
|----|------|------|
| MATLAB 算法 | `path_planning/` 或 `profile_prediction/` | 实际计算 |
| Python 原型 | `repair_app/core/` | 无 MATLAB 时的降级实现 |
| Bridge 集成 | `repair_app/bridge/adapters/` | MATLAB 调用封装 |

### 6.2 添加步骤

1. **定义 Protobuf 消息**（如需新通信协议）
   - 编辑 `repair_protocol.proto`
   - 运行 `protoc` 生成 `repair_protocol_pb2.py`（勿手改生成代码）

2. **实现 MATLAB 算法**
   - 在 `path_planning/` 或 `profile_prediction/` 新增 `.m` 文件
   - 入口函数遵循 `run_*.m` 命名约定
   - 通过 `matlab_bridge_server.m` 暴露给 Bridge

3. **实现 Python 原型**（降级模式）
   - 在 `repair_app/core/` 新增模块
   - 保持与 MATLAB 算法相同的输入输出契约
   - 用于 `CSAM_ALGORITHM_ENGINE=python` 调试

4. **封装 Bridge 适配器**
   - 在 `repair_app/bridge/adapters/` 扩展 `matlab_adapter.py`
   - 遵循现有适配器模式

5. **暴露给 UI**
   - 通过 `repair_app/service/coordination_service.py` 暴露
   - **不可**让 UI 直接 import 新算法模块

6. **更新参数 Schema**
   - 新参数加入 `repair_app/config/parameter_schema.json`
   - 通过 `schema_loader` 读取，禁止硬编码

7. **编写测试**
   - 单元测试：`repair_app/tests/test_*.py`
   - Mock 测试：使用 `repair_app/tests/mocks/matlab_mock.py`
   - 算法验证：参考 `docs/MATLAB集成/算法验证体系.md`

8. **更新文档**
   - 算法说明：`docs/MATLAB集成/算法说明.md`
   - 验证报告：`docs/MATLAB集成/算法集成报告.md`

### 6.3 算法验证

新算法必须通过双引擎比对验证：

- MATLAB 引擎 vs Python 原型引擎
- 使用 `repair_app/validation/` 模块
- 容差范围内结果一致方可合入

## 7. CI/CD 流程

### 7.1 CI 触发

- Push 到 `main` / `master` / `develop` 分支
- PR 到 `main` / `master` 分支
- 配置文件：`.github/workflows/ci.yml`

### 7.2 CI Job（共 6 个）

| Job | 触发 | 运行环境 | 说明 |
|-----|------|---------|------|
| `smoke-test` | 所有 PR | ubuntu + windows / py3.12 | 冒烟测试，<2min，必须通过 |
| `test` | PR + 主分支 | ubuntu + macos + windows / py3.10-3.12 | 完整测试 + 覆盖率（fail_under=60） |
| `regression-test` | 所有 PR | ubuntu / py3.12 | 回归测试 |
| `gui-test` | 所有 PR | ubuntu / py3.12 | GUI 测试（offscreen） |
| `performance-test` | 仅主分支 | ubuntu / py3.12 | 性能测试（不阻塞） |
| `lint` | 所有 PR | ubuntu / py3.11 | pre-commit（flake8 + bandit） |

### 7.3 依赖关系

```
smoke-test
   ↓
   ├── test（完整矩阵）
   ├── regression-test
   ├── gui-test
   └── performance-test（仅主分支）

lint（独立，无依赖）
```

`smoke-test` 是前置门禁，失败则后续 job 不执行。

### 7.4 本地模拟 CI

```powershell

# 模拟 gui（Linux 风格）
```

- HTML 报告作为 artifact 上传（`coverage-html`）
