## 模块职责

### run_app.py — Python 入口

应用程序启动脚本，被 `pyproject.toml` 的 `[project.scripts]` 注册为 `csam-repair` 命令。负责初始化 Qt 应用、加载配置、启动 MainWindow。

### repair_app/ui/ — GUI 层

PySide6 桌面界面，负责三维点云可视化、缺陷选区交互与工作流编排。

| 文件 | 职责 |
|------|------|
| `main_window.py` | 主窗口（God Class，约 1898 行），集成工具栏、画布、停靠面板、工作流、对话框与状态栏 |
| `defect_selector.py` | 缺陷选区控件，处理点云拾取与区域选择 |
| `repair_visualizer.py` | 三维可视化器，渲染点云、路径与修复结果 |
| `workers.py` | 后台工作线程（QThread），避免阻塞 UI 主线程 |

### repair_app/core/ — 核心算法层

业务无关的算法实现与领域计算。

| 文件 | 职责 |
|------|------|
| `path_planner.py` | 路径规划算法（Python 原型） |
| `morphology_predictor.py` | 形貌预测算法（Python 原型） |
| `feasibility_checker.py` | 修复可行性检查 |
| `material_database.py` + `material_db.json` | 材料数据库及访问层 |
| `normal_estimator.py` | 点云法向量估计 |
| `stl_reader.py` | STL 文件读取 |
| `defect_sample.py` | 缺陷样本模型 |

### repair_app/service/ — 服务层

业务逻辑编排，协调领域层与基础设施。UI 层不得直接调用算法模块，所有业务交互通过服务层进行。

## Bridge 通信层

`repair_app/bridge/` 是新一代通信桥接层，目标是替代旧版 `communication/`。当前生产路径为 **v2.1 协议 + BridgeClient**。

### 通信链路

```
MainWindow
  ↓ _Coord.create_zmq_client()
CoordinationService
  ↓ 返回 LegacyZmqClient（bridge 适配器，API 与旧版 ZmqRepairClient 完全兼容）
LegacyZmqClient  (bridge/adapters/legacy_adapter.py)
  ↓ 委托
BridgeClient  (bridge/communication/zmq_client.py)
  ↓ ZMQ REQ/REP
matlab_bridge_server.m / MatlabAdapter
```

**通信入口**：`CoordinationService.create_zmq_client()` 是 UI 层获取通信客户端的唯一入口。它返回 bridge 适配器 `LegacyZmqClient`，API 与旧版 `ZmqRepairClient` 完全兼容，便于平滑迁移。

### 模块说明

| 文件 | 职责 |
|------|------|
| `bridge/adapters/legacy_adapter.py` | `LegacyZmqClient` 适配器，将旧版 API 适配到 `BridgeClient`，保证调用方零改动迁移 |
| `bridge/communication/zmq_client.py` | `BridgeClient` + `_RequestWorker` + `_HealthWorker`（均为 QThread），异步请求与健康检查 |
| `bridge/communication/config.py` | `BridgeConfig`（frozen dataclass），集中所有通信参数，无硬编码值，支持环境变量覆盖 |
| `bridge/communication/exceptions.py` | 结构化异常层次（`BridgeError` 基类及子类）+ `translate_zmq_error` 翻译函数，业务层永不接触原始 ZMQ 异常 |
| `bridge/communication/serializer.py` | Protobuf 序列化/反序列化 |
| `bridge/communication/protocol.py` | `MessageType`（IntEnum）、`PROTOCOL_VERSION = "2.1"`、状态码映射 |
| `bridge/communication/message.py` | `MessageEnvelope`、`generate_request_id` |
| `bridge/communication/heartbeat.py` | 心跳机制实现 |
| `bridge/services/matlab_service.py` | `MatlabService` 业务门面（**未接入 GUI**，技术债务） |

### 异常层次

所有通信层异常继承自 `BridgeError`，业务层只需捕获 `BridgeError`：

```
BridgeError                      # 基类（携带 request_id）
├── ConnectionError              # 连接失败/中断
│   ├── ConnectionTimeoutError   # 超时（携带 timeout_ms）
│   └── EngineUnavailableError   # MATLAB 引擎未启动/不可达
│       └── EngineCrashError     # 引擎崩溃
├── SerializationError           # 序列化失败
├── InvalidParameterError        # 参数校验失败（携带 parameter）
├── AlgorithmError               # MATLAB 算法执行异常（携带 algorithm）
├── ProtocolError                # 协议版本/格式错误（携带 expected/actual_version）
└── ShutdownError                # 通信层关闭中/已关闭
```

`translate_zmq_error(exc, request_id)` 将底层 `zmq.Again`、`zmq.ZMQError`、`ValueError`、`TypeError` 等翻译为上述结构化异常。

### 新增通信应使用

```python
# 适配器（与旧版 API 兼容，推荐迁移用）
from repair_app.bridge.adapters.legacy_adapter import LegacyZmqClient

# 业务层门面（推荐）
from repair_app.bridge import MatlabService
```

## MATLAB 算法服务

MATLAB 算法服务以 `matlab_bridge_server.m`（项目根目录）为入口，MATLAB 作为进程宿主通过 `pyenv` 调用 Python 的 `MatlabAdapter`（`BridgeServer` 子类），对外提供 ZMQ v2.1 协议的算法调用服务。

### 架构组成

| 组件 | 位置 | 职责 |
|------|------|------|
| `matlab_bridge_server.m` | 项目根目录 | MATLAB 宿主脚本，通过 `pyenv` 启动 Python `MatlabAdapter`，监听 ZMQ 端口 5555 |
| `MatlabAdapter` | `repair_app/bridge/adapters/matlab_adapter.py` | `BridgeServer` 子类，处理修复请求，调用 MATLAB 算法或降级到 Python |
| `MatlabEngineProxy` | `repair_app/bridge/adapters/matlab_engine_proxy.py` | `matlab.engine` 单例封装，连接共享会话，符合 `_algorithm_fn` 签名 |

### MATLAB 共享引擎会话

`MatlabEngineProxy` 通过 `matlab.engine.shareEngine('matlab_bridge')` 将当前 MATLAB 会话共享，Python 侧通过 `matlab.engine.connect_matlab('matlab_bridge')` 连接该共享会话，实现反向调用 MATLAB 算法函数。

### 算法目录

| 目录 | 实际内容 | 主入口函数 |
|------|----------|-----------|
| `路径规划\` | morphology 算法源码（注：目录名与内容相反） | `run_profile_prediction.m` |
| `形貌预测\` | path_planning 算法源码（注：目录名与内容相反） | `run_path_planning.m` |

两个主入口函数：
- `run_path_planning.m`：路径规划算法入口
- `run_profile_prediction.m`：形貌预测算法入口

### 降级策略

当 MATLAB 不可用时，`MatlabAdapter` 通过 `_invoke_with_fallback` 自动降级到 `LocalEngine` 的 Python 原型算法，保证生产连续性。降级由 `CSAM_ALGORITHM_ENGINE` 环境变量控制（`auto` / `matlab` / `python`）。

## 协议

系统当前使用 **v2.1 协议**作为唯一通信路径，GUI 生产环境实际使用。

### v2.1（唯一协议）

| 属性 | 值 |
|------|-----|
| 定义文件 | `repair_protocol.proto` |
| 编码 | Protobuf 二进制 |
| 传输 | ZMQ REQ/REP，端口 5555 |
| 核心消息 | `RepairRequest`、`RepairResult`、`ProgressUpdate`、`HealthCheck` |
| 状态 | 生产环境实际使用 |

v2.1 是业务专用协议，强耦合冷喷涂修复语义（材料类型、修复状态码、工艺参数等）。Python 侧由 `repair_protocol_pb2.py` 提供生成代码，被 bridge 层复用。

### 版本兼容

- `PROTOCOL_VERSION = "2.1"`
- `COMPATIBLE_PROTOCOL_VERSIONS = ("2.0", "2.1")`

## 编码规范

### Python

- **flake8**：代码检查，`max-line-length = 120`
- **bandit**：安全分析
- **pre-commit 钩子**：flake8、bandit、trailing-whitespace、end-of-file-fixer
- 使用 `numpy` 向量化操作而非 Python 循环
- 使用 `np.random.randint` 生成随机数（不使用 `random` 模块）
- 禁止 `try-except-pass`，必须始终记录错误
- 禁止 `np.savez` / `np.load` 配合 `allow_pickle=True`，使用 JSON 存储元数据
- HMAC 密钥从环境变量读取，不硬编码
- 小型 git 提交：每次提交一个逻辑变更，每次最多 5 个文件

### MATLAB

- 注释使用 **ASCII** 字符（R2025b 拒绝非 ASCII 字符）
- **不使用** `clear all` / `fclose all`
- **不使用** `evalin('base', 'pack')`
- 算法函数通过 wrapper 封装后注册，wrapper 负责参数验证、调用原生函数与结果序列化
