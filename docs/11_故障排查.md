## 一、启动失败

### 1.1 Python 启动失败

#### 症状 1：软件无法启动，命令行报错

**可能原因**：Python 未安装或版本不对、依赖未安装、虚拟环境未激活。

**解决方法**：

1. 打开 PowerShell，执行 `python --version`，确认输出为 3.10、3.11 或 3.12 之一
2. 进入软件目录：`cd D:\work\demo\industrial-vision`
3. 激活虚拟环境：`.\venv\Scripts\Activate.ps1`
4. 重新运行：`python run_app.py`
5. 查看命令行输出的错误信息定位原因

#### 症状 2：启动时提示 "No module named 'xxx'"

**解决方法**：按缺失模块补装依赖。

| 缺少的模块 | 解决命令 |
|-----------|---------|
| PySide6 | `pip install PySide6` |
| zmq | `pip install pyzmq` |
| numpy | `pip install numpy` |
| scipy | `pip install scipy` |
| shapely | `pip install shapely` |
| reportlab | `pip install reportlab` |
| cryptography | `pip install cryptography` |

或一次性重装所有依赖：

```
pip install -r requirements.txt
```

#### 症状 3：激活虚拟环境时提示"禁止运行脚本"

**原因**：PowerShell 执行策略限制。

**解决方法**：

```
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

按 Y 确认，然后重新激活虚拟环境。

### 1.2 MATLAB 启动失败

#### 症状 1：找不到 `matlab_bridge_server` 命令

**可能原因**：未进入项目目录、MATLAB 工作路径不正确。

**解决方法**：在 MATLAB 中先切换到项目根目录，再执行启动命令：

```matlab
cd('D:\work\demo\industrial-vision')
matlab_bridge_server
```

#### 症状 2：pyenv 未配置或指向错误的 Python

**原因**：MATLAB 不知道用哪个 Python 解释器来运行 MatlabAdapter。

**解决方法**：在 MATLAB 中显式指定项目虚拟环境的 Python：

```matlab
cd('D:\work\demo\industrial-vision')
pyenv('Version', 'D:\work\demo\industrial-vision\venv\Scripts\python.exe')
matlab_bridge_server
```

确认 `pyenv` 输出的 Version 与项目虚拟环境一致、Status 为 `Loaded`。

#### 症状 3：MATLAB 工具箱（Toolbox）缺失

**原因**：部分算法依赖 `Map_Toolbox`、`Curve_Fitting_Toolbox`。

**解决方法**：在 MATLAB 中执行以下命令检查许可证，返回 1 表示可用：

```matlab
license('test', 'Map_Toolbox')
license('test', 'Curve_Fitting_Toolbox')
```

如返回 0，请联系 IT 续期，或临时切换到本地计算引擎（设置 `CSAM_ALGORITHM_ENGINE=python`）。

#### 症状 4：MATLAB 报"文本字符无效"

**原因**：R2025b 拒绝 `.m` 文件中的非 ASCII 字符，算法文件注释或字符串含中文/特殊符号。

**解决方法**：联系开发者修复 `.m` 文件中的非 ASCII 字符，确保所有注释为纯 ASCII。修复后重启 `matlab_bridge_server`。

### 1.3 GUI 启动失败

#### 症状 1：窗口出现但白屏

**原因**：显卡驱动问题或 OpenGL 渲染异常。

**解决方法**：

1. 更新显卡驱动到最新版
2. 设置环境变量后重新启动：
   ```powershell
   $env:QT_QPA_PLATFORM="windows"
   python run_app.py
   ```
3. 如仍有问题，尝试切换 OpenGL 后端：
   ```powershell
   $env:QT_OPENGL="angle"
   python run_app.py
   ```

#### 症状 2：界面字体显示异常或乱码

**原因**：系统语言设置或字体缺失。

**解决方法**：

1. 让技术员把系统区域设置改为"中文（简体，中国）"，勾选"Beta 版 UTF-8 支持"，重启电脑
2. 确认系统已安装中文字体（如微软雅黑、宋体）

#### 症状 3：界面文字太小看不清

**解决方法**：

1. 右键桌面 → 显示设置 → 调整缩放比例到 125% 或 150%
2. 或在软件启动前设置：
   ```powershell
   $env:QT_AUTO_SCREEN_SCALE_FACTOR=1
   python run_app.py
   ```

#### 症状 4：界面布局错乱

**解决方法**：

1. 关闭软件重新启动
2. 检查显示器分辨率是否满足最低要求（1366×768）
3. 多显示器环境下，确保软件窗口在主显示器上

## 二、连接异常

### 2.1 MATLAB 连接失败

#### 症状 1：共享会话未找到

**原因**：MatlabEngineProxy 通过 `matlab.engine.connect_matlab` 连接共享会话失败，会话名称不匹配或 MATLAB 未启动共享会话。

**解决方法**：

1. 确认 MATLAB R2025b 已启动
2. 确认在 MATLAB 中已执行 `matlab_bridge_server` 启动桥接服务
3. 检查环境变量 `CSAM_MATLAB_SHARED_NAME` 是否与服务端会话名称一致
4. 在 MATLAB 中执行 `matlab.engine.engineName` 查看当前会话名称
5. 重启 MATLAB 与桥接服务

#### 症状 2：`connect_matlab` 超时

**原因**：MATLAB 启动慢、会话未就绪、防火墙拦截。

**解决方法**：

1. 等待 MATLAB 完全启动后再启动桥接服务
2. 在 PowerShell 中验证端口监听：
   ```powershell
   Get-NetTCPConnection -State Listen -LocalPort 5555
   ```
3. 如端口未监听，重启 `matlab_bridge_server`
4. 检查防火墙是否放行 5555 端口

#### 症状 3："远程服务"选项灰色

**原因**：MATLAB 服务未启动或未正确配置。

**解决方法**：

1. 确认 MATLAB R2025b 已安装
2. 在 MATLAB 中执行：
   ```matlab
   cd('D:\work\demo\industrial-vision')
   pyenv('Version', 'D:\work\demo\industrial-vision\venv\Scripts\python.exe')
   matlab_bridge_server
   ```
3. 等待 MATLAB 显示服务已启动
4. 在 PowerShell 中验证端口：`Get-NetTCPConnection -State Listen -LocalPort 5555`

### 2.2 ZMQ 连接失败

#### 症状 1：端口 5555 被占用

**原因**：另一个程序（或之前未正常关闭的本软件进程）正在使用该端口。

**解决方法**：

1. 检查任务栏和系统托盘，关闭所有之前打开的软件实例
2. 查找占用端口的进程并结束：
   ```powershell
   Get-NetTCPConnection -State Listen -LocalPort 5555 | Select-Object OwningProcess
   Get-Process -Id <上一步得到的PID> | Stop-Process
   ```
3. 重启电脑后重试
4. 如需更换端口，修改环境变量 `CSAM_ZMQ_ADDRESS`，例如：
   ```powershell
   $env:CSAM_ZMQ_ADDRESS="tcp://127.0.0.1:5556"
   ```
   注意：Python 端和 MATLAB 端必须使用相同的地址

#### 症状 2：防火墙拦截

**解决方法**：

1. 在 Windows 防火墙"高级安全设置"中添加入站规则，允许 5555 端口的 TCP 流量
2. 如使用企业防火墙，联系 IT 放行该端口
3. 临时关闭防火墙测试是否为防火墙问题（仅用于排查，排查后及时开启）

#### 症状 3：ZMQ 地址配置错误

**原因**：`CSAM_ZMQ_ADDRESS` 格式错误或两端配置不一致。

**解决方法**：

1. 确认地址格式正确：Windows 用 `tcp://127.0.0.1:5555`，macOS/Linux 可用 `ipc:///tmp/csam_engine`
2. 确认 Python 端和 MATLAB 端使用相同地址
3. 确认 IP 地址可达（跨机通信时使用实际 IP，不是 127.0.0.1）

### 2.3 Bridge 通信错误

#### 症状 1：请求超时

**原因**：MATLAB 算法计算慢、网络不稳定、MATLAB 进程卡死。

**解决方法**：

1. 查看 MATLAB 命令窗口是否有错误输出
2. 如果 MATLAB 卡住，在 MATLAB 中按 Ctrl+C 终止服务
3. 重新启动服务：在 MATLAB 中再次运行 `matlab_bridge_server`
4. 复杂算法（如 `generate_path`、`profile_predict`）调大超时：
   ```powershell
   $env:CSAM_BRIDGE_TIMEOUT_MS="120000"
   ```
5. 重试请求

#### 症状 2：序列化失败

**原因**：请求或响应数据无法通过 Protobuf 序列化，通常是输入参数类型不对或数据量过大。

**解决方法**：

1. 查看日志中 `request.crash` 事件的详细错误
2. 检查输入参数是否符合接口要求（点云格式、参数范围）
3. 减小点云数据量后重试
4. 如持续失败，联系开发者并提供日志

#### 症状 3：协议版本不匹配

**原因**：Python 端与 MATLAB 端协议版本（当前 v2.1）不一致，通常发生在升级后只重启了一端。

**解决方法**：

1. 确认两端运行同一版本软件
2. 升级后必须同时重启 MATLAB 算法服务（`matlab_bridge_server`）和 GUI（`python run_app.py`）
3. 如回滚版本，两端都需回滚并重启

## 三、算法错误

### 3.1 路径规划失败

#### 症状 1：STL 格式相关问题

**原因**：本软件直接处理点云（CSV/TXT/XYZ/ASC），不支持直接加载 STL。

**解决方法**：

1. 使用三维扫描仪或转换工具把 STL 转换为点云格式（CSV/TXT/XYZ/ASC）
2. 确认点云文件至少有 3 列数字（x, y, z 坐标）
3. 把文件复制到简单路径（如 D:\test\）再加载

#### 症状 2：参数无效

**原因**：路径规划参数超出允许范围。

**解决方法**：

1. 检查参数是否在范围内：
   - 层高：0.1-10 mm
   - 扫描角度：-90 到 90°
   - 扫描步长：0.1-10 mm
   - 规划层数：1-50
2. 输入框变红表示数值非法，按提示修改
3. 重新生成路径

#### 症状 3：MATLAB 算法异常

**原因**：MATLAB 算法函数报错，可能是工具箱缺失、数据异常、算法 bug。

**解决方法**：

1. 查看 MATLAB 命令窗口的完整错误信息
2. 查看日志中 `request.crash` 事件
3. 检查工具箱许可证：`license('test', 'Map_Toolbox')`
4. 尝试用演示数据复现，排除数据问题
5. 临时切换到本地计算引擎：`$env:CSAM_ALGORITHM_ENGINE="python"`
6. 联系开发者并提供 MATLAB 错误信息与日志

### 3.2 形貌预测失败

#### 症状 1：CFD（计算流体动力学）数据缺失

**原因**：形貌预测依赖速度场等 CFD 中间数据，文件缺失或损坏。

**解决方法**：

1. 检查 `morphology_prediction/` 目录是否存在 `pointlist.npz`、`velocitylist.json` 等中间文件
2. 如缺失，重新执行路径规划与形貌预测
3. 从备份恢复 `morphology_prediction/` 目录
4. 检查磁盘空间是否充足

#### 症状 2：mesh（网格）生成失败

**原因**：点云数据质量差、缺陷区域选取不合理、参数极端。

**解决方法**：

1. 重新选取缺陷区域，确保覆盖完整缺陷
2. 调整扫描步长（如改为 1-2 mm）
3. 减小规划层数
4. 检查点云数据是否有异常坐标（如 NaN、极端值）
5. 切换计算引擎重试

#### 症状 3：预测结果为空

**解决方法**：

1. 检查右侧"结果摘要"，看填充点数是否为 0
2. 如果为 0，可能是参数不合理（粒子速度不足、送粉速度过低）
3. 增大粒子速度（必须大于临界速度）、增大送粉速度
4. 重新执行预测

### 3.3 降级触发条件及日志识别

#### 降级触发条件

当 `CSAM_ALGORITHM_ENGINE=auto`（默认）时，以下情况会自动降级到 Python 原型算法：

- MATLAB 共享会话未找到或连接超时
- MATLAB 算法调用抛出异常
- Bridge 通信失败（心跳丢失、引擎连接丢失）
- MATLAB 工具箱许可证失效

#### 日志识别

降级事件通过以下日志关键字识别（logger 名 `csam.bridge.matlab`）：

| 关键字 | 含义 |
|--------|------|
| `fallback.invoke` | 已触发降级，改用 Python 原型算法 |
| `engine.lost` | MATLAB 引擎连接丢失 |
| `heartbeat.miss` | Bridge 心跳丢失 |
| `adapter.crash` | MatlabAdapter 崩溃 |
| `request.crash` | 请求处理崩溃 |

> 降级后系统会继续工作，但精度可能降低。运维人员发现频繁降级时，应排查 MATLAB 服务稳定性。

## 四、导出问题

### 4.1 G-code 导出失败

#### 症状 1：文件权限不足

**原因**：目标文件夹没有写入权限。

**解决方法**：

1. 换一个有写入权限的文件夹（如桌面、D 盘根目录）
2. 右键目标文件夹 → 属性 → 安全 → 确保当前用户有"写入"权限
3. 避免导出到系统保护目录（如 C:\Program Files）

#### 症状 2：路径无效

**原因**：文件名含特殊字符、路径含中文或空格、路径过长。

**解决方法**：

1. 用纯英文或数字命名文件（如 `20260714_partA.nc`）
2. 保存到简单路径（如 `D:\export\`）
3. 避免路径总长度超过 260 字符（Windows 限制）

#### 症状 3：提示"安全检查未通过"

**原因**：航点坐标有异常值（如 NaN、无穷大、超出合理范围）。

**解决方法**：

1. 重新生成路径
2. 检查点云数据是否有异常坐标
3. 调整路径规划参数后重试
4. 查看命令行错误日志定位具体航点

### 4.2 PDF 报告导出失败

#### 症状 1：reportlab 未安装

**解决方法**：

```
pip install reportlab
```

安装后重新启动软件。

#### 症状 2：中文字体问题

**原因**：系统缺少中文字体，或 reportlab 未正确注册中文字体。

**解决方法**：

1. 确认系统已安装中文字体（如微软雅黑、宋体）
2. 确认字体文件未损坏
3. 联系开发者确认字体注册逻辑

#### 症状 3：图片缺失

**原因**：形貌预测未完成或结果为空，导致 PDF 中无法嵌入对比图。

**解决方法**：

1. 确认已完成形貌预测且结果不为空
2. 确认右侧"结果摘要"中填充点数大于 0
3. 重新执行形貌预测后再导出

#### 症状 4：导出卡住

**解决方法**：

1. 等待 30 秒，导出大型 PDF 可能需要时间
2. 如 1 分钟后仍无响应，参考[六、恢复操作](#六恢复操作)处理
3. 强制关闭后重新打开，重新导出

## 五、性能问题

### 5.1 MATLAB 计算慢

#### 症状 1：独立启动延迟

**原因**：MATLAB 启动本身需要几秒到几十秒，加载工具箱、初始化 Python 解释器（pyenv）也需时间。

**解决方法**：

1. 保持 MATLAB 与桥接服务长期运行，避免频繁重启
2. 使用共享引擎会话（默认行为），多个请求复用同一会话
3. 启动后第一次调用算法会较慢，后续调用会快很多

#### 症状 2：首次编译慢

**原因**：MATLAB 算法首次调用时需要 JIT 编译，第一次明显慢于后续。

**解决方法**：

1. 耐心等待首次调用完成
2. 如可接受，预先用演示数据跑一遍完整工作流"预热"算法
3. 检查 MATLAB 内存是否超过阈值（默认 4096 MB），内存不足会导致频繁交换

#### 症状 3：超时频繁

**解决方法**：

1. 调大请求超时：
   ```powershell
   $env:CSAM_BRIDGE_TIMEOUT_MS="120000"
   ```
2. 减小点云数据量或规划层数
3. 检查 MATLAB 服务器硬件资源（CPU、内存）

### 5.2 GUI 卡顿

#### 症状 1：3D 渲染卡顿

**原因**：点云数据量大、显卡性能不足、显卡驱动旧。

**解决方法**：

1. 减小点云数据量（在扫描时降低密度，或让技术员精简）
2. 更新显卡驱动
3. 关闭其他占用显卡资源的程序
4. 尝试切换 OpenGL 后端：`$env:QT_OPENGL="angle"`
5. 在显示设置中关闭不必要的可视化效果（如逐层动画）

#### 症状 2：大数据量响应慢

**解决方法**：

1. 减小点云数据量（一般几百万个点够用）
2. 减小规划层数
3. 增大扫描步长
4. 关闭其他占内存的程序
5. 增加电脑内存到 16GB

### 5.3 内存占用高

#### 症状：软件或 MATLAB 内存持续增长

**解决方法**：

1. 定期清理 `morphology_prediction/` 目录的旧中间文件
2. 定期清理 `logs/` 目录（默认 30 天滚动，可手动清理）
3. 关闭其他占内存的程序
4. 检查 MATLAB 内存是否超过阈值（默认 4096 MB），超过时重启 MATLAB 服务
5. 减小规划层数与点云数据量
6. 如经常不足，考虑升级内存到 16GB

## 六、恢复操作

### 6.1 MATLAB Bridge 崩溃恢复

#### 步骤

1. 确认 MATLAB 进程是否已退出（任务管理器查看）
2. 如 MATLAB 进程仍在但无响应，在 MATLAB 中按 Ctrl+C 终止服务，或直接结束 MATLAB 进程
3. 重新启动 MATLAB
4. 在 MATLAB 中重新运行：
   ```matlab
   cd('D:\work\demo\industrial-vision')
   pyenv('Version', 'D:\work\demo\industrial-vision\venv\Scripts\python.exe')
   matlab_bridge_server
   ```
5. 等待 MATLAB 显示服务已启动
6. GUI 侧重试当前操作，或重新生成修复方案
7. 检查 `logs/app_*.log`（logger 名 `csam.bridge.matlab`）确认崩溃原因

### 6.2 GUI 崩溃恢复

#### 步骤

1. `crash_handler` 会自动记录崩溃日志到 `logs/` 目录

### 6.3 完整重置步骤

## 七、日志分析

### 7.1 日志位置

系统日志统一由 Python 应用日志管理，输出到 `logs/` 目录。

| 日志文件 | 级别 | 滚动策略 | 保留期 |
|----------|------|----------|--------|
| `logs/app_{date}.log` | 全部级别（DEBUG 及以上） | 单文件 10 MB 滚动 | 30 天 |
| `logs/error_{date}.log` | ERROR 及以上 | 按日期滚动 | 60 天 |
| `logs/structured_{date}.jsonl` | 全部级别（JSONL 结构化，可选） | 按日期滚动 | 30 天 |
| 控制台 | 全部级别 | — | 彩色输出 |

> MatlabAdapter 运行于 MATLAB 宿主进程内，但其日志通过 Python logger 输出（logger 名 `csam.bridge.matlab`），与 Python 应用日志统一管理，同样输出到 `logs/` 目录。

### 7.2 日志级别

日志级别由环境变量 `CSAM_LOG_LEVEL` 控制，同时影响 Python 应用日志与 MatlabAdapter 日志。

| 级别 | 用途 |
|------|------|
| `DEBUG` | 最详细，排查问题时临时启用（日志量大，影响性能） |
| `INFO` | 生产环境默认，记录关键事件 |
| `WARNING` | 仅警告及以上，关注潜在问题 |
| `ERROR` | 仅错误及以上，定位故障起点 |

**配置方法**：

```powershell
# Windows PowerShell
$env:CSAM_LOG_LEVEL = "DEBUG"

# macOS/Linux
export CSAM_LOG_LEVEL=DEBUG
```

生产环境默认 `INFO`，排查问题时切换为 `DEBUG`。

### 7.3 关键日志关键词

排查问题时重点检索以下关键词：

| 关键词 | 含义 | 处理建议 |
|--------|------|----------|
| `fallback.invoke` | MATLAB 不可用，已降级到 Python 原型 | 排查 MATLAB 服务状态 |
| `engine.lost` | MATLAB 引擎连接丢失 | 检查 MATLAB 进程与网络 |
| `heartbeat.miss` | Bridge 心跳丢失 | 检查网络稳定性、MATLAB 负载 |
| `request.crash` | 请求处理崩溃 | 查看详细错误，定位算法或通信问题 |
| `adapter.start` | MatlabAdapter 启动成功 | 确认服务启动的依据 |
| `adapter.stop` | MatlabAdapter 停止 | 确认服务停止的依据 |
| `request.start` | 请求处理开始（携带 request_id） | 按 request_id 关联全链路 |
| 超时 / timeout | 请求超时 | 调大 `CSAM_BRIDGE_TIMEOUT_MS` 或优化算法 |
| 连接失败 / connect failed | 连接 MATLAB 或 ZMQ 失败 | 检查端口、防火墙、会话名称 |

### 7.4 日志分析技巧

1. **按 `request_id` 关联全链路**：每个请求分配唯一 `request_id`，在 Python 与 MATLAB 日志中均可检索，用于追踪完整调用链。
2. **`error` 级别优先排查**：`error_{date}.log` 仅记录 ERROR 及以上，是定位故障的起点。
3. **结构化日志便于聚合**：`structured_{date}.jsonl` 可导入 ELK / Loki 等日志平台进行聚合分析。
4. **MATLAB 日志与 Python 日志交叉比对**：同一 `request_id` 在两侧均有记录，可定位通信层与算法层的边界问题。

## 八、日常运维检查清单

建议每日执行以下检查，确保系统正常运行。

### 8.1 端口 5555 检查

```powershell
# 检查端口监听状态
Get-NetTCPConnection -State Listen -LocalPort 5555

# 测试端口连通性
Test-NetConnection -ComputerName 127.0.0.1 -Port 5555
```

- [ ] 端口 5555 处于监听状态
- [ ] 端口可连通

### 8.2 MATLAB 进程检查

```powershell
# 检查 MATLAB 进程
Get-Process -Name MATLAB -ErrorAction SilentlyContinue
```

- [ ] MATLAB 进程存活
- [ ] `matlab_bridge_server` 运行中（MATLAB 命令窗口可见服务已启动）

```matlab
% 在 MATLAB 中检查工具箱许可证
license('test', 'Map_Toolbox')          % 返回 1 表示可用

```

- [ ] 工具箱许可证有效

- [ ] `logs/` 目录存在且可写
- [ ] 当日 `app_{date}.log` 有新内容
- [ ] `error_{date}.log` 无新增 ERROR 条目
- [ ] 无 `engine.lost`、`heartbeat.miss` 频繁出现
- [ ] 无非预期的 `fallback.invoke`（除非 MATLAB 维护期）

- [ ] 系统盘剩余空间充足（建议 > 10GB）
- [ ] `logs/` 目录未异常膨胀（DEBUG 级别日志量大）

- [ ] git 仓库已推送到远程

| 检查项 | 频率 | 命令/方法 |
