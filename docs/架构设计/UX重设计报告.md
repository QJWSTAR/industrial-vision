## 一、目标用户画像

### 1.1 用户是谁

| 用户类型 | 典型背景 | 使用场景 | 核心诉求 |
|----------|----------|----------|----------|
| 工艺工程师 | 材料工程背景，不写代码 | 评估修复方案可行性 | 导入 STL → 看结果 → 导出报告 |
| 算法工程师 | 有 MATLAB 经验，不写 Python | 验证算法效果 | 换参数 → 看对比 → 导数据 |
| 科研人员 | 学术背景，偶尔使用 | 论文实验 | 快速跑通 → 截图 → 导报告 |

### 1.2 用户不会做的事

- 不会打开命令行运行 `python run_app.py`
- 不会在 MATLAB 中运行 `matlab_bridge_server`
- 不会配置 `pyenv`、环境变量、虚拟环境
- 不会复制 `pointlist.npz`、`velocitylist.json`
- 不会阅读开发文档来理解工作流

### 1.3 用户期望

> "我双击图标，软件打开。我导入一个零件，点一下'开始计算'，等几分钟，看到结果，导出报告。就这样。"

## 二、现有流程 vs 优化后流程

### 2.1 启动流程对比

#### 现有流程（用户需要 7 步）

```
用户操作                    系统行为
─────────────────────────────────────────────
1. 打开命令行               —
2. cd 到项目目录             —
3. 激活 venv                —
4. python run_app.py        启动 GUI
                            ├ 创建 ZmqClient（不连接）
                            ├ 加载 License（仅日志）
                            └ 300ms 后加载演示数据
5. 切到 MATLAB 窗口          —
6. cd 到项目目录             —
7. 运行 matlab_bridge_server 共享引擎 + 启动 Bridge
```

**问题**：
- 用户需要同时操作命令行 + MATLAB
- 5 步手动操作才能让软件可用
- 如果忘记启动 MATLAB，软件会降级但用户不知道原因

#### 优化后流程（用户 0 步）

```
用户操作                    系统行为
─────────────────────────────────────────────
（双击桌面图标）             启动 GUI
                            ├ 显示启动遮罩"正在初始化..."
                            ├ 自动检测 MATLAB 安装路径（注册表）
                            ├ 自动启动 MATLAB Bridge 子进程
                            │   └ matlab_bridge_server.m（后台无窗口）
                            ├ 自动连接 ZeroMQ（tcp://127.0.0.1:5555）
                            ├ 自动检查 License
                            ├ 自动检查 Toolbox（Mapping/Curve Fitting）
                            ├ 自动加载上次配置
                            └ 显示主界面（就绪）
```

**用户无需任何操作，等待 15-30 秒自动就绪。**

### 2.2 计算流程对比

#### 现有流程（用户需要 12+ 步）

```
步骤 1：路径规划（7 步）
─────────────────────────
1.  点"加载点云"            弹出文件对话框
2.  选择点云文件            加载点云
3.  切换到"选取模式"         —
4.  拖动鼠标选取缺陷区域     高亮选区
5.  选择材料                下拉框
6.  选择计算引擎            "远程服务(MATLAB)"
7.  点"生成修复路径"         调用 MATLAB（等待 10-30s）
                            └ 结果返回，更新 3D 视图

步骤 2：形貌预测（3 步）
─────────────────────────
8.  点"02 形貌预测"          切换面板
9.  调整冷喷涂参数           10 个参数
10. 点"执行形貌预测"         调用 MATLAB（等待 20-60s）
                            └ 结果返回，更新 ProfileResultPanel

步骤 3：导出（2 步）
─────────────────────────
11. 点"导出 G-code"         弹出保存对话框
12. 选择保存位置             写入 .nc 文件

（如果要 PDF 还要 2 步）
13. 点"导出 PDF 报告"
14. 选择保存位置
```

**问题**：
- 用户需要理解"路径规划"和"形貌预测"是两个独立步骤
- 需要手动切换面板
- 需要选择计算引擎（普通用户不知道选什么）
- 需要调整 10+ 个参数才能开始
- 导出需要分两次操作

#### 优化后流程（用户 3 步）

```
步骤 1：导入
─────────────────────────
1.  拖拽 STL 到窗口          或点"导入"按钮
                            ├ 自动识别零件类型
                            ├ 自动检测缺陷区域（算法）
                            └ 自动推荐材料

步骤 2：开始计算
─────────────────────────
2.  点"开始计算"             一键执行：
                            ├ 自动路径规划（MATLAB）
                            ├ 自动形貌预测（MATLAB）
                            ├ 自动结果可视化
                            └ 自动生成报告（缓存）

步骤 3：导出
─────────────────────────
3.  点"导出"                 一键导出：
                            ├ G-code（.nc）
                            ├ PDF 报告
                            └ 可选：STL、CSV
```

**从 12+ 步减少到 3 步。**

### 2.3 流程对比总表

| 维度 | 现有流程 | 优化后流程 | 改善 |
|------|----------|------------|------|
| 启动手动操作 | 7 步 | 0 步 | -100% |
| 计算手动操作 | 12+ 步 | 3 步 | -75% |
| 需要理解的步骤 | 5 个阶段 | 1 个按钮 | -80% |
| 需要配置的参数 | 20 个 | 3 个（材料/层数/速度） | -85% |
| 需要操作 MATLAB | 是 | 否 | 消除 |
| 需要命令行 | 是 | 否 | 消除 |

    def start_bridge(self) -> subprocess.Popen:
        """后台启动 MATLAB Bridge 子进程（无窗口）。"""

#### 5.3 一键计算流程

新增 `ComputePipeline` 类，串联路径规划→形貌预测→可视化→报告：

```python
# 伪代码 — repair_app/service/compute_pipeline.py（新增）
class ComputePipeline(QThread):
    """一键计算管线，串联所有计算步骤。"""

    stages = [
        ("路径规划", self._run_path_planning),
        ("形貌预测", self._run_profile_prediction),
        ("可视化生成", self._run_visualization),
        ("报告生成", self._run_report),
    ]

    stage_changed = Signal(str, int)  # (stage_name, progress)
    finished = Signal(dict)           # results
    failed = Signal(str)              # error
```

## 十三、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| MATLAB 未安装 | 无法启动 Bridge | 检测失败时提示安装，降级到 Python |
| MATLAB 版本不兼容 | 算法执行失败 | 版本检查，R2024b 以下警告 |
| Toolbox 缺失 | 算法报错 | 启动时检查，提示安装 |
| 端口 5555 被占用 | Bridge 启动失败 | 自动尝试 5556-5560 |
| 自动缺陷检测不准 | 选区错误 | 允许用户手动修正 |
| 子进程崩溃 | Bridge 断开 | 自动重启 + 降级 |
| 首次启动慢（>30s） | 用户焦虑 | 进度条 + 预估时间 |

## 十四、总结

### 核心改变

| 维度 | 现有 | 目标 |
|------|------|------|
| 启动方式 | 命令行 + MATLAB 手动 | 双击 .exe，全自动 |
| 操作步骤 | 22-33 次点击 | 4 次点击 |
| 参数配置 | 20 个参数 | 3 个关键参数 |
| 计算流程 | 分步手动执行 | 一键自动串联 |
| 状态反馈 | 程序日志 | 人类可读状态 |
| MATLAB 操作 | 用户手动 | 后台自动 |
| 首次体验 | 需读文档 | 向导引导 |

### 最终目标

> **一个第一次接触软件的人，无需阅读开发文档，5 分钟内即可完成：导入 STL → 运行 MATLAB 算法 → 查看结果 → 导出报告。整个过程中不需要手动操作 MATLAB，不需要运行 main.m，不需要复制任何中间文件。**
