# MATLAB 生命周期管理文档

> 版本：1.0.0 | 协议：v2.1 | 更新日期：2026-07-14 | 文档语言：简体中文

> 本文档描述软件对 MATLAB 的完整生命周期管理。
> 普通用户无需打开 MATLAB，软件负责启动、监控、崩溃恢复和退出清理。

---

## 一、设计目标

### 1.1 用户要求

| 要求 | 实现状态 |
|------|---------|
| 普通用户无需打开 MATLAB | ✅ 自动以 `-batch` 模式启动，无 GUI 窗口 |
| 软件负责 MATLAB 生命周期管理 | ✅ 完整生命周期：启动 → 监控 → 恢复 → 退出 |
| 软件启动自动检测 MATLAB R2025b | ✅ 优先检测 R2025b，向下兼容到 R2022a |
| Bridge 未启动时自动启动 | ✅ `MatlabBridgeLauncher.start()` |
| 检测 Bridge Ready | ✅ 端口轮询（5555） |
| 软件退出 MATLAB 自动关闭 | ✅ `atexit` + `closeEvent` + `aboutToQuit` 三重清理 |
| MATLAB 崩溃自动重连恢复 | ✅ 看门狗 3 秒轮询 + 自动重启（最多 3 次） |

### 1.2 已彻底解决的问题

| 问题 | 根因 | 解决方案 |
|------|------|---------|
| 共享 Session 失败 | Python 在 MATLAB pyenv 内运行却用 `find_matlab()` 跨进程发现 | `CSAM_BRIDGE_IN_MATLAB=1` 环境变量 + `connect_matlab()` 直接连接 |
| Ctrl+C 无法退出 | `signal.signal(SIGINT, stop)` 吞咽中断信号 | 移除 signal handler，让 KeyboardInterrupt 自然传播 |
| MATLAB 僵尸进程 | `zmq.Context.instance()` 全局单例从不 terminate + 子进程未正确清理 | 独立 Context + `_cleanup()` + 三阶段强制清理（terminate → kill → taskkill） |

### 3.2 MATLAB 版本检测

**优先级**：R2025b > R2025a > R2024b > R2024a > R2023b > R2023a > R2022b > R2022a

**查找顺序**：

1. 环境变量 `CSAM_MATLAB_EXE`（用户指定路径）
2. PATH 中的 `matlab` 命令
3. Windows: `C:\Program Files\MATLAB\R20XXx\bin\matlab.exe`
4. macOS: `/Applications/MATLAB_R20XXx.app/bin/matlab`
5. Linux: `/usr/local/MATLAB/R20XXx/bin/matlab`

**版本解析**：从路径中匹配 `R\d{4}[ab]` 格式（如 R2025b）。

### 3.3 Bridge 就绪检测

- **端口**：5555（ZMQ REP/REQ）
- **检测方式**：`socket.connect((127.0.0.1, 5555))`，超时 0.5s
- **轮询间隔**：1 秒
- **超时**：120 秒（MATLAB 首次启动较慢）
- **进程退出检测**：`process.poll() is not None` → 立即失败

### 3.4 MATLAB 启动命令

```bash
matlab.exe -batch "cd('D:/work/demo/industrial-vision'); matlab_bridge_server"
```

**关键参数**：
- `-batch`：不显示 MATLAB GUI 窗口，静默执行脚本
- `CREATE_NEW_PROCESS_GROUP`（Windows）：确保 Ctrl+C 不会传递到 MATLAB 子进程
- `stdout=PIPE`：捕获 MATLAB 输出用于调试

## 四、关闭流程

### 4.1 触发方式

| 触发方式 | 处理 |
|---------|------|
| 用户点击窗口关闭按钮 | `MainWindow.closeEvent` → `manager.stop()` |
| 用户 Ctrl+C（命令行启动） | KeyboardInterrupt → `app.quit()` → `aboutToQuit` → `manager.stop()` |
| 软件崩溃 | `atexit.register(launcher.stop)` 兜底清理 |
| 系统关机/注销 | OS 发送 SIGTERM → `atexit` 兜底清理 |

### 4.2 关闭流程

```
触发关闭
    ↓
MainWindow.closeEvent()
    ├── 中断计算线程（requestInterruption + quit + terminate）
    ├── _compute_worker.stop_launcher()  ← 关闭一键计算的 launcher
    ├── MatlabLifecycleManager.get_instance().stop()
    │       ↓
    │   LifecycleManager.stop()
    │       ├── _enabled = False
    │       ├── _stop_watchdog()
    │       │   └── QTimer.stop() + deleteLater()
    │       └── launcher.stop()
    │               ↓
    │       MatlabBridgeLauncher.stop()
    │           ├── 检查 reused_existing → 复用模式不关闭
    │           ├── 阶段 1: terminate() (SIGTERM)
    │           │   └── wait(timeout=10s)
    │           │       └── 成功 → 返回
    │           ├── 阶段 2: kill() (SIGKILL)
    │           │   └── wait(timeout=5s)
    │           │       └── 成功 → 返回
    │           └── 阶段 3: _force_kill_os(pid)
    │               ├── Windows: taskkill /F /T /PID
    │               └── Linux/macOS: kill -9
    │
    └── zmq_client.close()
    ↓
app.aboutToQuit → on_about_to_quit()
    └── manager.stop()  ← 再次调用（幂等，确保清理）
    ↓
atexit (兜底)
    └── launcher.stop()  ← 已注册的 atexit 回调
```

### 4.3 三阶段强制清理

| 阶段 | 信号 | 超时 | 说明 |
|------|------|------|------|
| 1. 优雅关闭 | SIGTERM (terminate) | 10s | 让 MATLAB 执行 onCleanup 清理 |
| 2. 强制终止 | SIGKILL (kill) | 5s | 直接终止进程 |
| 3. OS 级清理 | taskkill /F /T | 5s | Windows 终止整个进程树 |

**保证**：无论 MATLAB 处于何种状态，三阶段清理后都不会有僵尸进程。

## 五、异常恢复流程

### 5.1 崩溃检测

**看门狗**（`MatlabLifecycleManager._watch_tick`）：

- **轮询间隔**：3000ms
- **检测条件**：
  - 自启动模式：`process.poll() is not None`（进程已退出）
  - 复用模式：`not _is_port_open(5555)`（端口不可连接）
- **状态过滤**：仅在 `READY` 状态下检测（`BUSY` 状态跳过，避免计算中误判）

### 5.2 自动重启流程

```
看门狗轮询 (每 3 秒)
    ↓
detect_crash() == True?
    ├── No → 继续监控
    └── Yes ↓
         _set_status(CRASHED, "MATLAB 进程已退出（返回码=X）")
         ↓
         auto_restart_enabled?
         ├── No → 保持 CRASHED 状态，等待用户手动处理
         └── Yes ↓
              QTimer.singleShot(100ms, _try_restart)
              ↓
          _try_restart()
              ├── restart_count < MAX_RESTARTS (3)?
              │   ├── No → _set_status(FAILED, "重启次数耗尽")
              │   └── Yes ↓
              │        _set_status(RESTARTING, "正在重启...")
              │        ↓
              │    launcher.restart()
              │        ├── restart_count += 1
              │        ├── sleep(2s)  ← 避免立即崩溃循环
              │        ├── 清理旧进程（kill + wait）
              │        ├── self._process = None
              │        └── self.start(timeout=120s)
              │            ├── 成功 → _set_status(READY)
              │            └── 失败 → _set_status(CRASHED)
              │                       └── 下次轮询再次尝试
              ↓
          重启成功？
              ├── Yes → 计算成功后 reset_restart_count()
              └── No → 等待下次轮询或达到 MAX_RESTARTS
```

### 5.3 重启限制

| 参数 | 值 | 说明 |
|------|---|------|
| `MAX_RESTARTS` | 3 | 最大自动重启次数 |
| `RESTART_DELAY_S` | 2.0 | 重启前等待时间（避免崩溃循环） |
| `STARTUP_TIMEOUT_S` | 120 | 每次启动超时 |
| `WATCH_INTERVAL_MS` | 3000 | 看门狗轮询间隔 |

**重置条件**：计算成功后调用 `reset_restart_count()`，重置计数器。

### 5.4 计算中的崩溃保护

- **`mark_busy()`**：计算开始前调用，状态变为 `BUSY`，看门狗暂停崩溃检测
- **`mark_idle()`**：计算结束后调用，状态恢复 `READY`，看门狗恢复监控
- **目的**：避免计算过程中 MATLAB 短暂无响应被误判为崩溃

## 六、已解决问题详解

### 6.1 共享 Session 失败

**根因**：Python 在 MATLAB pyenv 宿主模式内运行，却用 `find_matlab()` 跨进程发现 MATLAB 会话，导致连接失败。

**解决方案**：
- `matlab_bridge_server.m` 设置 `setenv('CSAM_BRIDGE_IN_MATLAB', '1')`
- `matlab_engine_proxy.py` 的 `_ensure_connected()` 检测此环境变量
- 检测到后直接 `connect_matlab(shared_name)`，跳过 `find_matlab()`

### 6.2 Ctrl+C 无法退出

**根因**：`signal.signal(SIGINT, stop)` 安装的信号处理器吞咽了 `KeyboardInterrupt`，导致 Ctrl+C 只触发 `stop()` 函数而不传播异常。

**解决方案**：
- `zmq_server.py` 的 `install_signal_handlers()` 改为空操作
- `KeyboardInterrupt` 自然传播到 MATLAB，触发 `onCleanup` 清理
- MATLAB 子进程使用 `CREATE_NEW_PROCESS_GROUP`，Ctrl+C 不会传递到子进程

### 6.3 MATLAB 僵尸进程

**根因**：
1. `zmq.Context.instance()` 全局单例从不 `terminate()`
2. MATLAB 子进程在父进程退出时未被正确清理

**解决方案**：
1. `zmq_server.py` 改用独立 `zmq.Context()` + `_cleanup()` 完整释放链
2. `MatlabBridgeLauncher` 三阶段强制清理：
   - `terminate()` (SIGTERM) → wait 10s
   - `kill()` (SIGKILL) → wait 5s
   - `taskkill /F /T /PID` (Windows) 或 `kill -9` (Linux)
3. `atexit.register(launcher.stop)` 兜底清理
4. `app.aboutToQuit` 信号触发清理
5. `MainWindow.closeEvent` 触发清理

## 十一、使用指南

### 11.1 普通用户

1. 双击"启动软件.bat"
2. 软件自动启动 MATLAB（状态栏显示 🟡 → 🟢）
3. 导入 STL → 选取缺陷 → 点击"🚀 开始计算"
4. 软件退出时自动关闭 MATLAB（无需手动操作）

### 11.2 MATLAB 未在默认路径

设置环境变量：
```
set CSAM_MATLAB_EXE=D:\your\path\to\matlab.exe
```

或在系统 PATH 中添加 MATLAB 的 `bin` 目录。

### 11.3 故障排查

| 问题 | 解决方案 |
|------|---------|
| 状态栏显示 ⛔ FAILED | 检查 MATLAB 安装，设置 `CSAM_MATLAB_EXE` |
| 状态栏显示 🔴 CRASHED | 等待自动重启（最多 3 次），查看日志 |
| 启动超时（120s） | MATLAB 首次启动较慢，可手动启动 `matlab_bridge_server` |
| 端口 5555 被占用 | 确保无其他程序占用，或重启软件 |
| MATLAB 僵尸进程 | 软件三阶段清理已杜绝；若仍存在，手动 `taskkill /F /IM matlab.exe` |
