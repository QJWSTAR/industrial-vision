## 1. 概述

CSAM Repair 是一款跨平台（macOS、Windows、Linux）桌面应用，用于冷喷涂增材制造（Cold Spray Additive Manufacturing，CSAM）的缺陷修复。基于 PySide6（Qt for Python）构建，提供交互式三维点云可视化工作流，涵盖点云处理、路径规划、形貌预测、可行性检查与工业导出（G-code / 机器人指令 / PDF 报告）。

### 1.1 关键技术栈

| 维度 | 选型 |
|------|------|
| GUI 框架 | PySide6（Qt for Python） |
| 可视化 | matplotlib |
| 通信 | ZeroMQ（REQ/REP） + Protocol Buffers v2.1 |
| 算法 | MATLAB R2025b（生产） + Python 原型（降级） |
| 打包 | PyInstaller（单文件 EXE / macOS .app） |
| Python | 3.12 |

### 1.2 唯一生产通信路径

GUI 通过 `CoordinationService.create_zmq_client()` 获取通信客户端，经 ZeroMQ（`tcp://127.0.0.1:5555`，Protobuf v2.1）与 MATLAB 宿主进程通信。`repair_app/bridge/` 是唯一生产通信路径，旧版 `repair_app/communication/` 已弃用（仅保留 `repair_protocol_pb2.py` 供 bridge 复用）。

### 2.1 分层说明

| 层 | 主要职责 | 关键模块 |
|----|----------|----------|
| 表现层（UI） | 用户交互、三维可视化、任务调度 | `repair_app/ui/` |
| 服务层 | 中介 UI 与底层，屏蔽实现细节 | `CoordinationService` |
| 通信层（Bridge） | ZMQ v2.1 Protobuf，唯一生产通信路径 | `repair_app/bridge/` |
| 领域层 | 接口抽象与领域模型 | `repair_app/domain/` |
| 引擎层 | 仅 `LocalEngine`（Python 原型，降级用） | `repair_app/engine/local_engine.py` |
| 核心层 | Python 原型算法（路径规划、形貌预测、可行性） | `repair_app/core/` |
| 基础设施层 | 数据访问、平台抽象、导出、工具 | `repository/`、`platform/`、`export/`、`utils/` |

> **注意**：本项目不存在控制器层（controller/）。工作流协调由 `MainWindow` 与 `CoordinationService` 共同承担。

### 4.2 本地数据流（降级或纯 Python 路径）

```
点云（CSV/TXT/XYZ）
  → FileService.load_point_cloud()
  → DefectSelector（交互式选取）
  → PathPlanningWorker（QThread）
    → PathPlanner（核心算法）
    → Waypoints（ndarray）
  → MorphologyWorker（QThread）
    → MorphologyPredictor（核心算法）
    → Repair points（ndarray）
  → ExportService
    → G-code（.nc）或 PDF 报告
```

### 4.3 关键特征

- 协议版本：v2.1（`PROTOCOL_VERSION = "2.1"`，定义于 `bridge/communication/protocol.py`）
- 序列化：Protobuf 二进制
- 端口：5555
- MATLAB 不可用时，`MatlabAdapter` 通过 `_invoke_with_fallback` 自动降级到 `LocalEngine`（Python 原型）

## 5. 降级策略

`MatlabAdapter` 在 auto 模式下，当 MATLAB 调用失败时通过 `_invoke_with_fallback` 自动降级到 `LocalEngine` 的 Python 原型算法，保证生产连续性。降级行为由环境变量 `CSAM_ALGORITHM_ENGINE` 控制。

### 5.1 三种模式

| 模式 | 值 | 行为 | 适用场景 |
|------|-----|------|----------|
| 自动 | `auto` | 优先 MATLAB，不可用降级 Python（默认） | 生产环境 |
| 强制 MATLAB | `matlab` | 强制使用 MATLAB，不可用报错 | 算法精度验证 |
| 强制 Python | `python` | 强制使用 Python 原型 | 调试、无 MATLAB 环境 |

### 5.2 降级流程

```
┌──────────────┐    MATLAB 调用失败     ┌─────────────────────┐
│ MatlabAdapter│ ─────────────────────▶ │ _invoke_with_fallback│
│ .handle_repair│                       └──────────┬──────────┘
└──────────────┘                                   │
                                                   ▼
                                       ┌──────────────────────┐
                                       │  auto 模式？          │
                                       └──────────┬──────────┘
                                                  │
                          ┌───────────────────────┴───────────────────────┐
                          ▼                                               ▼
                  ┌──────────────┐                                ┌──────────────┐
                  │ 是：降级      │                                │ 否：抛出      │
                  │ → LocalEngine │                                │ MatlabAlgorithm│
                  │  (Python 原型)│                                │ Error         │
                  └──────────────┘                                └──────────────┘
```

### 5.3 降级相关异常

`MatlabAlgorithmError`（定义于 `bridge/adapters/matlab_adapter.py`）表示 MATLAB 算法执行失败。在 `matlab` 模式下，该异常会向上抛出；在 `auto` 模式下，触发降级到 `LocalEngine`。

## 6. 部署拓扑

### 6.1 单机部署（Windows 工作站）

生产环境为单机部署：Python GUI 进程与 MATLAB 宿主进程运行于同一台 Windows 工作站，通过 ZMQ 回环地址通信。

```
┌─────────────────────────────────────────────────────────────┐
│                   Windows 工作站（单机）                      │
│                                                             │
│  ┌────────────────────┐         ┌────────────────────────┐  │
│  │   Python GUI 进程   │         │  MATLAB 宿主进程        │  │
│  │  (PySide6 + ZMQ)   │         │  (matlab_bridge_server  │  │
│  │                    │  ZMQ    │   .m + MatlabAdapter)    │  │
│  │  tcp://127.0.0.1   │◄───────►│  :5555                  │  │
│  │      :5555         │  5555   │  (pyenv 调用 Python)     │  │
│  └────────────────────┘         └────────────────────────┘  │
│                                                             │
│  config/calibration_db.json  ← 标定（Python 侧读取）         │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 端口分配

| 端口 | 协议 | 用途 | 进程 |
|------|------|------|------|
| 5555 | ZMQ v2.1（Protobuf） | 生产通信（唯一路径） | `matlab_bridge_server.m` |

> 系统仅使用 5555 一个端口。未来若需逐层进度推送，可预留 PUB 5556（`ProgressUpdate` 消息已在 proto 中定义）。

### 6.3 跨平台传输地址

`platform/transport.py` 按操作系统选择传输地址，可由环境变量 `CSAM_ZMQ_ADDRESS` 覆盖：

| 平台 | 默认传输地址 | 说明 |
|------|-------------|------|
| Windows | `tcp://127.0.0.1:5555` | TCP 回环 |
| POSIX（Linux/macOS） | `ipc:///tmp/csam_engine` | Unix 域套接字 |

## 7. 关键架构决策

| 决策 | 说明 | 影响 |
|------|------|------|
| Bridge 是唯一生产通信路径 | 旧版 `communication/` 已弃用但保留（`repair_protocol_pb2` 仍被 bridge 复用） | 兼容性回退，代码冗余待清理 |
| GUI 通过 CoordinationService 访问底层 | UI 不直接调用 `core/` / `communication/` | 解耦 UI 与实现，便于替换通信层 |
| MATLAB 通过 pyenv 宿主 Python | MATLAB 作为进程宿主启动 Python `MatlabAdapter`（`BridgeServer` 子类），共享引擎会话供反向调用 | MATLAB 与 Python 同进程，避免跨进程通信开销 |
| auto 模式降级策略 | MATLAB 不可用时 `MatlabAdapter` 通过 `_invoke_with_fallback` 自动降级到 `LocalEngine` Python 原型 | 保证生产连续性，由 `CSAM_ALGORITHM_ENGINE` 控制 |
| 标定置于 Python 侧 | `config/calibration_db.json` + `calibration_wizard.py` | MATLAB 保持纯计算，标定与 UI 同进程 |
| 引擎抽象 | `IEngine` 接口仅 `LocalEngine` 实现（降级用）；MATLAB 算法走 Bridge 通信路径，不实现 `IEngine` | 接口与通信解耦 |
| 单一配置来源 | `utils/config.py` 的 `PARAM_SPECS` 定义所有参数边界；`BridgeConfig` 集中通信参数 | 配置一致性 |
| 平台抽象 | 所有操作系统相关代码隔离在 `repair_app/platform/` | 跨平台可移植 |

## 8. 已知架构问题

| 问题 | 位置 / 证据 | 影响 |
|------|------------|------|
| MainWindow God Class | `repair_app/ui/main_window.py`（约 1898 行） | 单文件承担过多职责（工具栏、画布、停靠面板、工作流、对话框、状态栏），难维护，应拆分 |
| 通信层无自动重连 | `bridge/communication/zmq_client.py` | 连接断开后不会自动恢复，需用户重启操作 |
| 异常类型丢失 | `bridge/communication/zmq_client.py:279` | 底层异常未被翻译为结构化 `BridgeError`，业务层难以区分错误类型 |
| 心跳丢失不触发重连 | `bridge/communication/heartbeat.py` | `HeartbeatMonitor` 检测到心跳丢失时仅告警，不触发自动重连 |
| MatlabService 未接入 GUI | `bridge/services/matlab_service.py` | 门面已实现但 GUI 仍通过 `LegacyZmqClient` 直接访问，架构纯洁性受损 |
| 旧版 communication/ 未删除 | `repair_app/communication/` | `zmq_client.py` 已弃用但保留，`repair_protocol_pb2.py` 仍被 bridge 复用 |
| HMAC 密钥硬编码回退 | — | 存在硬编码回退值，生产环境必须通过 `CSAM_HMAC_SECRET` 覆盖 |
| 版本号不一致 | 多处 | `__version__`、协议版本、server 版本存在不一致 |
