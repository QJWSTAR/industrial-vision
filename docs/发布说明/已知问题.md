# 已知问题 — CSAM 修复软件 V1.0.0

**版本**：1.0.0 (正式版 Stable Release)
**发布日期**：2026-07-15
**来源**：RC 审查报告（docs/archive/RC_REVIEW.md）

本文件汇总 V1.0.0 正式版的全部已知问题，分两类：

- **已知限制（设计决策）**：当前版本有意保留的设计选择，不影响功能正确性。
- **已知缺陷（待修复）**：需要在后续版本中修复的问题，均不阻塞 V1.0.0 发布。

每个问题包含：ID、严重度、描述、影响、缓解措施、计划修复版本。

---

## 一、已知限制（设计决策）

### L-1. verify_feature 功能门禁缺失

- **ID**：L-1（对应 RC 审查 C-4）
- **严重度**：低
- **描述**：`LicenseManager` 未实现 `verify_feature` 方法，License 中的 `features` 字段当前不参与功能判定。
- **影响**：当前所有用户获得全部功能，功能门禁失效。V1.0 为全功能授权版本，无分级 License 需求，因此不影响发布。
- **缓解措施**：V1.0 全功能授权，无分级场景；生产模式 License 仍校验签名、机器码与有效期。
- **计划修复版本**：V1.1（实现功能门禁）

### L-2. 开发模式 HMAC 密钥硬编码回退

- **ID**：L-2（对应 RC 审查 C-6）
- **严重度**：低
- **描述**：`license_manager.py` 中 `_DEV_HMAC_FALLBACK = "csam_dev_secret_2026"` 硬编码于源码，开发模式未设置 `CSAM_HMAC_SECRET` 时回退使用该密钥。
- **影响**：仅影响开发模式。生产模式（frozen）正确使用空密钥并拒绝验证，不受影响。
- **缓解措施**：生产部署必须通过环境变量 `CSAM_HMAC_SECRET` 覆盖；frozen 模式下空密钥直接拒绝，无回退路径。
- **计划修复版本**：V1.1（开发模式改为强制环境变量注入）

### L-3. License 验证顺序非最优

- **ID**：L-3（对应 RC 审查 C-7）
- **严重度**：低
- **描述**：签名验证在机器码/过期检查之后执行，理论上允许渐进式篡改探测。
- **影响**：低。公钥已从 `_MEIPASS` 只读目录加载（B-3 修复），篡改 License 无法通过签名验证，攻击面已被收敛。
- **缓解措施**：公钥只读加载已生效；HMAC 空密钥在生产模式正确拒绝。
- **计划修复版本**：V1.1（调整验证顺序：签名优先）

## 二、已知缺陷（待修复）

### D-1. MATLAB 算法调用无超时

- **ID**：D-1（对应 RC 审查 C-5）
- **严重度**：中
- **描述**：`matlab_engine_proxy.py` 中 `call_timeout_s` 参数已定义但从未使用，MATLAB 调用阻塞时 GUI 无超时退出路径。
- **影响**：MATLAB 卡死时 GUI 永久阻塞，操作员无法判断系统状态，存在工业安全隐患。
- **缓解措施**：ZMQ 层有 30s 超时部分缓解；MATLAB 算法经验证卡死概率低；卡死时可手动关闭 MATLAB 进程触发降级。
- **计划修复版本**：V1.1（异步调用 + 超时，需 MATLAB Engine API `background=True`）

### D-2. 测试覆盖率低于阈值

- **ID**：D-2（对应 RC 审查 COV-1）
- **严重度**：低
- **描述**：测试覆盖率为 49.97%，低于 60% 阈值。402 个测试全部通过，零回归。
- **影响**：部分代码路径未被测试覆盖，存在回归风险。
- **缓解措施**：核心路径（Bridge / License / 降级策略 / G-code 校验）已覆盖；端到端验证 27 项全部通过。
- **计划修复版本**：V1.1（覆盖率提升至 80%）

### D-3. GUI 硬编码 QSS 样式

- **ID**：D-3（对应 RC 审查 M-2 / M-3）
- **严重度**：低
- **描述**：`dialogs.py`（约 50+ 处）与 `main_window.py`（约 25 处）直接使用 `setStyleSheet("color:#DC2626;")` 等硬编码色值，未走 ThemeManager。
- **影响**：Light 主题下对话框仍为深色配色，视觉撕裂；主题切换不彻底。
- **缓解措施**：默认使用暗色工业主题，视觉一致；不影响功能。
- **计划修复版本**：V1.1（统一改用 ThemeManager token）

### D-4. 架构违规：UI 层直接导入底层模块

- **ID**：D-4（对应 RC 审查 M-1）
- **严重度**：低
- **描述**：`workers.py` 直接 `from repair_app.core.path_planner import ...`；`main_window.py` 有 6 处延迟导入 bridge 层，绕过 CoordinationService。
- **影响**：UI 层与底层模块耦合，可维护性下降。不影响功能正确性。
- **缓解措施**：Bridge 仍是唯一生产通信路径；延迟导入限定在事件回调内，未破坏分层边界。
- **计划修复版本**：V1.1（扩展 CoordinationService facade，暴露迭代器/生命周期接口）

### D-5. README 与 MATLAB 自动化行为矛盾

- **ID**：D-5（对应 RC 审查 M-4）
- **严重度**：低
- **描述**：`README.md` 指导用户手动打开 MATLAB、运行 `matlab_bridge_server`，与代码的自动启动行为（launcher 以 `-nodesktop -nosplash -r` 模式拉起 MATLAB）矛盾。
- **影响**：操作员按 README 手动操作可能与 lifecycle_manager 冲突。
- **缓解措施**：发布说明已明确 MATLAB 由软件自动启动；用户手册以自动启动行为为准。
- **计划修复版本**：V1.0.x（发布后立即更新 README）

### D-6. STL 读取缺少畸形文件防护

- **ID**：D-6（对应 RC 审查 M-5）
- **严重度**：低
- **描述**：`stl_reader.py` ASCII 解析未检查 `parts` 长度；`f.readlines()` 无大小限制。
- **影响**：恶意或畸形 STL 文件可导致崩溃或 OOM。工业环境中 STL 来源可控，风险低。
- **缓解措施**：仅加载受信任来源的 STL 文件；ASCII 解析异常会被全局钩子捕获并报告。
- **计划修复版本**：V1.1（增加输入校验与大小限制）

### D-7. 异常报告泄露敏感路径

- **ID**：D-7（对应 RC 审查 M-6）
- **严重度**：低
- **描述**：`exception_reporter.py` 生成的报告包含 `sys.executable` 完整路径、用户数据目录与完整 traceback。
- **影响**：异常报告若被不当分享可能泄露部署信息。
- **缓解措施**：异常报告默认写入本地目录，不自动外发；分享前需人工审查。
- **计划修复版本**：V1.1（对路径脱敏）
