# 安装包说明 — CSAM Repair V1.0.0

> **版本**：1.0.0（正式版） ｜ **发布日期**：2026-07-15 ｜ **面向角色**：发布工程师
> **打包工具**：PyInstaller（repair_app.spec） ｜ **目标平台**：Windows 10/11 64 位

本文档面向发布工程师，说明 CSAM Repair v1.0.0 正式版的安装包类型、构建流程、验证清单与常见问题处理。

---

## 1. 安装包类型

v1.0.0 提供三种交付形态，按优先级排列：

| 类型 | 文件名 | 适用场景 | 说明 |
|------|--------|----------|------|
| **Portable ZIP** | `CSAM_Repair_v1.0.0_Windows_x64.zip` | 默认发布形态 | 解压即用，无需安装，绿色分发 |
| **Installer EXE** | `CSAM_Repair_v1.0.0_Windows_x64.exe` | 需要开始菜单快捷方式的场景 | 由 Portable ZIP 二次封装为 NSIS/Inno Setup 安装器（可选） |
| **Source** | `industrial-vision-1.0.0.zip` | 开发者或自定义构建场景 | 源码包，需自行配置 Python 环境并打包 |

> 推荐默认分发 **Portable ZIP**。如需安装版，由发布工程师使用 NSIS 或 Inno Setup 将 ZIP 封装为 EXE 安装器，详见第 7 节。

## 2. 构建步骤（build_windows.bat 详解）

### 2.1 前置条件

- Windows 10/11 64 位
- Python 3.10–3.12（推荐 3.12），已加入 PATH
- 项目源码完整（含 `repair_app.spec`、`requirements.txt`、`build_windows.bat`）
- 磁盘空间 ≥ 5 GB（构建临时文件 + dist 产物）
- 建议在项目根目录执行，路径中避免中文与空格

### 2.2 一键构建

在 PowerShell 或 CMD 中切换到项目根目录，执行：

```powershell
.\build_windows.bat
```

脚本会自动完成 6 个步骤：

| 步骤 | 动作 | 说明 |
|------|------|------|
| [1/5] | 检查 Python 环境 | 验证 `python --version` 可用，未安装则中止并提示下载链接 |
| [2/5] | 安装依赖包 | `pip install -r requirements.txt` + `pip install pyinstaller`，约 5–10 分钟 |
| [3/5] | 验证关键模块 | 检查 PySide6、zmq、protobuf、numpy、matplotlib、reportlab、cryptography 可正常导入 |
| [4/6] | 检查 License 密钥对 | 若 `config\public_key.pem` 不存在，调用 `license_manager keygen` 生成 RSA-2048 密钥对 |
| [5/6] | 清理旧构建 | 删除 `build\` 与 `dist\` 目录，保证产物干净 |
| [6/6] | 运行 PyInstaller | `python -m PyInstaller --clean repair_app.spec`，约 3–10 分钟 |

### 2.3 打包配置关键项（repair_app.spec）

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 入口脚本 | `run_app.py` | GUI 主入口 |
| 输出名称 | `CSAM_Repair` | 生成 `dist\CSAM_Repair.exe` |
| 模式 | onefile | 单文件 EXE，首次启动解压到临时目录 |
| `console` | `False` | 关闭控制台窗口，纯 GUI 应用 |
| `disable_windowed_traceback` | `True` | 禁用 traceback 弹窗，避免泄露内部信息 |
| `upx` | `True` | 启用 UPX 压缩，减小体积 |
| `upx_exclude` | Qt6 系列 DLL | Qt DLL 不压缩，避免加载失败 |
| `icon` | `p1.ico` | 应用图标 |
| `runtime_hooks` | `hooks/pyi_runtime_hook.py` | 运行时初始化钩子 |

### 2.4 打包的数据文件

以下文件通过 `repair_app.spec` 的 `datas` 字段打包到 EXE 内部（`sys._MEIPASS`）：

| 源文件 | 打包目标 | 用途 |
|--------|----------|------|
| `repair_app/config/parameter_schema.json` | `repair_app/config/` | 参数 Schema，启动时必需 |
| `repair_app/core/material_db.json` | `repair_app/core/` | 材料数据库 |
| `config/calibration_db.json` | `config/` | 标定配置 |
| `config/public_key.pem` | `config/` | License 验证公钥（只读，安全关键） |
| `matlab_bridge_server.m` | `.` | MATLAB Bridge 服务脚本 |
| `path_planning/` | `path_planning/` | MATLAB 路径规划算法 |
| `profile_prediction/` | `profile_prediction/` | MATLAB 形貌预测算法 |
| `repair_protocol.proto` | `.` | Protobuf 协议定义 |

> `license.key` **不打包进 EXE**，由发布工程师单独放置到 `dist/config/`，详见第 5 节。

## 3. 构建后验证清单

构建完成后，按以下清单逐项确认：

- [ ] `dist\CSAM_Repair.exe` 已生成，文件大小约 180–250 MB
- [ ] `dist\config\public_key.pem` 存在（由 PyInstaller 自动释放）
- [ ] `dist\config\license.key` 已放置（人工放置，见第 5 节）
- [ ] 在**干净虚拟机**（未安装 Python）上双击 EXE 能正常启动主界面
- [ ] 主界面标题显示 `CSAM Repair v1.0.0`
- [ ] 菜单"帮助 → 关于"显示版本号 1.0.0 与发布日期 2026-07-15
- [ ] 加载示例 STL 文件（`path_planning/part.stl`）能正常显示
- [ ] 缺陷选择、可行性判断功能正常
- [ ] 导出 G-code / PDF 报告功能正常
- [ ] 若有 MATLAB R2025b 环境，执行路径规划能自动连接 MATLAB（端口 5555）
- [ ] 首次启动后 `%APPDATA%\CSAM_Repair\` 目录被自动创建
- [ ] SHA256 校验值已计算并记录（见发布包清单.md）

## 4. dist/ 目录结构说明

执行 `build_windows.bat` 后，`dist\` 目录结构如下：

```
dist/
├── CSAM_Repair.exe          # 主程序（单文件，含全部依赖与数据）
└── config/                  # 用户可修改的配置目录（exe 同级）
    ├── public_key.pem       # License 验证公钥（PyInstaller 释放，只读）
    ├── calibration_db.json  # 标定配置（PyInstaller 释放，可修改）
    └── license.key          # 授权文件（人工放置，见第 5 节）
```

### 4.1 配置目录加载优先级

软件运行时，配置目录按以下优先级查找（由 `repair_app/utils/resource_path.py` 实现）：

1. **exe 同级 `config/`**（首选，用户可修改）
2. **`_MEIPASS/config/`**（打包内置默认值，只读回退）

- `license.key`、`calibration_db.json` 从 `config/` 加载，可被用户替换
- `public_key.pem` 安全敏感，**始终从 `_MEIPASS/config/` 加载**（防止目录替换攻击）

### 4.2 内部资源（不暴露给用户）

以下资源打包在 EXE 内部（`sys._MEIPASS`），用户不可见、不可修改：

- `repair_app/config/parameter_schema.json`
- `repair_app/core/material_db.json`
- `matlab_bridge_server.m`
- `path_planning/*.m`
- `profile_prediction/*.m`
- `repair_protocol.proto`

## 5. License 文件部署

### 5.1 文件放置位置

```
dist/
├── CSAM_Repair.exe
└── config/
    ├── public_key.pem    # 验证公钥（自动生成或随包发布）
    └── license.key       # 授权文件（必须人工签发并放置）
```

- `license.key` 必须放在 `dist/config/` 目录下，与 `CSAM_Repair.exe` 同级
- 文件名为固定的 `license.key`，不可改名
- 缺失该文件时，软件启动会提示授权无效

### 5.2 密钥对生成方法

License 采用 RSA-2048 + PSS 签名。密钥对由发布工程师生成一次，长期使用：

```powershell
# 在项目根目录执行（需已安装 cryptography）
python -m repair_app.utils.license_manager keygen
```

执行后会在 `config/` 目录生成：

- `config/public_key.pem` — 公钥（**随软件发布**，打包进 EXE 与 `dist/config/`）
- `config/private_key.pem` — 私钥（**严禁外泄**，由发布工程师妥善保管，权限 0600）

> `build_windows.bat` 的步骤 [4/6] 会在公钥缺失时自动生成密钥对。生产环境建议由发布工程师预先生成并妥善保管私钥。

### 5.3 License 签发方法

为每台目标机器签发专属 License（绑定机器码）：

```powershell
# 用法：python -m repair_app.utils.license_manager issue <用户名> <有效天数>
python -m repair_app.utils.license_manager issue "客户A" 365
```

执行后生成 `config/license.key`，内容包括：

- `machine_id`：目标机器码（自动采集，绑定该机器）
- `issued_to`：授权用户名
- `issued_at` / `expires_at`：签发时间与到期时间
- `features`：授权功能列表（默认 `["basic"]`）
- `max_layers`：最大层数限制（默认 50）
- `signature`：RSA-PSS 签名（无私钥时退化为 HMAC，仅限开发模式）

### 5.4 离线签发流程（生产推荐）

目标机器无法联网时，按以下流程离线签发：

1. 在目标机器上运行软件，记录启动时显示的**机器码**（或运行 `python -m repair_app.utils.license_manager` 查看）
2. 将机器码发送给持有私钥的发布工程师
3. 发布工程师在私钥所在机器上执行签发命令（需修改 `license_manager.py` 支持指定 `machine_id` 参数）
4. 将生成的 `license.key` 文件回传给用户
5. 用户将 `license.key` 放入 `dist/config/` 目录

### 5.5 验证 License 是否生效

```powershell
python -m repair_app.utils.license_manager
```

输出示例：

- 有效：`✅ License 有效 (365 天后到期)`
- 永久授权：`✅ License 有效 (永久授权)`
- 无效：`❌ <具体错误原因>`

## 6. 首次启动验证步骤

按以下顺序验证发布包可用性：

### 6.1 启动前检查

1. 确认 `dist/CSAM_Repair.exe` 与 `dist/config/` 完整
2. 确认 `dist/config/license.key` 已放置
3. 确认 `dist/config/public_key.pem` 存在

### 6.2 启动验证

1. 双击 `dist\CSAM_Repair.exe`（或执行 `启动软件.bat`）
2. 首次启动需 5–10 秒（解压临时文件到 `%TEMP%\_MEIxxxxx`）
3. 主界面正常显示，无白屏或闪退
4. 标题栏显示 `CSAM Repair v1.0.0`
5. 菜单"帮助 → 关于"显示版本信息

### 6.3 功能验证

1. 加载示例 STL 文件，3D 视图正常渲染
2. 在缺陷区域点击选择，可行性判断结果正常显示
3. 执行一次完整的修复流程（路径规划 + 形貌预测）
4. 导出 G-code 与 PDF 报告，文件生成在 `%APPDATA%\CSAM_Repair\exports\`
5. 查看日志：`%APPDATA%\CSAM_Repair\logs\app.log` 无 ERROR 级别记录

### 6.4 MATLAB 联调验证（可选）

若部署环境含 MATLAB R2025b：

1. 软件执行路径规划时**自动启动** MATLAB（参数 `-nodesesktop -nosplash -r matlab_bridge_server`）
2. 用户无需手动操作 MATLAB
3. Bridge 通信建立后，端口 5555 监听正常
4. 路径规划与形貌预测返回真实 MATLAB 计算结果
5. GUI 原生渲染 mesh、逐层轮廓、粒子分布等可视化

## 7. 常见构建问题与解决

| 序号 | 问题现象 | 可能原因 | 解决方法 |
|------|----------|----------|----------|
| 1 | `python --version` 报错 | Python 未安装或未加入 PATH | 安装 Python 3.12，安装时勾选 "Add Python to PATH" |
| 2 | `pip install` 失败 | 网络问题或镜像源不可用 | 配置国内镜像：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| 3 | 模块导入失败（步骤 3） | 依赖未完整安装 | 重新执行 `pip install -r requirements.txt`，或 `pip install PySide6 --force-reinstall` |
| 4 | PyInstaller 报 `ModuleNotFoundError` | `hiddenimports` 列表不完整 | 在 `repair_app.spec` 的 `hiddenimports` 中补充缺失模块 |
| 5 | PyInstaller 报中文路径错误 | 项目路径含中文或空格 | 将项目移动到纯英文无空格路径，如 `D:\work\industrial-vision` |
| 6 | 打包后 EXE 启动闪退 | 缺 VC 运行时或 Qt 插件 | 安装 [VC Redist 2015-2022](https://aka.ms/vs/17/release/vc_redist.x64.exe)；检查 `hooks/pyi_runtime_hook.py` |
| 7 | EXE 启动白屏 | matplotlib 后端冲突 | 设置环境变量 `QT_QPA_PLATFORM=offscreen` 测试；确认 `repair_app.spec` 排除了 `backend_tkagg` 等 |
| 8 | Qt DLL 加载失败 | UPX 压缩了 Qt DLL | 确认 `upx_exclude` 列表包含 `Qt6Core.dll`、`Qt6Gui.dll`、`Qt6Widgets.dll` 等 |
| 9 | License 验证失败 | `license.key` 缺失或机器码不匹配 | 确认 `dist/config/license.key` 存在；按 5.3 节重新签发绑定本机的 License |
| 10 | MATLAB 连接超时 | MATLAB 未安装或 Bridge 未启动 | 确认 MATLAB R2025b 已安装；软件会自动启动 Bridge，无需手动操作；检查端口 5555 未被占用 |
| 11 | 打包体积过大（>300 MB） | 未启用 UPX 或包含冗余模块 | 确认 `upx=True`；检查 `excludes` 列表是否排除了 `PySide6.QtQml`、`QtQuick` 等 |
| 12 | 杀毒软件误报 | UPX 压缩触发启发式规则 | 将 EXE 加入白名单；或考虑关闭 UPX（`upx=False`）并重新打包 |
| 13 | 构建后图标不显示 | `p1.ico` 路径错误或格式不对 | 确认项目根目录存在 `p1.ico`；使用 256×256 多分辨率 ICO 格式 |

### 7.1 日志定位

启动失败但无明示错误时，查看日志：

```
%APPDATA%\CSAM_Repair\logs\app.log
%APPDATA%\CSAM_Repair\logs\error.log
%APPDATA%\CSAM_Repair\logs\crash_*.log
```

### 7.2 临时调试模式

如需查看控制台输出排查问题，临时修改 `repair_app.spec`：

```python
console=True,  # 临时改为 True，查看启动日志
disable_windowed_traceback=False,
```

重新打包后在 CMD 中运行 EXE，观察控制台输出。
