## 一、安装与环境

### Q1. 软件支持哪些操作系统？

主部署平台为 **Windows 10 (1903+) / Windows 11**，并完整支持 **macOS 10.14 (Mojave)+**（含 Apple Silicon M1/M2/M3）。Linux 桌面端未做官方回归测试，但源码层无平台锁，可在具备 Python 3.10+ 与 PySide6 的 Linux 上以源码方式运行。MATLAB Server 通过 `java.net.ServerSocket` 通信，跨平台一致。

| 平台 | 最低版本 | 推荐版本 |
|------|----------|----------|
| Windows | 10 (1903) | 11 |
| macOS | 10.14 Mojave | 13 Ventura+ |
| Linux | — | 源码自行编译，非官方 |

详见 [02 安装指南](02_用户安装指南.md)。

### Q2. 需要什么版本的 Python？

最低 **Python 3.10**，推荐 **3.11 或 3.12**。低于 3.10 不受支持（代码使用了 `from __future__ import annotations`、`str | None` 联合类型语法及 `dataclasses` 新特性）。安装 Python 时请勾选 "Add Python to PATH"。

```powershell
python --version   # 验证，应输出 3.10 及以上
```

### Q3. 需要什么版本的 MATLAB？

启用远程 MATLAB 算法引擎时，推荐 **MATLAB R2025b**（开发与回归基准）。最低兼容 R2021a，但 R2025b 在命令行有若干显示怪癖（见 Q14、Q15），代码已针对性修复。若仅使用本地 Python 引擎，则完全不需要 MATLAB。

### Q4. 必须安装 MATLAB 才能用软件吗？

**不必须。** 软件内置 Python `LocalEngine`（原型引擎），可在无 MATLAB 环境下独立完成路径规划、形貌预测、可行性检查与导出。`EngineFactory.create_engine()` 默认 `auto` 策略：先尝试 `MatlabEngine`，不可达时自动降级到 `LocalEngine`，GUI 始终有可用引擎。

### Q5. 哪些 MATLAB 工具箱是必需的？

**仅 Mapping Toolbox（`Map_Toolbox`）和 Curve Fitting Toolbox（`Curve_Fitting_Toolbox`**），且各自只有 1–2 个算法依赖：

- `Map_Toolbox`：仅 `path_planning.generate_path` 与 `morphology.profile_predict`（用到 `polyxpoly`）。
- `Curve_Fitting_Toolbox`：仅 `morphology.particle_fitting`（用到 `fit`/`fittype`）。

其余 17 个算法仅需基础 MATLAB。缺失工具箱时，对应算法返回 `ERR_DEPS`（见 Q50），其余功能不受影响，Server 健康状态降级为 `DEGRADED`。

### Q6. containers.Map / graph / conncomp 需要工具箱吗？

**不需要。** `containers.Map`、`graph`、`conncomp`、`dfsearch` 均为 **基础 MATLAB** 内置函数（H2 修正项）。`register_algorithms.m` 中 `layer_slice`、`model_process`、`spot_interp`、`classify_removed_triangles`、`improve_short_edges` 等包装器均标注 "base MATLAB only"，不依赖任何工具箱许可证。

### Q7. 如何创建和激活 Python 虚拟环境？

**Windows（PowerShell）：**
```powershell
python -m venv venv
venv\Scripts\activate
```

**macOS / Linux：**
```bash
python3 -m venv venv
source venv/bin/activate
```

激活成功后命令行前缀会出现 `(venv)`。退出使用 `deactivate`。强烈建议在虚拟环境中安装依赖，避免污染全局解释器。

### Q8. pip install 失败怎么办？

按以下顺序排查：

1. **升级 pip**：`pip install --upgrade pip`。
2. **网络问题**：切换国内镜像 `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。
3. **PySide6 二进制过大超时**：单独安装 `pip install PySide6 --force-reinstall`。
4. **Windows 报 "DLL load failed"**：安装 [Visual C++ 2015-2022 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)。
5. **macOS 权限错误**：务必在虚拟环境中安装，不要用系统 Python。
6. **构建依赖缺失（numpy/scipy 编译失败）**：升级至 pip 最新版以获取预编译 wheel。

### Q9. PySide6 安装后导入报错怎么办？

常见原因与对策：

- **`No module named PySide6`**：虚拟环境未激活，或未安装。重新 `pip install PySide6`。
- **`DLL load failed while importing QtWidgets`**：缺少 VC++ 运行库（Windows），安装见 Q8。
- **与 PyQt 冲突**：同一环境同时安装 PyQt5/PyQt6 会冲突，卸载 PyQt：`pip uninstall PyQt5 PyQt6`。
- **OpenGL 渲染异常/白屏**：设置 `set QT_OPENGL=angle`（Windows）强制使用 ANGLE 后端。
- **中文字体缺失**：见 [02 安装指南](02_用户安装指南.md) 中"中文字体渲染问题"。

### Q10. 软件需要多少磁盘空间和内存？

| 资源 | 最低 | 推荐 |
|------|------|------|
| 磁盘（源码 + 依赖） | 500 MB | 1 GB |
| 内存 | 4 GB | 8 GB+ |
| 磁盘（PyInstaller 单文件 exe） | — | 首次解压需额外 ~300 MB 临时空间 |
| 大点云（100K+ 点）规划 | 8 GB | 16 GB+ |

MATLAB Server 进程额外占用内存，长驻运行时由 `resource_cleanup.m` 每 50 请求清理一次（见 Q49）。

## 二、启动与连接

### Q11. 如何启动 MATLAB Server？

在 MATLAB 命令窗口中：

```matlab
cd('D:\work\demo\industrial-vision\matlab_server')
startup
```

`startup.m` 会读取环境变量（见 `config.m`）、自动定位路径规划与形貌预测算法目录（编码无关探测，避免中文目录名乱码），然后启动 `server.run()`。启动成功后会打印 `CSAM MATLAB Server starting on tcp://*:5570 (port 5570), protocol v3.0`。

### Q12. 如何启动 Python GUI？

```powershell
python run_app.py
```

若已 `pip install -e .`，也可使用入口命令 `csam-repair`。GUI 启动后会自动加载 8000 点演示数据（见 Q21），并通过 `EngineFactory` 探测 MATLAB Server。

### Q13. 应该先启动 MATLAB Server 还是 GUI？

**先 Server 后 GUI。** GUI 启动时 `EngineFactory.create_engine("auto")` 会尝试连接 MATLAB Server，若此时 Server 未就绪，将降级到 LocalEngine。先启动 Server 可确保生产路径生效。若 GUI 已先启动，可重启 GUI 或在 GUI 内手动切换引擎。

### Q14. MATLAB R2025b 命令行显示 "Java is not enabled" 怎么办？

这是 **R2025b 的显示怪癖，并非实际禁用**。`version('-java')` 可能打印 "Java is not enabled"，但实际 JVM 已加载。验证方法：

```matlab
usejava('jvm')      % 返回 1 (true) 表示 JVM 可用
java.lang.System.getProperty('java.version')   % 能返回版本号即正常
```

`startup.m`、`server.m`、`json_codec.m` 依赖 `java.net.ServerSocket`、`InputStream.readNBytes` 等 Java API，只要 `usejava('jvm')=1` 即可正常运行，无需额外处理。

### Q15. MATLAB Server 启动报 "文本字符无效" 怎么办？

**原因**：R2025b 拒绝源文件中的非 ASCII 字符（如 em-dash `—`、en-dash `–`、`ö`、`σ` 等）。

**现状**：代码已修复所有 `.m` 文件中的此类字符，统一替换为 ASCII 等价物。

**若再次出现**：

1. 检查最近修改的 `.m` 文件编码，确保为 UTF-8 无 BOM。
2. 搜索非 ASCII 字符并替换（注释中的中文不受影响，问题主要出现在字符串字面量与符号字符）。
3. 临时规避：在 MATLAB 中执行 `feature('DefaultCharacterSet', 'UTF-8')`。

### Q16. GUI 状态栏显示"未连接"怎么办？

表示 MATLAB Server 不可达，GUI 已降级到 LocalEngine。排查：

1. 确认 MATLAB Server 已启动（Q11）。
2. 确认端口一致：默认 5570（`CSAM_MATLAB_PORT` / `CSAM_MATLAB_BIND`）。
3. 检查防火墙是否放行 5570（见 [06 故障排查](06_故障排查.md) §2）。
4. 若仅用本地引擎，"未连接"属正常状态，可忽略。

### Q17. 如何强制使用本地计算引擎？

设置环境变量：

```powershell
set CSAM_ENGINE_DISABLE_MATLAB=1
python run_app.py
```

`EngineFactory._create_matlab_engine()` 检测到该变量为 `"1"` 时直接返回 `None`，强制使用 `LocalEngine`，适用于无 MATLAB 环境调试或算法对照验证。

### Q18. MATLAB Server 监听哪个端口？

默认 **5570**，由 `CSAM_MATLAB_BIND=tcp://*:5570` 控制（见 `config.m:26`）。注意：此端口与 ZMQ 桥接端口 5555 是两个独立通道——5570 是 MATLAB Server 的 TCP/JSON 通道，5555 是旧版 ZMQ 引擎通道（见 Q19）。

### Q19. ZMQ 通信地址如何配置？

通过环境变量 `CSAM_ZMQ_ADDRESS`：

| 平台 | 默认值 | 说明 |
|------|--------|------|
| Windows | `tcp://127.0.0.1:5555` | TCP 回环 |
| macOS / Linux | `ipc:///tmp/csam_engine` | Unix 域套接字 |

```powershell
set CSAM_ZMQ_ADDRESS=tcp://127.0.0.1:5556   # Windows
export CSAM_ZMQ_ADDRESS=tcp://127.0.0.1:5556 # POSIX
```

> 注意：生产路径（`MatlabEngine`）走 5570 端口的 TCP/JSON 通道，不走 ZMQ。ZMQ 通道（5555）用于旧版 `MatlabZmqEngine`。两者不要混淆。

### Q20. 启动时许可证校验失败怎么办？

许可证校验依赖 `CSAM_HMAC_SECRET`：

- **生产环境**：必须在 `.env` 或系统环境变量中设置真实密钥。
- **开发环境**：可不设置，`license_manager` 使用内置开发回退密钥并记录 WARNING 日志，不阻止启动。
- **生成开发许可证**：`python -m repair_app.utils.license_manager issue "Developer" 365`。
- **完整校验**：将 `public_key.pem` 与 `license.key` 放入 `config/` 目录后重启。

## 三、操作与功能

### Q21. 软件启动后没有数据怎么办？

GUI 启动后会通过 `QTimer.singleShot(300, self._load_demo)` **自动加载 8000 点内置演示数据**（`generate_defect_sample(defect_types=["pit"], seed=..., n_points=8000)`，见 `main_window.py:1380`）。状态栏会提示 "演示数据已加载 (8,000 点)"。若未自动加载，检查 `morphology_prediction/` 目录是否存在。

### Q22. 如何加载自己的点云文件？

通过菜单或工具栏的"加载文件"按钮，支持 `.xyz`、`.ply`、`.stl` 等格式。若未选择文件，GUI 弹窗询问 "是否加载内置演示数据？"。STL 文件经由 `path_planning.read_stl_file` 算法解析为 N×12 三角面片矩阵。点云应包含 XYZ 坐标，法向量可由 `normal_estimator` 自动估算。

### Q23. 如何框选缺陷区域？

1. 在左侧工具栏切换到 **选取模式**（`defect_selector` 支持框选/笔刷/擦除三种模式）。
2. 在三维视图中拖拽框选或笔刷涂抹缺陷区域。
3. 选区掩码（mask）实时高亮，可撤销（`_btn_undo`）。
4. 至少选中 3 个点后"生成路径"按钮才会启用（`main_window.py:1295`）。

### Q24. 增材模式和修复模式有什么区别？

- **增材模式（Additive）**：在基底上堆积新材料，路径规划基于 `additive_triangles_cluster`，采用满层切片策略。
- **修复模式（Repairing）**：在缺陷区域补材，路径规划基于 `repairing_triangles_cluster`，需考虑边界缓冲（`buffer_repairing`）。

`layer_slice` 同时处理两类簇并输出 `additive_layerlist` 与 `repairing_layerlist`；`generate_path` 据此生成差异化扫描路径。两者可混合执行。

### Q25. 临界速度为什么是灰色的？

**临界速度由材料数据库自动计算，不可手动编辑。** `main_window.py:753` 对 `critical_velocity` 字段执行 `setEnabled(False)`，工具提示为 "临界速度由材料数据库自动计算，不可手动修改"。当用户选择材料时（`main_window.py:1304`），程序调用 `setValue(mat.v_cr_base_ms)` 自动填入。如需调整，请修改 `material_db.json` 中对应材料的 `v_cr_base_ms` 字段。

### Q26. 本地引擎和远程 MATLAB 引擎有什么区别？

| 维度 | LocalEngine（Python） | MatlabEngine（远程） |
|------|----------------------|---------------------|
| 实现 | `repair_app/engine/local_engine.py` | `repair_app/engine/matlab_engine.py` |
| 算法 | Python 原型实现 | MATLAB 19 个注册算法 |
| 精度 | 原型级，用于演示 | 工业级，生产路径 |
| 通信 | 进程内调用 | TCP/JSON（端口 5570） |
| 依赖 | 仅 Python | MATLAB R2025b + 工具箱 |
| 调用方式 | 同步 | Worker 线程 + 异步回调 |

`EngineFactory` 自动选择：MATLAB 可达用 MatlabEngine，否则降级 LocalEngine。

### Q27. 生成路径时界面卡住怎么办？

**不应卡住。** 路径生成设计为非阻塞：

- **本地引擎**：算法在 `QThread` Worker（`ui/workers.py`）中执行，UI 线程不阻塞。
- **远程引擎**：通过异步回调（`_on_result_ready` / `_on_error_occurred`）返回结果。

若界面确实冻结，可能原因：

1. 点云过大（100K+）——属正常耗时，请耐心等待（见 Q43）。
2. Worker 线程异常未触发回调——查看 `logs/app.log`。
3. 重复点击触发并发拒绝（见 Q41）。

### Q28. 可行性检查评分低怎么办？

可行性评分（`feasibility_checker`）综合临界速度、粒子速度、喷涂距离、材料匹配等因素。提升方法：

1. 提高粒子速度（需高于材料临界速度，见 Q35）。
2. 调整喷涂距离至典型值 30mm（见 Q36）。
3. 选择匹配的材料组合。
4. 检查气体温度与压力是否在工艺窗口内（见 Q37）。

### Q29. P1 动画无法播放怎么办？

P1 动画（`P1CompositePlayer`）播放 MATLAB 生成的中间帧（三视图：喷嘴/射线、TCP 路径、沉积形貌色温图）：

1. **按钮灰色**：`_btn_p1_demo` 在 `frame_count > 0` 时才启用（`main_window.py:718`）。需先完成形貌预测生成 `.mat` 帧数据。
2. **无帧数据**：先执行形貌预测步骤。
3. **播放无图像**：检查 `morphology_prediction/` 目录下的中间文件。

### Q30. 如何导出 G-code？

完成路径生成后（`_mock_waypoints` 非空），"导出 G-code" 按钮启用（`main_window.py:1161`）。点击后由 `export/gcode_exporter.py` 生成 G-code 文件。导出前会经 `export_validator` 校验路径完整性。

### Q31. 如何导出 PDF 报告？

完成形貌预测后（`_repair_xyz` 非空），"导出 PDF" 按钮启用（`main_window.py:1162`）。由 `export/report_generator.py` 生成包含缺陷选区、路径、形貌预测结果的 PDF 报告。

### Q32. 演示数据可以删除吗？

可以。演示数据由 `generate_defect_sample` 在内存中动态生成，不依赖磁盘文件。但 `morphology_prediction/pointlist.npz` 与 `velocitylist.json` 是算法中间产物，删除后下次运行会重新生成。`morphology_prediction/` 目录本身用于保存中间帧与预测结果，建议保留。

## 四、参数与算法

### Q33. 层高参数设多少合适？

典型值 **2.0 mm**（`layer_slice` 默认 `layer_height=2.0`，见 `register_algorithms.m:216`）。范围 0.1–10 mm。层高越小，切片越密，路径精度越高但耗时越长；层高越大，堆积越快但形貌精度下降。修复模式建议 1.0–2.0 mm，增材模式可适当增大。

### Q34. 扫描角度为什么默认 -45 度？

`generate_path` 默认 `scanning_angle=-45.0`（`register_algorithms.m:249`）。-45° 是冷喷涂工艺的常用扫描方向，可使相邻层扫描线呈 90° 交叉，改善沉积均匀性与表面粗糙度。可根据工件几何调整，常见值为 ±45°、0°、90°。

### Q35. 粒子速度和临界速度的关系？

**粒子速度必须高于材料临界速度（`v_cr`）才能沉积**，否则粒子反弹或冲蚀。临界速度由材料数据库自动填入（见 Q25），典型值 400 m/s（`main_window.py:737` 默认）。`feasibility_checker` 会检查 `v_particle > v_cr` 并据此评分（见 Q28）。`morphology.particle_fitting` 通过 CFD 数据拟合粒子速度分布。

### Q36. 喷涂距离设多少？

典型值 **30 mm**（Stand-off Distance, SoD）。`particle_fitting` 默认 `SoD=30.0`（`register_algorithms.m:451`）。距离过近会导致粒子未充分加速，过远会导致束流发散。典型工艺窗口 20–40 mm。

### Q37. 气体温度和压力如何影响修复质量？

- **温度**：升高气体温度可提高粒子出口速度与塑性变形能力，但过高会恶化喷嘴热负荷。
- **压力**：提高压力增加粒子速度，使其更易超过临界速度（见 Q35），但过高增加设备损耗。

两者通过 CFD 拟合进入 `particle_fitting` 的射线属性（速度、长度、临界速度），间接影响形貌预测与可行性评分。

### Q38. 规划层数和预测层数有什么区别？

- **规划层数**：`layer_slice` 根据 `layer_height` 对几何模型切片得到的层数，是**输入参数**。
- **预测层数**：`profile_predict` 根据工艺参数预测的实际有效沉积层数，是**输出结果**。

预测层数可能少于规划层数（部分层因速度不足未沉积），可行性检查会据此评估。

### Q39. 避障精度参数的作用？

`generate_path` 的 `resolution`（默认 1.0）控制 A* 避障搜索的栅格分辨率（`register_algorithms.m:258`）。`a_star_search` 在基底占用栅格上搜索连接路径，分辨率越高（值越小）路径越精细但计算量越大。`linkPath_freeDistance` 控制无碰撞自由距离阈值。

### Q40. 材料选择如何影响参数？

选择材料后，程序从 `material_db.json` 读取该材料的 `v_cr_base_ms`（临界速度）与密度等属性，**自动填充**临界速度字段（`main_window.py:1304`，见 Q25）。材料属性同时影响 `feasibility_checker` 的评分与 `particle_fitting` 的拟合参数。不同材料对应不同的工艺窗口，选错材料会导致可行性评分偏低。

## 五、错误与故障

### Q41. "前一个请求仍在进行中"错误怎么办？

**原因**：`BridgeClient` 采用单请求串行模式，前一个请求未完成时拒绝新请求（`zmq_client.py:188` / `bridge/communication/zmq_client.py:206`）。

**解决**：

1. 等待当前请求完成（状态栏会更新）。
2. 或调用 `close()` 取消当前请求。
3. 避免在路径生成/形貌预测进行中重复点击按钮（GUI 会弹窗 "路径规划仍在进行中，请等待完成"，`main_window.py:1613`）。

### Q42. 请求超时（30 秒）怎么办？

默认超时 30 秒（`CSAM_BRIDGE_TIMEOUT_MS=30000`）。超时通常因算法耗时或网络延迟：

1. **调大超时**：`set CSAM_BRIDGE_TIMEOUT_MS=120000`（2 分钟）。
2. **算法本身耗时**：`generate_path` 超时设为 120s，`profile_predict` 设为 120s（见 `register_algorithms.m` 各 `add()` 的 timeout 参数）。
3. **网络问题**：检查 MATLAB Server 负载与网络连通性。

### Q43. MATLAB Server 崩溃后如何恢复？

1. **重启 Server**：在 MATLAB 中重新执行 `cd matlab_server; startup`。
2. **GUI 行为**：路径 A（生产路径）**不会自动重连**（见 Q44），需在 GUI 中重新触发请求，`EngineFactory` 会重新探测并连接。
3. **降级运行**：若不便重启 Server，可设 `CSAM_ENGINE_DISABLE_MATLAB=1` 临时降级到 LocalEngine。
4. **查看日志**：`logs/matlab_server_<date>.log` 查看崩溃原因（见 Q45）。

### Q44. 通信中断后 GUI 会自动重连吗？

**路径 A（MatlabEngine，TCP/JSON）不会自动重连。** 通信中断后需重启请求或重启 GUI。`EngineFactory` 在创建时探测一次，运行中断线不会自动重连。若需恢复，重新触发操作即可（`MatlabEngine` 会尝试重新连接）。心跳监控（`lifecycle.py`）会检测断线并将状态置为 `RECONNECTING`，但实际重连需手动触发。

### Q45. 日志文件在哪里？

| 日志 | 路径 | 格式 |
|------|------|------|
| Python 应用日志 | `logs/app_{YYYY-MM-DD}.log` | 文本 |
| Python 错误日志 | `logs/error_{YYYY-MM-DD}.log` | 文本（仅 ERROR+） |
| Python 结构化日志 | `logs/structured_{YYYY-MM-DD}.jsonl` | JSONL |
| Python 兼容日志 | `logs/app.log` | 文本（UTF-8） |
| MATLAB Server 日志 | `logs/matlab_server_{YYYYMMDD}.log` | JSONL（UTF-8） |
| 崩溃日志 | `repair_app/utils/logs/crash_{timestamp}.log` | 文本 |

日志目录由 `CSAM_MATLAB_LOG_DIR`（MATLAB）与 `LOG_DIR`（Python）控制，默认 `./logs`。

### Q46. 如何开启 DEBUG 日志？

**Python**：
```powershell
set CSAM_LOG_LEVEL=DEBUG
```

**MATLAB**：
```powershell
set CSAM_MATLAB_LOG_LEVEL=debug
```

MATLAB 日志级别为小写（`debug/info/warn/error`），Python 为大写（`DEBUG/INFO/WARNING/ERROR`）。DEBUG 级别会记录完整请求/响应、心跳、健康检查等细节，适用于深度排查，但日志量较大。

### Q47. 打包后的 exe 闪退怎么办？

1. **从命令行运行**：`CSAM_Repair.exe` 在 cmd 中运行以查看错误输出。
2. **首次启动慢**：PyInstaller 单文件 exe 首次需 10–30 秒解压临时文件，**属正常现象**，非闪退。
3. **查看崩溃日志**：`repair_app/utils/logs/crash_*.log`（`install_crash_handler` 记录）。
4. **路径含中文/空格**：将 exe 移至纯 ASCII 路径。
5. **VC++ 运行库缺失**：安装 Visual C++ 2015-2022 Redistributable。

### Q48. 中文路径导致错误怎么办？

软件本身支持中文路径，但部分场景（PyInstaller 打包、MATLAB R2025b 源文件）对中文敏感：

1. **MATLAB 源文件**：`startup.m` 采用编码无关探测定位中文算法目录（`路径规划/`、`形貌预测/`），避免硬编码中文。
2. **打包 exe**：将 exe 放入纯 ASCII 路径。
3. **加载文件**：尽量使用英文文件名，或确保系统区域设置支持 UTF-8。
4. **MATLAB Server 工作目录**：建议放在纯 ASCII 路径下。

### Q49. MATLAB Server 内存占用过高怎么办？

`resource_cleanup.m` 已实现自动清理：

- **触发频率**：每 `CSAM_MATLAB_CLEANUP_INTERVAL=50` 请求清理一次。
- **内存阈值**：`CSAM_MATLAB_MEM_THRESHOLD_MB=4096`，超过则触发 `drawnow('reduce')` 释放图形句柄。
- **JVM GC**：每次清理调用 `java.lang.System.gc()`。
- **手动 pack**：`pack` 只能在命令提示符执行，函数内无效（M2 修正），需操作员手动运行。

若仍过高：重启 Server，或调低 `cleanup_interval`（如 20）。

### Q50. 算法执行报 ERR_DEPS 怎么办？

**原因**：缺少所需 MATLAB 工具箱许可证。`ERR_DEPS`（`ResponseStatus.ERR_DEPS=4`）表示算法声明的依赖（`Map_Toolbox` / `Curve_Fitting_Toolbox`）不可用。

**诊断**：在 MATLAB 中执行：
```matlab
license('test', 'Map_Toolbox')           % 返回 1=可用, 0=不可用
license('test', 'Curve_Fitting_Toolbox')
```

**解决**：

1. 安装对应工具箱并激活许可证。
2. 若无法安装，避开依赖该工具箱的算法（见 Q5），改用其他算法或本地引擎。
3. 健康检查（`health.m`）的 `toolbox_available` 字段会列出所有工具箱可用性。

## 六、开发与扩展

### Q51. 如何新增 MATLAB 算法？

在 `matlab_server/register_algorithms.m` 中用 `add()` 注册，**无需修改 dispatcher**：

```matlab
add(reg, 'my_category.my_algorithm', '1.0.0', @wrap_my_algorithm, ...
    'my_category', '描述算法功能', ...
    {'Map_Toolbox'}, 60000);   % 依赖、超时(ms)
```

然后实现 `wrap_my_algorithm(params, inputs)` 包装器，使用 `get_param`/`get_input`/`get_json` 提取参数，用 `ok(results, artifacts)` 返回结果。`server.m` 的 dispatcher 会自动路由到新注册的算法。详见 [07 开发者文档](07_开发者文档.md)。

### Q52. 如何运行测试？

```powershell
pytest                              # 运行全部测试
pytest repair_app/tests/ -v         # 详细模式
pytest --cov=repair_app --cov-report=term-missing   # 带覆盖率
pytest repair_app/tests/test_stress.py              # 压力测试
```

测试位于 `repair_app/tests/`（stage1–stage5、stress、fixes 等）与 `repair_app/bridge/tests/`。压力测试 `test_stress.py` 包含 100K 点云与多层规划场景。

### Q53. 如何打包发布？

**Windows**：
```cmd
build_windows.bat
```

或手动 PyInstaller：
```powershell
pyinstaller repair_app.spec
```

`repair_app.spec` 已配置 hiddenimports、排除 UPX 压缩 Qt DLL、包含数据文件。打包产物在 `dist/` 目录。详见 `docs/PACKAGING_GUIDE.md` 与 [08 运维手册](08_运维手册.md)。

### Q54. 测试覆盖率是多少？

当前覆盖率约 **73%**，CI 门控阈值为 **60%**（`.github/workflows/ci.yml:48` 的 `--cov-fail-under=60`）。覆盖率低于 60% 时 CI 流水线失败。运行 `pytest --cov=repair_app --cov-report=html` 可生成 HTML 详细报告。

### Q55. 如何贡献代码？

参见项目根目录 `CONTRIBUTING.md`。要点：

1. Fork 仓库并创建特性分支。
2. 遵循现有代码风格（`pyproject.toml` 配置 black/isort/flake8）。
3. 新功能需附带测试，覆盖率不得下降。
4. 提交前运行 `pytest` 与 `flake8`。
5. 提交 PR 时使用 `.github/pull_request_template.md` 模板。
6. 预提交钩子见 `.pre-commit-config.yaml`。
