## 目录结构

软件把所有用户数据放在一个统一的根目录下。

开发环境：`项目根/user_data/`
打包环境：`%APPDATA%/CSAM_Repair/`（Windows 标准）

```
CSAM_Repair/                 （或 user_data/）
├── projects/                项目文件（.csam）
├── exports/                 导出文件
│   ├── gcode/               G-code 文件
│   ├── pdf/                 PDF 报告
│   └── stl/                 STL 文件
├── logs/                    日志文件
│   ├── app_YYYY-MM-DD.log   全部日志
│   ├── error_YYYY-MM-DD.log 错误日志
│   ├── crash_YYYYMMDD_HHMMSS.log       崩溃日志
│   └── exception_YYYYMMDD_HHMMSS.log   异常报告
├── recovery/                自动保存
│   └── auto.autosave        自动保存快照
├── cache/                   临时缓存
└── recent_projects.json     最近项目列表
```

想自定义目录？设环境变量 `CSAM_USER_DATA` 指向你的目录就行。

## 自动保存

软件每 60 秒自动保存一次当前状态。

### 保存什么

- 点云文件路径
- 当前模式（修复 / 增材）
- 材料选择
- 工艺参数
- 选区摘要（点数、体积、面积）

### 保存到哪

`recovery/auto.autosave`

### 什么时候保存

- 每 60 秒自动保存一次
- 关闭软件时再保存一次
- 手动点 "保存项目" 不会影响自动保存

### 注意

自动保存只存状态，不存点云数据本身。点云还是原来的文件，软件只记住路径。如果点云文件被删了或移动了，恢复时会提示找不到。

---

## 自动恢复（Crash 恢复）

软件崩溃或异常关闭后，下次启动会自动检测。

### 恢复流程

1. 启动软件
2. 500 毫秒后检查 `recovery/auto.autosave` 是否存在
3. 存在就弹对话框：

```
检测到上次会话未正常关闭（自动保存于 2026-07-14 10:30:00）。

是否恢复以下状态？
  点云: D:/data/defect.xyz
  模式: 修复

选择「Yes」恢复，「No」放弃恢复并删除快照。
```

4. 点 Yes：恢复点云、模式、材料、参数
5. 点 No：删除快照，从空白开始

### 什么时候不会恢复

- 正常退出（关软件前会保存，但下次启动不弹恢复框，因为快照被清了）
- 第一次启动（没有快照）
- 快照文件损坏

## 统一导出目录

### 之前的问题

自动生成的 PDF 报告硬编码写到桌面。桌面没有就写到项目根。

### 现在的行为

所有导出文件统一放在 `exports/` 下：

| 类型 | 子目录 | 例子 |
|------|--------|------|
| G-code | `exports/gcode/` | `repair.nc` |
| PDF 报告 | `exports/pdf/` | `defect_part_001_report_20260714_103000.pdf` |
| STL | `exports/stl/` | `repair.stl` |

### 自动报告命名

一键计算后自动生成的 PDF 报告：

```
exports/pdf/{项目名}_report_{时间戳}.pdf
```

项目名取自点云文件名。时间戳格式 `YYYYMMDD_HHMMSS`。

### 手动导出

点 "导出 G-code" 或 "导出 PDF" 时，文件对话框默认路径就是统一导出目录，你可以改到别处。

### 快速打开导出目录

菜单 → 文件 → 打开导出目录，直接在资源管理器里看所有导出文件。

## 统一日志目录

### 之前的问题

日志写在 `get_data_dir()/logs/`，开发环境是项目根，打包环境是 exe 同级。

### 现在的行为

日志统一写到 `logs/`（用户数据目录下）：

| 文件 | 内容 | 保留 |
|------|------|------|
| `app_YYYY-MM-DD.log` | 全部日志（INFO 及以上） | 30 天 |
| `error_YYYY-MM-DD.log` | 错误日志（ERROR 及以上） | 60 天 |
| `crash_YYYYMMDD_HHMMSS.log` | 崩溃日志（原始 traceback） | 永久 |
| `exception_YYYYMMDD_HHMMSS.log` | 异常报告（结构化） | 永久 |

### 快速打开日志目录

菜单 → 文件 → 打开日志目录。

## Crash 恢复 + 异常报告

### 软件崩溃时发生什么

1. 全局异常钩子捕获未处理异常
2. 写崩溃日志 `crash_YYYYMMDD_HHMMSS.log`（原始 traceback）
3. 生成结构化异常报告 `exception_YYYYMMDD_HHMMSS.log`
4. 弹 GUI 对话框提示用户
5. 调用原 `sys.__excepthook__` 完成默认处理

### 异常报告包含什么


从左到右：

| `⚫ 本地模式` | 连接状态 | MATLAB 状态变化时更新 |

### License 状态颜色

| 状态 | 颜色 | 文字 |
|------|------|------|
| 永久授权 | 绿色 | ✅ 永久授权 |

| 有效 ≤ 7 天 | 橙色 | ⚠️ License N 天后到期 |

## 常见问题

### 软件崩溃了，我的工作没了吗

不会。软件每 60 秒自动保存一次。下次启动会弹恢复对话框，点 Yes 就回来了。

### 恢复对话框没弹

可能原因：

1. 上次是正常退出（快照被清了）
2. 自动保存文件损坏（已被自动删除）
3. 快照时间太久（点云文件可能已变化）

### 导出的文件在哪

菜单 → 文件 → 打开导出目录。或看 About 对话框 → "数据目录" 标签页。

### 日志在哪

菜单 → 文件 → 打开日志目录。

### License 还有几天到期

看状态栏右侧，或 About 对话框 → "License" 标签页。

### 软件版本是多少

看状态栏右侧 `v1.0.0`，或 About 对话框。

### 最近项目不见了

- 最近项目列表存在 `recent_projects.json`
- 文件被删或损坏时列表会清空
- 手动 "清空最近项目" 也会清空
- 打开新项目会自动重新积累

### 想改用户数据目录位置

设环境变量 `CSAM_USER_DATA` 指向你的目录，重启软件。

```
set CSAM_USER_DATA=D:\my_csam_data
```

### 打包后目录在哪

Windows 打包后默认在 `%APPDATA%\CSAM_Repair\`。这是 Windows 标准的用户数据目录。

## 技术细节（给开发人员看）

### PathManager 单例

```python
from repair_app.software.path_manager import PathManager
pm = PathManager.get_instance()
# 所有目录首次访问时自动创建
pm.projects_dir    # Path
pm.exports_dir     # Path
pm.logs_dir        # Path
pm.recovery_dir    # Path
pm.cache_dir       # Path
pm.gcode_dir       # Path
pm.pdf_dir         # Path
pm.stl_dir         # Path
```

### 目录解析优先级

1. 环境变量 `CSAM_USER_DATA`（最高优先级）
2. 打包环境：`%APPDATA%/CSAM_Repair`
3. 打包但无 APPDATA：exe 同级 `user_data/`
4. 开发环境：项目根 `user_data/`

### ProjectManager 接口

```python
pm = ProjectManager(path_manager)
pm.new_project("my_project")           # 新建
pm.save_project(state)                 # 保存
pm.load_project(Path("x.csam"))        # 加载，返回 state
pm.collect_state(                      # 收集状态
    point_cloud_path="/path/to.xyz",
    repair_mode=1,
    material_index=1,
    params={...},
    selection_summary={...},
)
```

### AutoRecovery 接口

```python
ar = AutoRecovery(path_manager)
ar.save(state)                         # 立即保存
ar.maybe_save(state, force=False)      # 按时间间隔保存
ar.load()                              # 加载，返回 state 或 None
ar.clear()                             # 删除快照
ar.has_pending_recovery                # 是否有可恢复数据
```

### ExceptionReporter 接口

```python
er = ExceptionReporter(path_manager)
er.report_exception(exc_type, exc_value, exc_tb, context="...")
er.report_text("错误描述", context="...")
# 或安装全局钩子：
install_exception_reporter(show_dialog=True)
```

### 异常钩子链

```
sys.excepthook（默认）
  ↑ 包装
crash_handler 的 _handler（写 crash_*.log）
  ↑ 包装
exception_reporter 的 wrapped_hook（生成结构化报告 + GUI 弹窗）
```

外层钩子先执行，然后调用内层。两层日志互补：crash_*.log 是原始 traceback，exception_*.log 带软件/License/MATLAB 上下文。

### 状态栏部件顺序

`addPermanentWidget` 从左到右添加：

```
[瞬时消息]  [版本]  [License]  [项目]  [连接]
```

瞬时消息由 `showMessage()` 控制，显示几秒后消失，永久部件始终可见。

### 自动保存定时器

- 间隔：60 秒
- 类型：QTimer（单次定时器，timeout 触发 `_do_autosave`）
- 启动：`MainWindow.__init__` 末尾
- 停止：`closeEvent` 开头
- 退出前强制保存一次
