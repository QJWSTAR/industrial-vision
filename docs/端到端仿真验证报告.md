## 2. 关键架构发现

### 2.1 双路径架构现实

**核心发现：用户描述的"GUI → CoordinationService → MatlabService → Bridge → ZeroMQ → MATLAB"单一链路在代码中并不存在为一个连续整体。** 项目实际存在两条并行且互不连接的通信路径：

| 维度 | 路径 A：ZMQ v2.1（Protobuf） | 路径 B：TCP v3.0（JSON） |
|------|------------------------------|--------------------------|
| **GUI 实际使用** | **是**（MainWindow 唯一远程路径） | **否**（仅测试代码使用） |
| 入口 | `CoordinationService.create_zmq_client()` | `EngineFactory.create_engine()` |
| 中间层 | `LegacyZmqClient` → `BridgeClient` | `MatlabEngine` → `TcpChannel` |
| 传输 | ZMQ REQ/REP，端口 5555 | TCP socket，端口 5570 |
| 协议 | `repair_protocol.proto` v2.1（Protobuf 二进制） | `algorithm_protocol_v3.proto` v3.0（JSON 编码） |
| MATLAB 端 | `matlab_bridge_server.m`（根目录） | `matlab_server/server.m`（java.net.ServerSocket） |
| 重连机制 | 无 | TcpChannel 内置重试 + LifecycleSupervisor（未启用） |
| 心跳后果 | 仅标记 `is_connected=False` | LifecycleSupervisor 可触发重连（未启用） |

**影响**：
- `MatlabService`（bridge/services/matlab_service.py）是路径 A 上的门面，但 **GUI 从未实例化它**（[F-01](#f-01)）
- `MatlabEngine`/`EngineFactory`/`LifecycleSupervisor` 属于路径 B，**GUI 也从未使用**（[F-02](#f-02)）
- `test_migration.py` 声称验证"MainWindow → CoordinationService → MatlabService → Bridge → Engine"链路，但实际 MatlabService 未接入 MainWindow（[F-03](#f-03)）

### 4.3 CRITICAL：异常类型丢失缺陷

<a name="f-01"></a>
**[F-01] CRITICAL — 异常类型翻译完全失效**

**位置**：`zmq_client.py:276-280`

```python
def _on_error_occurred(self, msg: str, request_id: str) -> None:
    self._connected = False
    if self._on_error:
        err = translate_zmq_error(Exception(msg), request_id=request_id)  # L279
        self._on_error(err)
```

**根因链路**：
1. `_RequestWorker.run()` 捕获异常时（L95-96）：`self.error_occurred.emit(str(exc), "")` —— 丢失原始异常对象，只保留字符串
2. 信号传递 `str` 到 `_on_error_occurred`
3. L279 将字符串包成 `Exception(msg)` 传给 `translate_zmq_error`
4. `translate_zmq_error` 依赖 `isinstance(exc, zmq.Again)` 和 `isinstance(exc, zmq.ZMQError)` 分类
5. 对普通 `Exception(str)`，两个 isinstance **永远为 False**
6. 所有错误落入 L91 `return BridgeError(f"未预期的通信错误: {exc}")`

**影响**：
- `ConnectionTimeoutError`（含 `timeout_ms` 字段）**永不产出**
- `EngineUnavailableError`、`EngineCrashError` **永不产出**
- GUI 无法区分超时、连接失败、引擎崩溃——所有通信错误都显示为"未预期的通信错误"
- 结构化异常翻译系统形同虚设

**修复方案**：在 `_RequestWorker.run()` 中保留原始异常对象，通过信号传递异常类型信息（如异常类名），或在 `_on_error_occurred` 中根据消息内容分类。

**R2025b 影响**：MATLAB 端超时或连接中断时，GUI 无法给出有意义的错误提示，操作员无法判断是网络问题还是 MATLAB 崩溃。

### 5.2 CRITICAL：路径 A 无自动重连

<a name="f-05"></a>
**[F-05] CRITICAL — 心跳丢失后不触发重连**

**位置**：`zmq_client.py:248`、`heartbeat.py:96`

```python
# zmq_client.py:248 — start_heartbeat 只连接了 status_changed
self._heartbeat.status_changed.connect(self._on_heartbeat_status)
# 未连接 engine_lost 信号！

# heartbeat.py:96 — engine_lost 信号发出后无人接收
self.engine_lost.emit()
```

**影响**：
- 心跳连续丢失达阈值后，`HeartbeatMonitor` 发出 `engine_lost` 信号
- `BridgeClient` **未连接** `engine_lost` 信号的 handler
- 仅通过 `status_changed(DOWN)` 设置 `self._connected = False`
- **不会尝试重连**——引擎恢复后也不会自动恢复连接
- 路径 A 的"每请求一连接"模式意味着下一个请求会新建 socket，但如果 MATLAB Server 仍宕机，请求直接失败

**对比路径 B**：`LifecycleSupervisor`（lifecycle.py）有完整重连机制（指数退避、熔断器），但 GUI 未使用。

**修复方案**：在 `BridgeClient.start_heartbeat` 中连接 `engine_lost` 信号到重连处理函数，或在 `is_connected=False` 时提供显式重连 API。

## 8. 发现清单

### CRITICAL

<a name="f-01"></a>
#### [F-01] CRITICAL — 异常类型翻译完全失效
- **位置**：`bridge/communication/zmq_client.py:276-280`
- **影响**：`ConnectionTimeoutError`、`EngineUnavailableError` 等子类永不产出，GUI 无法区分错误类型
- **详见**：[第 4.3 节](#43-critical异常类型丢失缺陷)

<a name="f-05"></a>
#### [F-05] CRITICAL — 心跳丢失后不触发重连
- **位置**：`bridge/communication/zmq_client.py:248`、`bridge/communication/heartbeat.py:96`
- **影响**：引擎恢复后不会自动恢复连接，需手动重启请求
- **详见**：[第 5.2 节](#52-critical路径-a-无自动重连)

### HIGH

<a name="f-02"></a>
#### [F-02] HIGH — MatlabService 门面未接入 GUI
- **位置**：`bridge/services/matlab_service.py`（第 87 行类定义）
- **现状**：GUI 直接使用 `LegacyZmqClient` 适配器，跳过 `MatlabService` 门面
- **影响**：bridge 层"业务层通过 MatlabService 与 MATLAB 交互"的设计意图未实现；MatlabService 的结构化异常、心跳、延迟日志等功能未被使用
- **建议**：V1.1 将 GUI 升级为使用 MatlabService 门面

<a name="f-03"></a>
#### [F-03] HIGH — test_migration.py 验证声明与实际不符
- **位置**：`repair_app/tests/test_migration.py` 第 3 行 docstring
- **现状**：声称验证"MainWindow → CoordinationService → MatlabService → Bridge → Engine"链路，但 MatlabService 未接入 MainWindow
- **影响**：迁移测试通过但实际链路不完整，给出虚假信心
- **建议**：更新 docstring 描述实际验证内容，或真正接入 MatlabService

<a name="f-04"></a>
#### [F-04] HIGH — 版本协商始终返回 compatible=true
- **位置**：`matlab_server/dispatcher.m:58-65`
- **现状**：`VERSION_NEGOTIATE` 处理始终返回 `protocol_compatible=true`，不做实际版本检查
- **影响**：客户端协议版本与服务端不兼容时无法被检测，可能导致运行时解码失败
- **建议**：实现实际版本兼容性检查逻辑

<a name="f-08"></a>
#### [F-08] HIGH — generate_path.m 全局警告开关无 try/finally 保护
- **位置**：`形貌预测/generate_path.m:36, 63`
- **现状**：L36 `warning('off',...)` 关闭，L63 `warning('on',...)` 恢复，中间无 try/finally
- **影响**：若 L36-63 之间抛出异常，警告状态无法恢复，全局影响后续 MATLAB 会话所有 polyshape 警告
- **建议**：用 `onCleanup` 对象或 `try/finally` 包裹确保恢复
