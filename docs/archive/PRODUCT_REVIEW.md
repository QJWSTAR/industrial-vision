# 产品体验审查报告（Product Review）

> **审查日期**：2026-07-15
> **审查版本**：CSAM Repair v1.0.0 RC
> **审查方法**：5 个角色视角，从零开始体验，不假设项目背景
> **审查范围**：GUI 布局 / 交互流程 / 文档 / 专业功能 / 错误反馈 / 自动化程度
> **说明**：本报告仅做体验审查，不修改代码

---

## 一、角色 1：第一次使用的普通用户

### 1.1 角色画像

非技术背景，第一次接触冷喷涂软件，刚拿到安装包，需要完成一次完整的"加载 → 选区 → 计算 → 导出"流程。

### 1.2 体验过程

#### 第一印象：困惑

打开软件后，我看到一个深色界面，标题写着"冷喷涂缺陷修复工作流"。界面分成左中右三栏：

- **左侧**：4 个步骤按钮（01 数据与路径 / 02 形貌预测 / 03 结果校核 / 04 输出交付）、一个"材料选择"下拉框、22 个参数输入框
- **中间**：一个空的 3D 视图区，上方有几个图标按钮
- **右侧**：点云信息、可行性报告、进度条、结果摘要（全部为空）

**我不知道第一步该做什么。** 没有"欢迎使用"引导，没有"点这里开始"的提示，没有步骤编号的视觉引导。虽然左侧有"01 数据与路径"按钮，但它只是面板切换，不是操作引导。

#### 加载数据：勉强通过

300ms 后软件自动加载了演示数据（8000 个点），3D 视图出现了一个彩色点云。但**没有任何提示告诉我"演示数据已加载"**，我以为这是软件的默认背景。

我看到左侧有"📂 加载点云"按钮，点击后弹出文件对话框，过滤条件是"点云文件 (*.csv *.txt *.xyz *.asc)"。**我不知道这些格式是什么**，也不知道我的数据应该是什么格式（每行 X,Y,Z？还是带法向量？坐标系约定是什么？）。

#### 选取缺陷区域：卡住

这是**最痛苦的环节**。我看着 3D 点云，知道要"选取缺陷区域"，但：

1. 我在 3D 视图上点击、拖拽 — **没有任何反应**
2. 我不知道必须先点击上方工具栏的"🧭 导航模式"按钮切换到"✂️ 选取模式"
3. 切换后，我发现有 4 种选取方式（矩形/自由/区域/取消），**不知道该用哪种**
4. 我用矩形框选了一块区域，但**选区是在 XY 平面投影**，曲面背面也被选中了
5. 选完后没有明显反馈，直到我看右侧"点云信息"发现"已选"数字变了

**"导航/选取模式切换"是一个典型的模式陷阱。** 用户在导航模式下点击会以为软件没反应。

#### 设置参数：完全不懂

左侧 22 个参数输入框全部展示在我面前：

- 路径规划参数（10 个）：层高、扫描角度、扫描步长、边缘步长、倾斜角度、增材缓冲、修复缓冲、路径过渡距离、避障精度、规划层数
- 冷喷涂工艺参数（10 个）：粒子速度、临界速度（灰色禁用）、喷嘴直径、喷涂角度、喷涂距离、粉末粒径、气体温度、气体压力、送粉速度、移动速度
- 沉积参数（2 个）：深度补偿、预测层数

**这些参数我一个都不懂。** "增材缓冲"是什么？"避障精度"是什么？"v_cr"是什么缩写？没有任何 tooltip 解释（使用手册声称有 tooltip，但代码里实际没设置）。

我不敢改任何参数，全部用默认值。

#### 开始计算：等待

我点击绿色的"🚀 开始计算"按钮。状态栏显示"正在启动 MATLAB + Bridge..."。

然后**界面卡住了大约 2 分钟**（MATLAB 启动时间）。没有进度条，没有预估剩余时间，**没有取消按钮**。我不知道软件是卡死了还是在工作。

2 分钟后，状态栏显示"正在执行路径规划 + 形貌预测..."，进度条开始动。

#### 查看结果：信息分散

计算完成后，结果散落在**三个地方**：

1. 中间 3D 视图显示了彩色路径和喷嘴
2. 中间第二个 Tab（"MATLAB 形貌分析"）有 6 个指标卡片和 4 个子 Tab
3. 右侧"结果摘要"面板有 6 个键值对

**我不知道该看哪里。** 而且"逐层动画"控制出现了两次（3D 视图工具栏一次，底部播放器一次），功能重复让我困惑。

#### 导出：勉强完成

我点击"📤 导出 G-code"，弹出一个文件对话框，保存后完成。但：

- **我不知道导出的是绝对坐标还是增量坐标**（界面上没有选择）
- 导出的 G-code 文件头部没有材料名、日期、参数等追溯信息
- 我看到"📄 导出 PDF 报告"按钮，点击后生成了 PDF，但内容里有英文参数名（`particle_velocity_ms`），我看不懂

### 1.3 普通用户总结

| 体验环节 | 评分 | 核心问题 |
|----------|------|----------|
| 第一印象 | 3/10 | 无新手引导，界面信息过载 |
| 加载数据 | 6/10 | 自动加载演示数据是亮点，但格式要求不清晰 |
| 选取缺陷 | 2/10 | **模式陷阱**，选区工具需要培训，曲面选不准 |
| 设置参数 | 2/10 | 22 个参数无解释，无 tooltip，无推荐值 |
| 开始计算 | 4/10 | 2 分钟等待无反馈，无取消按钮 |
| 查看结果 | 4/10 | 结果分散在 3 处，动画控制重复 |
| 导出文件 | 5/10 | 能完成导出，但坐标系模式不可选，无追溯信息 |

**能否独立完成一次完整计算**：勉强能，但需要反复试错或查阅文档，体验不流畅。

## 二、角色 2：冷喷涂算法工程师

### 2.1 角色画像

熟悉冷喷涂工艺，了解 G-code 和机器人编程，需要精确控制算法参数，验证算法正确性，导出可追溯的工艺文件。

### 2.2 体验过程

#### 参数控制：参数范围冲突

我发现界面上参数的允许范围与配置文件 `config.py` 的 `PARAM_SPECS` **大面积冲突**：

| 参数 | config.py 权威范围 | UI 实际范围 |
|------|-------------------|------------|
| 粒子速度 | [100, 2000] m/s | [100, 1200] m/s |
| 临界速度 | [100, 2000] m/s | [100, 1000] m/s |
| 气体温度 | [20, 1200] °C | [200, 1200] °C |
| 气体压力 | [1, 100] bar | [10, 100] bar |
| 规划层数 | [1, 200] | [1, 50] |

**我不知道该信哪个。** 更严重的是，`config.py` 定义了 `PARAM_BOUNDS` 和 `ValidationService`，但**这些校验在 UI 中从未被调用**——我改任何参数都不会触发权威范围校验，唯一的保护是 SpinBox 的硬边界（用的是冲突的范围）。

#### 参数依赖：不联动

切换材料时，只有"临界速度"自动更新。但专业上我知道：

- `gas_temperature` 应该参考材料的 `recommend_preheat_temp_c`（Ti64=350°C, Al=150°C）
- `single_layer_max_thickness_mm` 与 `layer_height` + `num_layers` 有物理约束
- `particle_velocity` 应大于 `critical_velocity`

**这些依赖关系 UI 完全不提示也不校验。** 我必须自己查材料数据库（`material_db.json`），手动调整每个参数。

#### 无参数预设

我有 5 种材料（316L / Cu / Ti64 / Inconel / Al），每种材料有推荐工艺参数组合。**但软件没有"参数预设"功能**，每次切换材料都要手动调 10 个参数。

材料数据库 `material_db.json` 已经有完整的专业数据（密度、临界速度、角度衰减曲线、最大沉积效率、推荐预热温度等 13 项），**但切换材料时只读取了 `v_cr_base_ms` 一个字段**，其余数据全部浪费。

#### G-code 导出：追溯信息缺失

导出的 G-code 文件头部只有：

```
(冷喷涂缺陷修复 G-code)
(模式: absolute)
G21  (单位: mm)
G90  (绝对坐标)
```

**缺失**：材料名、生成日期、scan_id、操作员、工艺参数摘要、软件版本号、航点总数。对工业现场的可追溯性是硬伤——G-code 文件一旦脱离软件，无法溯源。

#### 坐标系模式不可切换

`GCodeExporter` 类支持绝对/增量两种模式，但 UI 上**没有切换入口**，只能用绝对模式。增量模式（G91）对某些设备是必须的，但我无法在界面上选择。

#### 机器人导出：功能不存在

`robot_exporter.py` 实现了 KUKA KRL 和 ABB Rapid 两种格式，代码通过测试。但**主窗口里没有"导出机器人程序"按钮**，`ExportService` 也没有封装该方法。

**我在软件里根本找不到导出机器人轨迹的入口。** 这是一份写好但未交付的功能。

#### 标定功能：数据存在但不生效

`calibration_db.json` 有 232KB 的真实标定记录（5 种材料、多组参数 + 修正系数）。`CalibrationWizard` 类能计算 3 个修正系数（宽度/高度/效率）。

但**修正系数从不应用到形貌预测**。`main_window.py` 实例化了 `CalibrationWizard`，但整个文件再无任何方法调用。232KB 的标定数据是"只写不读"的死数据。

#### 算法验证：可用但无批量

CLI `validate_algorithms.py` 能执行 MATLAB/Python 双引擎比对，生成 9 章节 Markdown Diff Report，质量达到工业级。但**不支持批量验证**——一次只能跑一个 seed × 一个缺陷类型。`DatasetManager` 和 `ExperimentManager` 已实现但未集成到 CLI。

### 2.3 算法工程师总结

| 体验环节 | 评分 | 核心问题 |
|----------|------|----------|
| 参数控制 | 3/10 | 范围双源冲突，校验未接线，无预设 |
| 参数依赖 | 2/10 | 切换材料只联动 1 个参数，无物理约束校验 |
| G-code 导出 | 4/10 | 无追溯信息，坐标系不可选，不支持方言 |
| 机器人导出 | 0/10 | **UI 无入口**，功能未交付 |
| 标定功能 | 1/10 | 修正系数从不应用，232KB 死数据 |
| 算法验证 | 7/10 | Diff Report 质量高，但无批量验证 |

**能否满足专业工作**：不能。多个专业功能（机器人导出、标定修正、参数预设、批量验证）已实现但未接线，算法工程师无法使用。

## 三、角色 3：工业现场操作员

### 3.1 角色画像

在车间使用软件，需要快速完成修复任务，环境嘈杂，可能戴手套操作鼠标，对软件内部原理不关心，只关心"怎么把活干完"。

### 3.2 体验过程

#### 启动：需要 MATLAB 知识

启动软件后，点击"开始计算"，软件尝试自动启动 MATLAB。如果 MATLAB 没装或路径不对，错误提示是：

> "MATLAB Bridge 未就绪：{message}\n请检查 MATLAB 是否安装，或设置环境变量 CSAM_MATLAB_EXE 指向 matlab.exe"

**"环境变量 CSAM_MATLAB_EXE"对车间操作员完全无法操作。** 他们不知道什么是环境变量，更不知道怎么设置。

#### 界面：信息过载

车间操作员不需要看到 22 个参数。他们只需要：

1. 加载今天的工件扫描数据
2. 框选要修的地方
3. 按"开始"
4. 等 G-code 出来

但软件把所有参数、所有模式、所有工具一次性展示出来，**没有"简单模式"和"高级模式"的区分**。

#### 术语：无法理解

界面上充满了操作员不懂的术语：

- "点云" → 应该叫"扫描数据"
- "形貌预测" → 应该叫"修复后外观模拟"
- "沉积" → 应该叫"涂层堆积"
- "临界速度" → 需要解释"颗粒能粘上去的最小速度"
- "增材缓冲"/"修复缓冲" → 需要解释"超出边界的额外喷涂距离"
- "v_cr" → 缩写无解释
- "STL" → 3D 文件格式，需解释
- "P1" → 含义不明，无解释

#### 错误反馈：不知道怎么办

当出错时，弹窗多是 `str(e)` 直接透传的原始异常信息，比如：

- "请求构建失败: {protobuf 序列化错误}"
- "计算失败: {MATLAB 英文错误}"
- "缓存失败: {文件 IO 异常}"

**操作员看不懂这些，也不知道该怎么办。** 只有少数错误提示包含"怎么办"的指引（如"请联系管理员获取有效 License"）。

#### 导出：缺少追溯

车间需要每件工件的 G-code 可追溯（材料、日期、操作员、参数）。但导出的 G-code **没有任何追溯信息**，一旦文件离开软件，无法知道是用什么参数生成的。

#### 耗时：MATLAB 启动太慢

每次启动 MATLAB 需要 30-120 秒。在车间批量修复场景下，**每件工件都等 2 分钟不可接受**。虽然代码注释说"不在此关闭 MATLAB，保留会话供后续计算复用"，但操作员不知道这个机制，可能每次都会重启软件。

### 3.3 操作员总结

| 体验环节 | 评分 | 核心问题 |
|----------|------|----------|
| 启动 | 3/10 | MATLAB 错误提示无法操作 |
| 界面 | 2/10 | 信息过载，无简单模式 |
| 术语 | 2/10 | 大量专业术语无解释 |
| 错误反馈 | 2/10 | 原始异常透传，无"怎么办"指引 |
| 导出 | 3/10 | 无追溯信息，车间无法归档 |
| 效率 | 3/10 | MATLAB 启动慢，无"复用会话"提示 |

**能否在车间独立使用**：不能。需要工程师预设好环境和参数后才能使用。

## 四、角色 4：软件测试工程师

### 4.1 角色画像

负责验证软件功能正确性，需要覆盖正常流程和异常流程，关注错误处理、边界条件、自动化测试可行性。

### 4.2 体验过程

#### 测试覆盖：数量充足

276 个单元测试全部通过（229 + 47），覆盖 Python 代码、Bridge 通信、导出功能、License 系统。

#### 但缺少端到端测试

没有 GUI 自动化测试（如 pytest-qt）。所有 GUI 交互（点击按钮、切换 Tab、输入参数）都需要手动验证。对于 22 个参数 × 5 种材料 × 2 种模式 = 220 种组合，手动测试不可行。

#### 错误处理：不一致

- 成功提示友好（如路径规划完成弹窗，含航点数、文件位置、下一步指引）
- 失败提示粗糙（`str(e)` 透传，无错误分类）
- 全部用 `QMessageBox.warning`，**无 critical/information 区分严重程度**
- 崩溃报告（`exception_reporter.py`）反而是最完整的错误提示

#### 伪测试已清理但仍有改进空间

之前清理了 2 处恒真断言（`assert len(received) >= 0`），但 `test_stage3.py::test_zmq_client_graceful_degradation` 在 zmq 可用时只验证了 `hasattr(client, 'is_connected')` 和 `hasattr(client, 'close')`——**这些是属性存在性检查，不是行为验证**。

#### CI 配置：已纳入 Bridge 测试

CI 已运行 `repair_app/tests/` + `repair_app/bridge/tests/`，覆盖率门禁 60%，3 平台 × 3 Python 版本矩阵。

#### 缺少的测试场景

1. **License 过期场景**：测试只覆盖了"有 license"和"无 license"，未覆盖"license 明天过期"的边界
2. **MATLAB 崩溃恢复**：`MatlabLifecycleManager` 的自动重启逻辑（MAX_AUTO_RESTARTS=3）未被测试
3. **并发请求**：多个"开始计算"同时触发时的行为
4. **大文件性能**：100 万点以上的点云加载和计算耗时
5. **G-code 安全检查**：`validate_toolpath` 的安全高度拦截是否真的能防止撞机

### 4.3 测试工程师总结

| 体验环节 | 评分 | 核心问题 |
|----------|------|----------|
| 单元测试 | 8/10 | 276 个测试通过，覆盖面广 |
| 端到端测试 | 3/10 | 无 GUI 自动化测试 |
| 错误处理 | 4/10 | 错误提示不一致，无严重程度分级 |
| CI/CD | 7/10 | 已纳入 Bridge 测试，多平台矩阵 |
| 边界测试 | 4/10 | License 过期、MATLAB 崩溃、大文件未覆盖 |

## 五、角色 5：产品经理

### 5.1 角色画像

关注产品定位、用户旅程、功能完整度、发布就绪度、与竞品对比。

### 5.2 体验过程

#### 产品定位：清晰但落地不完整

产品定位是"冷喷涂缺陷修复一体化软件"，涵盖"扫描数据 → 缺陷选区 → 路径规划 → 形貌预测 → 工艺交付"完整链路。定位清晰。

但**多个已开发功能未在 UI 中暴露**，导致产品价值未完全交付：

| 功能 | 代码状态 | UI 状态 | 影响 |
|------|---------|---------|------|
| 机器人轨迹导出（KUKA/ABB） | ✅ 实现并测试 | ❌ 无入口 | 用户无法导出机器人程序 |
| 标定修正系数应用 | ✅ 数据库 232KB | ❌ 从不应用 | 标定数据无效 |
| G-code 增量坐标模式 | ✅ 实现并测试 | ❌ 无切换入口 | 某些设备无法使用 |
| 参数预设 | ✅ 材料库有数据 | ❌ 无预设按钮 | 每次手动调参 |
| 批量算法验证 | ✅ 基础设施就绪 | ❌ CLI 未集成 | 无法批量验证 |
| 参数校验服务 | ✅ ValidationService 实现 | ❌ 从未调用 | 参数超限不报错 |

#### 用户旅程：断点多

理想用户旅程：加载 → 选区 → 计算 → 查看结果 → 导出

实际旅程中的断点：

1. **加载后无引导**：用户不知道下一步是选区
2. **选区有模式陷阱**：必须先切换导航/选取模式
3. **计算期间无反馈**：2 分钟等待无进度条
4. **结果分散**：3D Tab、MATLAB Tab、右侧摘要三处
5. **导出缺信息**：G-code 无追溯，机器人导出无入口

#### 与竞品对比

冷喷涂领域竞品少，但与通用 CAM 软件对比：

| 功能 | CSAM Repair | 通用 CAM 软件 |
|------|-------------|--------------|
| 新手引导 | ❌ 无 | ✅ 向导式 |
| 参数预设 | ❌ 无 | ✅ 材料库预设 |
| G-code 方言 | ❌ 仅通用 | ✅ Fanuc/Siemens/Haas |

## 六、跨角色共性问题

以下问题被 **3 个以上角色**独立提及，是系统性短板：

### 6.1 无新手引导（4/5 角色提及）

打开软件后无任何引导，22 个参数 + 复杂三栏布局让新用户无从下手。

### 6.2 术语门槛高（4/5 角色提及）

"点云"、"形貌预测"、"沉积"、"临界速度"、"增材缓冲"、"v_cr"、"STL"、"P1" 等术语直接暴露，无解释。

### 6.3 错误反馈粗糙（3/5 角色提及）

`str(e)` 透传原始异常，无"怎么办"指引，内部概念（"生命周期管理器"、"Bridge"、"ZMQ"）泄漏到用户界面。

### 6.4 功能未接线（3/5 角色提及）

机器人导出、标定修正、G-code 坐标系切换、参数预设、批量验证——已实现但 UI 无入口。

### 6.5 结果分散（3/5 角色提及）

计算结果散落在 3D Tab、MATLAB Tab、右侧摘要三处，逐层动画控制重复出现两处。

## 九、最终结论

### 核心价值

CSAM Repair 在**技术实现**层面已达到工业级水准：MATLAB 集成、Bridge 通信、License 安全、崩溃恢复、算法验证体系均有完整实现。276 个测试全部通过，代码质量经多轮审计修复后无 BLOCKER。

### 主要短板

但在**产品交付**层面存在系统性问题：

1. **6 个已开发功能未在 UI 接线**（机器人导出、标定修正、坐标系切换、参数预设、批量验证、参数校验），产品价值未完全交付
2. **无新手引导 + 22 个无解释参数 + 专业术语直接暴露**，新用户学习曲线陡峭
3. **错误反馈粗糙**，`str(e)` 透传 + 内部概念泄漏，用户遇到问题不知道怎么办
4. **G-code 导出无追溯信息**，工业现场无法归档

### 发布建议

**v1.0 可以发布**，但需修复全部 8 个 Must Fix 项。13 个 Should Fix 项建议在 v1.1 优先处理，特别是机器人导出接线和标定修正应用——这两个是算法工程师的核心需求，目前代码已就绪只差 UI 接线，投入产出比最高。

12 个 Nice to Have 项可纳入 v1.1+ 长期规划。
