## 一、启动失败

### 1.1 Python 启动报 ModuleNotFoundError

**症状**

```
ModuleNotFoundError: No module named 'PySide6'   # 或 numpy / scipy / zmq
```

**可能原因**

1. 虚拟环境未激活，使用了系统 Python。
2. 依赖未安装或安装不完整。
3. 解释器路径选错（IDE 指向了错误的 Python）。

**诊断步骤**

```powershell
# 1. 确认虚拟环境已激活（命令行前缀含 (venv)）
where python          # 应指向 venv\Scripts\python.exe

# 2. 确认关键依赖已安装
python -c "import PySide6, numpy, scipy; print('OK')"
```

**解决方案**

```powershell
venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
```

若仅缺个别包：`pip install PySide6 --force-reinstall`。详见 [05 FAQ Q8](05_常见问题.md)、[02 安装指南](02_用户安装指南.md)。

---

### 1.2 PySide6 导入失败 / DLL 加载失败

**症状**

```
DLL load failed while importing QtWidgets
ImportError: DLL load failed
```

或界面白屏、OpenGL 报错。

**可能原因**

1. Visual C++ 2015-2022 Redistributable 缺失（Windows）。
2. 同一环境并存 PyQt5/PyQt6，与 PySide6 冲突。
3. GPU 驱动 OpenGL 实现不兼容。

**诊断步骤**

```powershell
python -c "from PySide6 import QtWidgets; print(QtWidgets.__file__)"
pip list | findstr -i "pyqt pyside"   # 检查是否并存多个 Qt 绑定
```

**解决方案**

1. 安装 [VC++ 2015-2022 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)。
2. 卸载冲突包：`pip uninstall PyQt5 PyQt6 PyQt5-Qt5`。
3. 强制 ANGLE 后端：`set QT_OPENGL=angle`。
4. 重装 PySide6：`pip install PySide6 --force-reinstall`。

详见 [05 FAQ Q9](05_常见问题.md)。

### 1.3 MATLAB startup 报"文本字符无效"

**症状**

MATLAB 执行 `startup` 时报错：

```
Error: 文件 'xxx.m' 中文本字符无效。
```

**可能原因**

MATLAB R2025b 拒绝源文件中的非 ASCII 字符（em-dash `—`、en-dash `–`、`ö`、`σ`、全角符号等）。代码已修复全部此类字符，但二次修改可能重新引入。

**诊断步骤**

1. 定位报错的 `.m` 文件与行号。
2. 用编辑器（VSCode）打开，启用可见空白与非 ASCII 高亮，查找非 ASCII 字符。
3. 确认文件编码为 UTF-8 无 BOM。

**解决方案**

1. 将所有非 ASCII 字符替换为 ASCII 等价物（如 `—` → `--`，`σ` → `sigma`）。
2. 临时规避：`feature('DefaultCharacterSet', 'UTF-8')`。
3. 确保所有 `.m` 文件保存为 UTF-8 无 BOM。

详见 [05 FAQ Q15](05_常见问题.md)。

### 1.4 MATLAB startup 报端口占用

**症状**

```
Error using java.net.ServerSocket
Address already in use: bind
```

**可能原因**

1. 上一次 MATLAB Server 未正常关闭，5570 端口仍被占用。
2. 其他程序占用 5570。
3. 多个 MATLAB 实例同时启动 Server。

**诊断步骤**

```powershell
netstat -ano | findstr :5570    # 查看占用 5570 的进程 PID
tasklist /FI "PID eq <PID>"     # 确认进程名
```

**解决方案**

1. 终止占用进程：`taskkill /PID <PID> /F`（确认是残留 MATLAB 后）。
2. 或修改绑定端口：`set CSAM_MATLAB_BIND=tcp://*:5571`，同步修改 GUI 端 `CSAM_MATLAB_PORT=5571`。
3. 确保仅启动一个 MATLAB Server 实例。

### 1.5 许可证校验失败

**症状**

启动时日志记录 `License validation failed` 或 GUI 弹窗提示许可证无效。

**可能原因**

1. `CSAM_HMAC_SECRET` 未设置（生产环境）。
2. `config/license.key` 缺失或过期。
3. `config/public_key.pem` 缺失。

**诊断步骤**

```powershell
echo %CSAM_HMAC_SECRET%        # 确认是否设置
dir config\license.key config\public_key.pem   # 确认文件存在
```

**解决方案**

1. 生产环境：设置 `CSAM_HMAC_SECRET=<真实密钥>`。
2. 开发环境：可不设置，使用内置开发回退密钥（记录 WARNING，不阻止启动）。
3. 生成开发许可证：`python -m repair_app.utils.license_manager issue "Developer" 365`。
4. 将 `public_key.pem` 与 `license.key` 放入 `config/` 后重启。

详见 [05 FAQ Q20](05_常见问题.md)。

---

### 1.6 演示数据加载失败

**症状**

GUI 启动后无点云显示，状态栏无"演示数据已加载"提示，或日志报 `FileNotFoundError: morphology_prediction/...`。

**可能原因**

1. `morphology_prediction/` 目录缺失或被误删。
2. `pointlist.npz` / `velocitylist.json` 损坏。
3. 工作目录错误，相对路径无法解析。

**诊断步骤**

```powershell
dir morphology_prediction\     # 确认目录与文件存在
python -c "import numpy as np; print(np.load('morphology_prediction/pointlist.npz').files)"
```

**解决方案**

1. 从版本控制恢复 `morphology_prediction/` 目录。
2. 该目录下的中间文件可由算法重新生成，删除后重新运行形貌预测即可。
3. 确保从项目根目录启动 GUI（`python run_app.py`），工作目录正确。

详见 [05 FAQ Q21](05_常见问题.md)、[05 FAQ Q32](05_常见问题.md)。

## 二、MATLAB 无法连接

### 2.1 MATLAB Server 未启动

**症状**

GUI 状态栏显示"未连接"，`EngineFactory` 日志记录 `MatlabEngine not reachable — falling back to LocalEngine`。

**可能原因**

1. MATLAB Server 从未启动。
2. Server 启动后崩溃退出。
3. 在错误的 MATLAB 工作目录启动。

**诊断步骤**

```matlab
% 在 MATLAB 中确认 Server 是否运行
exist('server', 'file')     % 应返回 2
```

```powershell
netstat -ano | findstr :5570   # 确认 5570 端口是否监听
```

**解决方案**

```matlab
cd('D:\work\demo\industrial-vision\matlab_server')
startup
```

启动成功会打印 `CSAM MATLAB Server starting on tcp://*:5570 (port 5570), protocol v3.0`。详见 [05 FAQ Q11](05_常见问题.md)。

---

### 2.2 端口不匹配

**症状**

Server 已启动，但 GUI 仍显示"未连接"，日志报连接被拒绝。

**可能原因**

`CSAM_MATLAB_PORT`（客户端连接端口）与 `CSAM_MATLAB_BIND`（Server 绑定端口）不一致。

**诊断步骤**

| 端 | 环境变量 | 默认值 | 说明 |
|----|----------|--------|------|
| Server | `CSAM_MATLAB_BIND` | `tcp://*:5570` | `config.m:26` 解析 |
| Client | `CSAM_MATLAB_PORT` | `5570` | `MatlabEngine` 连接 |

```powershell
echo %CSAM_MATLAB_BIND%
echo %CSAM_MATLAB_PORT%
```

**解决方案**

确保两者端口一致。若需改用其他端口，两端同步修改：

```powershell
set CSAM_MATLAB_BIND=tcp://*:5571
set CSAM_MATLAB_PORT=5571
```

---

### 2.3 防火墙阻止

**症状**

Server 与 GUI 在不同机器，GUI 连接超时；本机正常。

**可能原因**

Windows 防火墙或企业网络防火墙未放行 5570（MATLAB Server TCP/JSON）或 5555（ZMQ 通道）端口。

**诊断步骤**

```powershell
# 在 GUI 机器上测试连通性
Test-NetConnection -ComputerName <server_ip> -Port 5570
```

**解决方案**

1. Windows 防火墙：入站规则放行 TCP 5570（及 5555，若用 ZMQ）。
2. 企业防火墙：联系网络管理员开放端口。
3. 生产环境建议 Server 与 GUI 同机部署（`tcp://127.0.0.1:5570`），规避防火墙问题。

---

### 2.4 EngineFactory 降级

**症状**

日志记录 `MatlabEngine creation failed: ... — falling back to LocalEngine`，GUI 静默使用本地引擎。

**可能原因**

1. `CSAM_ENGINE_DISABLE_MATLAB=1` 被设置。
2. `MatlabEngine.is_available` 健康检查失败。
3. 创建过程抛异常（如 socket 连接超时）。

**诊断步骤**

```powershell
echo %CSAM_ENGINE_DISABLE_MATLAB%   # 应为空或 0
```

查看 `logs/app.log` 中 `csam.engine.factory` 的 WARNING/INFO 日志。

**解决方案**

1. 若误设 `CSAM_ENGINE_DISABLE_MATLAB=1`，清除该变量或设为 `0`。
2. 确认 MATLAB Server 健康（见 §2.1）。
3. 临时强制本地引擎：`set CSAM_ENGINE_DISABLE_MATLAB=1`（仅调试用）。

详见 [05 FAQ Q17](05_常见问题.md)、[05 FAQ Q26](05_常见问题.md)。

---

### 2.5 健康检查超时

**症状**

`MatlabEngine.is_available` 返回 False，日志记录健康检查超时。

**可能原因**

健康检查超时阈值过小，或 Server 响应慢。

**诊断步骤**

健康检查超时由 `CSAM_BRIDGE_HEALTH_MS` 控制（默认 3000ms，见 §4.2）。

**解决方案**

```powershell
set CSAM_BRIDGE_HEALTH_MS=10000   # 调大至 10 秒
```

若仍超时，检查 Server 负载（CPU/内存）与网络延迟。

---

### 2.6 R2025b Java 怪癖

**症状**

MATLAB R2025b 命令行 `version('-java')` 显示 "Java is not enabled"，担心 Server 无法启动。

**可能原因**

R2025b 的显示怪癖，实际 JVM 已加载，不影响 `java.net.ServerSocket` 等调用。

**诊断步骤**

```matlab
usejava('jvm')                                    % 返回 1 = 可用
java.lang.System.getProperty('java.version')      % 返回版本号 = 正常
```

**解决方案**

无需处理。只要 `usejava('jvm')=1` 即可正常运行。详见 [05 FAQ Q14](05_常见问题.md)。

## 三、ZMQ 通信失败

> 注：ZMQ 通道（端口 5555）用于旧版 `MatlabZmqEngine`。生产路径 `MatlabEngine` 走 5570 端口的 TCP/JSON 通道。本章仅适用于使用 ZMQ 引擎的场景。

### 3.1 ZMQ 地址错误

**症状**

`zmq_client` 报 `ZMQError` 或连接超时。

**可能原因**

`CSAM_ZMQ_ADDRESS` 协议前缀与平台不匹配。

**诊断步骤**

```powershell
echo %CSAM_ZMQ_ADDRESS%
```

| 平台 | 正确格式 | 错误格式 |
|------|----------|----------|
| Windows | `tcp://127.0.0.1:5555` | `ipc:///tmp/...`（不支持） |
| POSIX | `ipc:///tmp/csam_engine` 或 `tcp://...` | — |

**解决方案**

```powershell
set CSAM_ZMQ_ADDRESS=tcp://127.0.0.1:5555   # Windows
# export CSAM_ZMQ_ADDRESS=ipc:///tmp/csam_engine   # POSIX
```

---

### 3.2 端口 5555 被占用

**症状**

ZMQ 绑定失败：`Address in use`。

**可能原因**

其他进程占用 5555，或多个 ZMQ Server 实例。

**诊断步骤**

```powershell
netstat -ano | findstr :5555
```

**解决方案**

1. 终止占用进程，或
2. 改用其他端口：`set CSAM_ZMQ_ADDRESS=tcp://127.0.0.1:5556`，同步修改 ZMQ Server 端。

---

### 3.3 pyzmq 未安装

**症状**

```
ModuleNotFoundError: No module named 'zmq'
```

**可能原因**

`pyzmq` 未安装或安装失败。

**诊断步骤**

```powershell
python -c "import zmq; print(zmq.__version__)"
```

**解决方案**

```powershell
pip install pyzmq
```

`pyzmq` 已在 `requirements.txt` 中声明，正常安装依赖时不应缺失。

---

### 3.4 请求超时

**症状**

ZMQ 请求 30 秒后超时，日志记录 `Request timeout`。

**可能原因**

1. 算法执行耗时超过 30 秒。
2. ZMQ Server 无响应。
3. 网络延迟。

**诊断步骤**

默认超时 30 秒（`CSAM_BRIDGE_TIMEOUT_MS=30000`）。

**解决方案**

```powershell
set CSAM_BRIDGE_TIMEOUT_MS=120000   # 调大至 2 分钟
```

复杂算法（`generate_path`、`profile_predict`）本身超时设为 120s。详见 [05 FAQ Q42](05_常见问题.md)。

---

### 3.5 "前一个请求仍在进行中"

**症状**

```
BridgeError: 前一个请求仍在进行中
```

**可能原因**

`BridgeClient` 采用单请求串行模式，前一个请求未完成时拒绝新请求（`bridge/communication/zmq_client.py:206`）。

**诊断步骤**

查看 GUI 是否有正在进行的路径规划/形貌预测任务（状态栏提示）。

**解决方案**

1. 等待当前请求完成。
2. 或调用 `BridgeClient.close()` 取消当前请求。
3. 避免在任务进行中重复点击按钮（GUI 会弹窗 "路径规划仍在进行中，请等待完成"）。

详见 [05 FAQ Q41](05_常见问题.md)。

---

### 3.6 异常类型丢失（已知缺陷）

**症状**

所有 ZMQ 错误均以基类 `BridgeError` 形式抛出，无法区分具体子类型（如 `BridgeTimeoutError`、`BridgeConnectionError`）。

**可能原因**

已知缺陷：`bridge/communication/zmq_client.py:279` 的 `_on_error_occurred` 将原始错误消息包装为 `Exception(msg)`，丢失了原始异常类型，导致 `translate_zmq_error` 无法识别子类型，统一返回基类 `BridgeError`。

**诊断步骤**

查看异常类名是否始终为 `BridgeError`（而非子类）。

**解决方案**

- **临时**：通过错误消息字符串内容区分场景（如包含 "timeout" 视为超时）。
- **根治**：修复 `_on_error_occurred`，保留原始异常对象传递给 `translate_zmq_error`，由其根据原始类型映射到正确的子类。该修复需在 [07 开发者文档](07_开发者文档.md) 描述的 bridge 模块中实施。

## 四、配置错误

### 4.1 环境变量未生效

**症状**

修改了环境变量但行为未变化，或 `.env` 文件被忽略。

**可能原因**

1. `.env` 文件未加载（程序未使用 python-dotenv）。
2. 系统环境变量在程序启动后才设置。
3. PowerShell 与 cmd 会话隔离，变量未跨会话生效。

**诊断步骤**

```powershell
# 确认变量在当前会话可见
echo %CSAM_MATLAB_PORT%
python -c "import os; print(os.environ.get('CSAM_MATLAB_PORT'))"
```

**解决方案**

1. 在启动 GUI 的同一会话中设置变量。
2. 或写入 `.env` 文件（若程序加载）。
3. 系统级设置：通过"系统属性 → 环境变量"永久配置。
4. 重启 GUI 使变量生效。

---

### 4.2 BridgeConfig 与 .env.example 不一致

**症状**

按 `.env.example` 配置后，实际行为与预期不符（超时、心跳、重试表现异常）。

**可能原因**

`bridge/communication/config.py` 的 `BridgeConfig` 默认值与 `.env.example` 注释值存在差异。下表列出所有不一致项：

| 配置项 | `.env.example` 注释值 | `BridgeConfig` 默认值 | 实际生效（未设变量时） |
|--------|----------------------|----------------------|----------------------|
| `health_check_timeout_ms` | 2000 (`CSAM_BRIDGE_HEALTH_MS`) | 3000 | 3000 |
| `heartbeat_interval_ms` | 2000 (`CSAM_BRIDGE_HEARTBEAT_MS`) | 5000 | 5000 |
| `retry_interval_ms` | 200 (`CSAM_BRIDGE_RETRY_MS`) | 2000 | 2000 |
| `log_latency_threshold_ms` | 5000 (`CSAM_BRIDGE_LATENCY_LOG_MS`) | 1000 | 1000 |

**诊断步骤**

```powershell
python -c "from repair_app.bridge.communication.config import BridgeConfig; c=BridgeConfig(); print('health=',c.health_check_timeout_ms,'hb=',c.heartbeat_interval_ms,'retry=',c.retry_interval_ms,'lat=',c.log_latency_threshold_ms)"
```

**解决方案**

1. 以 `BridgeConfig` 实际默认值为准（上表"实际生效"列）。
2. 若需匹配 `.env.example` 的注释值，显式设置环境变量：
   ```powershell
   set CSAM_BRIDGE_HEALTH_MS=2000
   set CSAM_BRIDGE_HEARTBEAT_MS=2000
   set CSAM_BRIDGE_RETRY_MS=200
   set CSAM_BRIDGE_LATENCY_LOG_MS=5000
   ```
3. 该不一致属文档与代码的已知偏差，建议后续同步 `.env.example` 注释。

---

### 4.3 MATLAB config.m 环境变量

**症状**

MATLAB Server 配置不生效（端口、日志目录、心跳、级别）。

**可能原因**

未设置 `config.m` 读取的环境变量。

**诊断步骤**

`config.m` 读取以下变量（均有默认值）：

| 变量 | 默认值 | 作用 |
|------|--------|------|
| `CSAM_MATLAB_BIND` | `tcp://*:5570` | 绑定地址 |
| `CSAM_MATLAB_LOG_DIR` | `<repo>/logs` | 日志目录 |
| `CSAM_MATLAB_HEARTBEAT_MS` | `1000` | 心跳间隔 |
| `CSAM_MATLAB_LOG_LEVEL` | `info` | 日志级别（小写） |
| `CSAM_MATLAB_MAX_REQ_BYTES` | `67108864` (64MB) | 请求体上限 |
| `CSAM_MATLAB_CLEANUP_INTERVAL` | `50` | 清理间隔（请求数） |
| `CSAM_MATLAB_MEM_THRESHOLD_MB` | `4096` | 内存阈值 |

**解决方案**

在启动 MATLAB **之前**设置变量（MATLAB 启动时读取 `getenv`）：

```powershell
set CSAM_MATLAB_BIND=tcp://*:5571
set CSAM_MATLAB_LOG_LEVEL=debug
```

---

### 4.4 版本不一致

**症状**

健康检查或版本协商时，Server 与客户端报告的版本号不匹配，可能触发 `ERR_VERSION`。

**可能原因**

| 端 | 版本字符串 | 位置 |
|----|-----------|------|
| MATLAB Server | `matlab-server-3.0.0` | `config.m:50` (`cfg.server_version`) |
| Python 客户端 | `matlab_server/1.0.0` | `matlab_engine.py:42` (`SERVER_APP_VERSION`) |

二者命名规则与版本号均不一致。

**诊断步骤**

```python
from repair_app.engine.matlab_engine import SERVER_APP_VERSION
print(SERVER_APP_VERSION)   # matlab_server/1.0.0
```

```matlab
cfg = config(); disp(cfg.server_version)   % matlab-server-3.0.0
```

**解决方案**

1. 当前协议协商以 `protocol_ver`（3.0）为准，版本字符串不一致通常不阻塞通信。
2. 若触发 `ERR_VERSION`，检查协议版本字段而非应用版本。
3. 建议后续统一版本字符串命名（已知偏差，待修复）。

## 五、性能问题

### 5.1 100K+ 点云规划慢

**症状**

大点云（100K 点以上）路径规划或形貌预测耗时长，疑似卡死。

**可能原因**

属正常现象。大点云的 A* 搜索、八叉树构建、射线三角相交计算复杂度高。

**诊断步骤**

参考 `repair_app/tests/test_stress.py:27`（`n = 100000` 点的压力测试）：

```python
def test_large_point_cloud(self):
    """100K points should complete without error."""
    n = 100000
```

**解决方案**

1. 耐心等待，观察日志确认任务仍在进行（非死锁）。
2. 调大超时：`set CSAM_BRIDGE_TIMEOUT_MS=300000`（5 分钟）。
3. 增大内存（推荐 16GB+）。
4. 降低 `resolution`（避障精度）以减少搜索量。
5. 分块处理超大点云。

---

### 5.2 MATLAB 内存增长

**症状**

MATLAB Server 长时间运行后内存持续增长，最终可能 OOM。

**可能原因**

长驻进程累积临时变量、图形句柄未释放。

**诊断步骤**

`resource_cleanup.m` 每 `CSAM_MATLAB_CLEANUP_INTERVAL=50` 请求自动执行：
- `java.lang.System.gc()` 触发 JVM GC。
- 内存超 `CSAM_MATLAB_MEM_THRESHOLD_MB=4096` 时 `drawnow('reduce')` 释放图形句柄。

**解决方案**

1. 调低清理间隔：`set CSAM_MATLAB_CLEANUP_INTERVAL=20`。
2. 调低内存阈值：`set CSAM_MATLAB_MEM_THRESHOLD_MB=2048`。
3. 定期重启 Server（运维计划任务）。
4. 手动 `pack`（仅在 MATLAB 命令提示符执行，函数内无效，M2 修正）。
5. 监控 `logs/matlab_server_<date>.log` 中的 `cleanup.done` 事件与 `mem_before/after_mb`。

详见 [05 FAQ Q49](05_常见问题.md)。

---

### 5.3 GUI 响应卡顿

**症状**

点击按钮后界面短暂无响应。

**可能原因**

1. UI 线程被阻塞（异常情况）。
2. 大点云渲染负载高。
3. Worker 线程异常未回调。

**诊断步骤**

- 算法应运行在 `QThread` Worker（`ui/workers.py`），不阻塞 UI 线程。
- 远程引擎通过异步回调返回结果。

**解决方案**

1. 确认是否大点云（见 §5.1）。
2. 查看 `logs/app.log` 是否有 Worker 异常。
3. 启用 LOD（细节层次）渲染（`utils/lod.py`）。
4. 若 UI 线程被阻塞，属缺陷，提交 issue 并附日志。

详见 [05 FAQ Q27](05_常见问题.md)。

---

### 5.4 首次启动慢

**症状**

打包后的 exe 首次启动需 10–30 秒，疑似闪退。

**可能原因**

PyInstaller 单文件模式首次运行需解压全部依赖到临时目录，属正常现象。

**诊断步骤**

从命令行运行 `CSAM_Repair.exe`，观察是否在解压后正常显示窗口。

**解决方案**

无需处理。若需加速，改用目录模式打包（`pyinstaller --onedir`）。详见 [05 FAQ Q47](05_常见问题.md)。

---

### 5.5 大数组序列化警告

**症状**

日志出现 `large array warning`，传输大矩阵时性能下降。

**可能原因**

`BridgeConfig.large_array_warn_threshold=1_000_000`（100 万元素），超过即记录警告。

**诊断步骤**

查看 `logs/app.log` 中的 large array 警告，确认涉及的张量名与形状。

**解决方案**

1. 警告本身不阻塞，属性能提示。
2. 大点云的 `pointlist`、`triangles` 等张量可能触发，属正常。
3. 若频繁触发且影响性能，考虑分块传输。

## 六、日志分析

### 6.1 Python 日志位置

| 日志文件 | 路径 | 内容 |
|----------|------|------|
| 应用日志 | `logs/app_{YYYY-MM-DD}.log` | 全级别日志 |
| 错误日志 | `logs/error_{YYYY-MM-DD}.log` | 仅 ERROR 及以上 |
| 结构化日志 | `logs/structured_{YYYY-MM-DD}.jsonl` | JSONL，便于程序化分析 |
| 兼容日志 | `logs/app.log` | UTF-8 文本（兼容旧路径） |
| 崩溃日志 | `repair_app/utils/logs/crash_{timestamp}.log` | 未捕获异常堆栈 |

日志目录由 `LOG_DIR` 控制，默认 `./logs`。配置见 `repair_app/utils/logger_config.py`。

### 6.2 MATLAB 日志位置

| 日志文件 | 路径 | 内容 |
|----------|------|------|
| Server 日志 | `logs/matlab_server_{YYYYMMDD}.log` | JSONL 格式，UTF-8 编码 |

日期格式为 `YYYYMMDD`（无分隔符）。日志目录由 `CSAM_MATLAB_LOG_DIR` 控制，默认 `<repo>/logs`。配置见 `matlab_server/config.m` 与 `logger.m`。

### 6.3 日志级别

| 端 | 可用级别 | 设置变量 | 默认 |
|----|----------|----------|------|
| Python | `DEBUG / INFO / WARNING / ERROR` | `CSAM_LOG_LEVEL` | `INFO` |
| MATLAB | `debug / info / warn / error` | `CSAM_MATLAB_LOG_LEVEL` | `info` |

> 注意大小写差异：Python 大写，MATLAB 小写。

开启 DEBUG：

```powershell
set CSAM_LOG_LEVEL=DEBUG
set CSAM_MATLAB_LOG_LEVEL=debug
```

DEBUG 级别记录完整请求/响应、心跳、健康检查，日志量大，仅用于深度排查。详见 [05 FAQ Q46](05_常见问题.md)。

### 6.4 关键日志事件

MATLAB Server 日志中的关键字段（JSONL）：

| 事件 | 含义 | 触发时机 |
|------|------|----------|
| `server.start` | Server 启动 | `startup` 后 |
| `request.start` | 请求开始 | 收到算法请求 |
| `request.crash` | 请求崩溃 | 算法抛异常 |
| `cleanup.done` | 资源清理完成 | 每 N 请求 |
| `server.stop` | Server 停止 | 正常关闭 |

Python 侧关注 `csam.engine.factory`、`csam.engine.matlab`、`csam.bridge` 等 logger 的输出。

### 6.5 如何分析请求失败

1. **搜索 error 级别**：在 `logs/matlab_server_<date>.log` 中搜索 `"level":"error"` 或 `"level":"warn"`。
2. **关联 request_id**：每个请求有唯一 `request_id`，沿该 ID 串联 `request.start` → `request.crash` 全链路。
3. **对照 Python 日志**：同一时间窗口查看 `logs/app_{date}.log` 中的对应请求。
4. **检查响应状态**：`ResponseStatus` 非 0 即为错误（1=ERR_INVALID, 2=ERR_TIMEOUT, 3=ERR_ALGORITHM, 4=ERR_DEPS, 5=ERR_NOT_FOUND, 6=ERR_CANCELLED, 7=ERR_VERSION）。
5. **结构化分析**：`structured_{date}.jsonl` 便于用 `jq` 等工具程序化过滤。

```bash
# 示例：提取所有 error 级别事件
cat logs/matlab_server_20260710.log | jq 'select(.level=="error")'
```

详见 [08 运维手册](08_运维手册.md)。

## 七、恢复流程

### 7.1 MATLAB Server 崩溃恢复

**症状**

MATLAB 进程异常退出，GUI 操作无响应。

**恢复步骤**

1. **确认崩溃**：检查 MATLAB 命令窗口是否退出，查看 `logs/matlab_server_<date>.log` 末尾的 `request.crash` 或异常堆栈。
2. **重启 Server**：
   ```matlab
   cd('D:\work\demo\industrial-vision\matlab_server')
   startup
   ```
3. **GUI 侧**：路径 A（`MatlabEngine`）**不会自动重连**（见 [05 FAQ Q44](05_常见问题.md)）。在 GUI 中重新触发请求即可，`MatlabEngine` 会重新连接。
4. **若不便重启**：`set CSAM_ENGINE_DISABLE_MATLAB=1` 临时降级到 LocalEngine 继续工作。
5. **根因排查**：分析崩溃日志，常见原因包括 OOM（见 §5.2）、工具箱许可证失效（见 [05 FAQ Q50](05_常见问题.md)）、算法异常。

---

### 7.2 GUI 崩溃恢复

**症状**

Python GUI 进程异常退出。

**恢复步骤**

1. **查看崩溃日志**：`install_crash_handler`（`repair_app/utils/crash_handler.py`）会记录崩溃堆栈到 `repair_app/utils/logs/crash_{timestamp}.log`。
2. **分析堆栈**：确认崩溃点（UI 线程 / Worker 线程 / 桥接层）。
3. **重启 GUI**：`python run_app.py`。
4. **MATLAB Server 无需重启**：Server 长驻，与 GUI 生命周期解耦。
5. **提交 issue**：附崩溃日志与复现步骤。

---

### 7.3 数据丢失恢复

**症状**

中间结果丢失（点云、路径、形貌预测）。

**恢复步骤**

1. **中间文件位置**：`morphology_prediction/` 目录保存算法中间产物（`pointlist.npz`、`velocitylist.json`、形貌帧数据等）。
2. **重新生成**：大部分中间文件可由算法重新生成——重新执行路径规划/形貌预测即可。
3. **演示数据**：由 `generate_defect_sample` 内存生成，重启 GUI 自动加载 8000 点（见 [05 FAQ Q21](05_常见问题.md)）。
4. **用户点云**：从原始数据源重新加载。
5. **定期备份**：建议对 `morphology_prediction/` 与 `config/` 目录做版本控制或定期备份。

---

### 7.4 配置恢复

**症状**

配置丢失或损坏，软件无法正常启动。

**恢复步骤**

1. **从模板重建**：`.env.example` 是完整配置模板，复制为 `.env`：
   ```powershell
   copy .env.example .env
   ```
2. **填写实际值**：至少设置 `CSAM_HMAC_SECRET`（生产环境）。
3. **核对端口**：确认 `CSAM_MATLAB_BIND` 与 `CSAM_MATLAB_PORT` 一致（见 §2.2）。
4. **核对配置偏差**：参考 §4.2 的 BridgeConfig 与 `.env.example` 差异表。
5. **MATLAB 侧配置**：参考 §4.3 的 `config.m` 环境变量表。

---

### 7.5 完整重置

**症状**

软件状态完全异常，需恢复到干净初始状态。

**完整重置步骤**

1. **关闭 GUI**：退出 Python GUI 进程。
2. **关闭 MATLAB Server**：在 MATLAB 命令窗口执行 `exit` 或关闭 MATLAB。
3. **清理日志**：
   ```powershell
   rmdir /s /q logs
   mkdir logs
   ```
4. **清理中间产物**（可选，会重新生成）：
   ```powershell
   del /q morphology_prediction\*.npz morphology_prediction\*.json
   ```
5. **重置配置**：从 `.env.example` 重建 `.env`（见 §7.4）。
6. **重启 MATLAB Server**：`cd matlab_server; startup`。
7. **重启 GUI**：`python run_app.py`。
8. **验证**：GUI 自动加载演示数据，状态栏确认引擎连接状态。

> 重置不会影响源代码与算法实现，仅清理运行时产物。详见 [08 运维手册](08_运维手册.md)。
